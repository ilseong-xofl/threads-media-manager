# Threads Collector

개인 Codex 계정과 로그인된 내부 브라우저로 Threads 게시글 정보를 수집하는 플러그인이다. **수집 완료까지만 진행하며 다운로드는 별도 로컬 앱에서 수행한다.**

## 포함 기능

- `$threads-setup`: 위치 기억, sample 예제 계정 양식 준비, 계정 등록·로그인 안내.
- `$threads-plugin-check`: 설치·버전·필수 도구 확인. 수집이나 다운로드를 시작하지 않는다.
- `$threads-collect`: 최초 미디어 원글10건, 이후 이전 기준까지 최대10건. 날짜별 Excel 원본으로 저장한다.

수집은 계정당 KST 하루 한 번이 기본이며 사용자 요청 시 실행한다. 이동50–80%, 처리시간 포함 최소 이동간격2–8초, 계정 후처리 뒤10–30초 대기, 최대40회/10분 탐색 규칙을 유지한다.

## 사용과 저장

처음에 “Threads 초기 설정해줘”를 요청한다. 생성된 accounts.xlsx의 sample 행을 지우고 실제 계정을 등록한 뒤 내부 브라우저 로그인 상태에서 “수집 시작해줘”를 요청한다. 활성 sample 행이 남으면 수집하지 않는다. 기존 사용자 양식과 설정을 업데이트로 초기화하지 않는다.

이미 초기 설정한 뒤에는 **새 Codex 대화**에서 다음과 같이 요청한다. 업데이트된 스킬은 새 대화에서 로드한다.

```text
Threads Collector 플러그인의 $threads-collect로 수집 시작해줘.
```

저장된 수집 폴더의 `accounts.xlsx`에서 활성 계정을 읽으므로 매번 경로를 적을 필요는 없다. 계정 목록을 수정했다면 Excel을 저장하고 닫는다. 이번에만 다른 계정 파일을 쓰려면 `지정한 accounts.xlsx 절대 경로로 수집 시작해줘`라고 요청한다. 기본 폴더는 바꾸지 않는다.

최초와 이후 모두 계정당 미디어 원글 최대10건이며, 이후에는 이전 기준 ID를 먼저 만나면 그 앞에서 끝낸다. 같은 날 이미 시도한 계정은 기본적으로 건너뛰므로 의도한 경우에만 `오늘 수집한 계정도 다시 수집해줘` 또는 `중단된 수집을 재개해줘`라고 요청한다. 재실행도 제한 신호 뒤의 자동 재시도를 허용하지 않는다.

최종 원본은 `results/YYYY/MM/threads-YYYY-MM-DD.xlsx`다. 같은 날 실행 이력을 누적하고 다음날 새 파일을 만든다. JSONL은 `_work`의 임시 수집 기록이며 결과·계정 Excel 검증 후 정리한다. 저장 실패는 임시 기록을 남기고 같은 입력으로 재수집 없이 복구한다.

[수집 원본 helper](references/collection-source.md)는 제공 Python의 표준 라이브러리만 사용한다. 다운로드 코드·SQLite 상태·Pillow·ffprobe는 플러그인의 구성 요소가 아니다. 수정 Excel의 자동 반영 기능은 없다.

수집 완료 후 같은 저장 폴더를 로컬 앱에서 열어 다운로드한다. 플러그인은 CDN 링크를 기록할 뿐 유효성 확인 GET/HEAD나 다운로드를 실행하지 않는다. 앱의 다운로드 오류가 수집 결과·기준을 되돌리지 않는다.

실제 결과와 Windows 미검증 범위는 저장소 `docs/progress.md`를 따른다. 이전 단독 수집 스킬을 자동 제거하지 않는다. 소스·설치 캐시·현재 대화 로드 버전을 구분하며 갱신 스킬의 자동 선택은 새 대화에서 확인한다.
