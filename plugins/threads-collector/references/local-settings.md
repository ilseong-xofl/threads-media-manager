# 수집 위치 기억과 초기 설정

각 멤버의 홈 폴더 아래 `.threads-media-manager/settings.json`은 플러그인 설치/업데이트 경로 밖의 작은 위치 설정이다. 홈은 현재 OS와 사용자 실행 환경에서 결정하며 다른 PC의 절대 경로를 복사하지 않는다.

```json
{
  "schema_version": 1,
  "collection_root": "<사용자가 선택한 이 PC의 절대 경로>"
}
```

계정명·URL·기준 게시글 ID·캡션·수집/다운로드 진행 상태를 넣지 않는다. 계정 입력은 accounts.xlsx, 수집 원문·기준은 결과 Excel, 다운로드 상태는 로컬 앱의 state.db가 소유한다. 이 설정은 초기 설정 helper가 쓰고 수집 스킬이 읽는다. 설치 캐시에 쓰지 않으므로 업데이트 후에도 같은 위치를 찾는다.

## 경로 선택

수집 요청에 명시된 `accounts.xlsx` 경로 → 저장된 `collection_root/accounts.xlsx` → 초기 설정에서 한 번 선택 순서다. 이번 요청의 명시 경로는 일회성 입력으로 사용할 수 있지만 기본 설정을 자동으로 바꾸지 않는다. 기존 설정과 다른 수집 폴더를 기본값으로 바꾸거나 자료를 이동하는 기능은 이번 단계에 포함하지 않는다.

설정 파일이 없는 처음 사용과 설정이 손상되었거나 기존 폴더/계정 파일이 없어진 상태를 구분한다. 이전 상태가 손상됐다고 새 양식을 만들거나 기본 위치를 임의 생성하지 않는다. 수집 실행은 선택 루트의 기존 잠금과 Excel 저장 복구 규칙을 그대로 따른다.

## helper 호출

[setup_collection.py](../scripts/setup_collection.py)는 Python 표준 라이브러리만 사용한다. Codex의 `load_workspace_dependencies`가 반환한 Python 실행 파일로 호출한다. 경로는 공백/한글을 포함할 수 있으므로 인수를 안전하게 인용한다. 사용자에게 직접 터미널 실행을 맡기지 않는다.

- `status`: 설정과 폴더 상태를 JSON으로 보고한다. 파일·폴더·잠금을 만들거나 변경하지 않는다.
- `init --collection-root <절대 경로>`: 처음 정한 수집 위치에 예제 행이 있는 `accounts.xlsx`와 `results/`, `backups/`, `_work/`를 준비한다. 기존 계정 파일은 최소 형식만 확인하고 byte를 바꾸지 않는다. 예제는 새 파일을 만들 때만 포함하며 반복 초기 설정이나 업데이트에서 기존 파일에 추가하지 않는다. 초기 설정은 계정의 유효성·로그인·수집 성공을 판정하지 않는다.
- `--config-path <절대 경로>`: 개발 검증을 격리하는 용도다. 일반 멤버에게 별도 설정 파일 위치를 고르게 하지 않으며 운영에서는 기본 경로를 쓴다.

JSON의 `ok`만으로 준비 완료를 판단하지 않는다. `setup_state=not_configured`는 처음 설정이 필요함, `prepared`는 폴더와 양식 준비 완료, `busy`는 기존 실행/Excel 잠금 확인 필요, `incomplete` 또는 `recovery_required`는 보완/복구 필요 상태다. 실패 시 `error.code`와 `message`를 근거로 안내한다. 계정·로그인·수집 준비 전체를 이 값 하나로 판단하지 않는다.

실제 파일 준비는 helper만 사용하고 실패를 임시 복사/덮어쓰기 코드로 우회하지 않는다. 기존 실행 잠금, 파일 충돌, 손상 설정, 지원하지 않는 양식은 중단 사유다. 중간 실패 시 기존 사용자 파일과 이미 준비된 양식을 보존하고 재실행에서 다시 확인한다.

기존 파일 덮어쓰기를 막는 원자적 최초 생성에는 로컬 파일시스템의 hard link 기능을 사용한다. 지원하지 않는 파일시스템은 오류로 멈추며 다른 방식으로 몰래 덮어쓰지 않는다. Excel 열림은 알려진 잠금 표식으로만 감지하므로 파일을 닫아야 한다. Windows 실제 런타임·파일시스템 동작은 별도 검증 전까지 미검증이다.

수집 스킬은 `status`의 설정에서 루트를 읽고 그 안의 계정 목록을 검증한다. 결과가 성공이라고 계정이 등록되어 있거나 로그인됐다고 추정하지 않는다. 런타임이 제공되지 않으면 준비 미완료로 안내하며 Python/Node 자동 설치나 다운로드를 진행하지 않는다.
