# 수집 중 JSONL 기록

수집 루프에서는 계정별 JSONL만 추가 기록한다. 관찰을 기록한 뒤 다음 스크롤로 진행하고, 목표 도달 또는 중단 후 한 번 정규화한다. 이 문서의 `_work` JSONL은 탐색 임시 복구 자료다. 최종 원본은 `results/...xlsx` 하나이며 [helper 계약](../../../references/collection-source.md)에 따라 저장·검증 후 임시 기록을 정리한다.

## 파일과 helper

시작 전 수집 helper inspect로 원본을 확인하고 기존 수집 복구·잠금을 점검한다. 다운로드 DB의 중단 상태는 읽지 않는다. 수집 중에는 공통 잠금을 생성하지 않고, `_work/<실행ID>/0001.jsonl`처럼 계정 순번으로 파일을 정한다. 사용자가 입력한 계정명을 파일 경로로 이어 붙이지 않는다. 파일을 플러그인 소스·설치 캐시에 만들지 않는다.

패키지 루트의 `scripts/collection_journal.py`를 제공된 Python으로 호출한다. 이 helper는 브라우저·Excel·네트워크를 사용하지 않는다.

```text
python <plugin>/scripts/collection_journal.py append --journal <account.jsonl> --input <record.json>
python <plugin>/scripts/collection_journal.py read --journal <account.jsonl> --output <records.json>
```

한 번 추출한 여러 게시글·첨부를 하나의 `batch` 기록으로 넣는다. 매 게시글마다 별도 프로세스를 실행하거나 Excel을 갱신하지 않는다. 입력 JSON은 셸 인자로 보간하지 말고 안전한 파일 작성 도구로 생성한다. helper는 UTF-8 한 줄을 추가하고 flush/fsync한다. 출력에는 요약만 나오며 서명 URL을 콘솔에 출력하지 않는다.

## 기록 구조

각 입력은 아래 필드를 가진 JSON 객체다. `seq`는 helper가 부여한다. 같은 `event_id`의 동일 입력을 다시 전달해도 중복 추가하지 않으며, 같은 ID의 다른 내용은 오류다. 자동 브라우저 재시도 권한을 뜻하지 않는다.

| 필드 | 의미 |
|---|---|
| `v` | `1` |
| `type` | `start`, `batch`, `end` |
| `run_id`, `account` | 실행 ID와 해당 계정; 파일 내에서 불변 |
| `event_id` | 계정 내 고유한 기록 ID; 도구 응답 불명 시 같은 입력·ID 유지 |
| `payload` | 아래 유형별 관찰 데이터 |

- `start`: 전체 실행의 KST 수집일, 계정의 실제 시도 시작 시각, initial/incremental, 기존 기준 ID, 이전 반영 실행 ID, 입력·결과 파일의 원본 해시, 결과 상대 경로, 목표 수와 적용한 최소 간격·이동·탐색 상한. 최소 간격 정책은 `min_scroll_gap_ms=[2000,8000]`, `gap_includes_processing=true`로 기록하며 처리 후 고정 추가 대기와 구분한다. 처음에 배타적으로 생성하며 기존 파일을 덮어쓰지 않는다.
- `batch`: 실제 관찰 시각, `posts`와 `media`, `scroll_index`, `gap_baseline`(initial_load/scroll_start), `target_gap_ms`, `extra_wait_ms`(직접 대기한 실측 시간), `actual_gap_ms`(기준 시점부터 실제 이동 호출 시작까지), 실제 이동 비율과 이동 호출 시작의 ISO 시각, 현재 DOM ID 순서, 신규·미완료·제거 ID, 로딩·제한 상태. 첫 화면은 스크롤 0이며 아직 발생하지 않은 이동의 간격 필드는 null로 둔다. 첫 이동의 actual_gap_ms는 초기 로딩 완료 기준, 이후는 직전 이동 호출 시작 기준이다. 같은 구간의 로딩 확인에는 목표를 재추첨하지 않는다. 단조시계 경과값과 ISO 시각을 혼합해 차이를 구하지 않으며, 실제 간격이 8초를 넘는 것은 위반이 아니다. 텍스트·답글 등의 제외 판정과 그 근거, 판정 대기 카드도 기록해 복구 때 다시 추측하지 않게 한다. 데이터가 없는 스크롤의 작은 측정값은 다음 batch 또는 end에 묶어 저장할 수 있다.
- `end`: 실제 종료 시각, 종료 상태·이유, 기존 기준 발견 여부, 이번 적격 원글 수, 다음 기준 후보, 누락 상태와 남은 미완료 카드. 실제 관찰·종료 조건에 근거해서만 작성한다. 목표 미달이라도 중단하면 기록하고 후처리한다. 시간·스크롤 상한/오류에서는 기존 기준을 유지한다.

`posts`와 `media`는 [Excel 계약](excel-contract.md)의 항목을 누락 없이 담되 시각은 오프셋이 있는 ISO 8601 문자열로 보관한다. 게시글 ID는 문자열, 캡션·줄바꿈과 URL 전체 쿼리는 그대로 보존한다. 후보 URL을 다운로드 성공으로 표시하지 않으며 쿠키·인증 정보·전체 HTML을 넣지 않는다. helper의 구조 검증은 원글 판정·미디어 연결·엑셀 열 검증을 대신하지 않는다.

## 후처리와 복구

1. 계정 탐색 종료 후 `read`로 JSONL을 읽는다. 게시글 `(계정, ID)`와 미디어 `(계정, ID, 순서)`로 관찰을 병합한다. 같은 ID의 보완 관찰을 새 게시글로 세지 않고 완전한 정보를 불완전한 재관찰로 지우지 않는다. DOM 등장 순서·기준 ID·목표 수 판정은 수집 중 처리하며 종료 후 임의 정렬로 다시 정하지 않는다.
2. 한 계정의 관찰을 정규화해 `{posts, media, run}` 입력을 만든다. 실제 종료·partial 상태와 기존 기준을 검증한다.
3. `commit-source --input ... --journal ...`을 `--lock-token` 없이 호출하여 결과 Excel과 accounts를 저장·검증한다. 이 짧은 반영 구간에만 helper가 공통 잠금을 잡고 반환 시 해제한다. 성공하면 helper가 전달한 journal·입력만 정리한다. 실패하면 남은 임시 기록으로 재수집 없이 같은 저장을 복구한다. 영구 JSONL은 생성하지 않는다.
4. `end` 없이 종료됐다면 완전히 기록된 JSONL 행만 복구하여 `partial`로 후처리한다. 기존 기준은 유지하고 종료 시각을 만들어내지 않는다. 복구만으로 브라우저 수집을 다시 시작하지 않는다.
5. 완전한 `start`가 하나도 없으면 실행·계정·시각을 추측하여 Excel 행이나 기준을 만들지 않고 원본을 보존한 채 중단한다. 마지막 줄이 개행 없이 잘려 있으면 helper는 `incomplete_tail`로 알린다. 원본을 보존하고 완전한 앞선 행만 복구하여 partial로 처리한다. 마지막 줄이라도 개행이 있는 잘못된 JSON, 중간 손상·순서/실행 식별 충돌은 추정 복구하지 않고 전체 중단한다. 손상 파일에 이어 쓰거나 잘린 끝을 자동 삭제하지 않는다.

이전 Excel-only 자료는 명시적인 읽기 전용 이관으로 처리한다. 형식·실행 연결이 충돌하면 자료를 보존하고 중단한다. 다운로드는 별도 로컬 앱의 기능이며 수집 후처리에 추가하지 않는다.
