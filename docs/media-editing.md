# 이미지 크롭·영상 캡처·구간 자르기

게시글 상세 우측 하단의 **편집**은 현재 캐러셀 항목에 적용한다. 로컬에 저장된 파일만 편집하며 원본을 덮어쓰지 않는다. 상세를 열거나 캐러셀에서 영상을 선택하면 현재 영상이 자동재생된다. 그리드 영상은 자동재생하지 않는다. 상세를 닫거나 다른 첨부로 이동하면 이전 영상은 종료한다.

- 이미지: 기본은 원본 비율과 전체 영역이다. 원본·자유·1:1·4:5·3:4·9:16·4:3·16:9를 선택할 수 있다. 모서리 드래그로 크기, 영역 안 드래그 또는 방향키로 위치를 조절하고 **편집본 저장**을 누른다. Shift+방향키는 10픽셀씩 이동한다. EXIF 방향을 적용한 이미지 좌표로 크롭하며 출력 크기를 표시한다.
- 영상 캡처: 편집을 연 뒤 **이미지 캡처**를 선택하고 **이미지로 캡처**를 누른 시점의 프레임을 PNG로 저장한다. 재생 중과 일시정지 상태 모두 가능하다. 인코딩을 기다리기 전에 프레임을 고정하며 재생을 멈추거나 다른 장면으로 이동하지 않는다. 연속 캡처할 수 있고 아직 프레임이 준비되지 않았으면 안내한다.

- 영상 구간 자르기: **편집 → 구간 자르기**에서 시작·종료 시간을 초 단위로 지정한다. 기본은 전체 구간이며 소수 초도 입력할 수 있다. **구간 미리보기**는 지정한 시작점에서 재생하고 종료점에서 멈춘다. **새 영상 만들기**는 해당 구간을 MP4로 생성한 뒤 새 편집본으로 이동한다. 예: 5초 영상에서 2~4초를 선택하면 약 2초 영상이 된다. 원본에 소리가 있으면 함께 포함한다. 잘라낸 영상도 다시 구간 편집하거나 이미지로 캡처할 수 있다.

결과는 원본 첨부 다음에 생성 순서대로 추가한다. 목록과 상세에서 같은 순서로 보여주며 `편집본` 표시가 붙는다. 편집본을 다시 크롭할 수도 있다. 원본 게시글 유형 배지, 완료 게시글 판단, 대기 다운로드 수는 원본 첨부만 기준으로 유지한다.

## 저장과 내보내기

앱이 기존 SQLite에 선택적 `media_edits` 테이블을 추가하고, 이미지 PNG 또는 영상 MP4를 `media/files/<library UUID>/<edit UUID>.<png|mp4>`에 저장한다. 편집 레코드는 원본 ID·생성 순서·시각·크롭 좌표·캡처 시각 또는 자른 시작/종료 초·파일 크기·해시를 보관한다. Excel과 원본 파일, 다운로드 작업·요청 이력·정책·대기 정보는 변경하지 않는다. 새로고침과 앱 재실행 후에도 결과를 읽는다.

IPC는 게시글 키와 등록된 로컬 미디어 ID로만 저장을 요청한다. 잠금을 획득하고 입력·원본 연결·크기·해시를 확인한 뒤 새 파일과 레코드를 저장한다. 실패·취소 시 미완성 결과를 정리하며, 저장 성공 뒤 목록 갱신만 실패한 경우에는 재저장을 유도하지 않고 새로고침을 안내한다. 편집 저장과 폴더 전환·다운로드·ZIP 저장의 중복 실행을 막는다.

이미지 처리는 한 변 8192픽셀, 전체 4천만 픽셀, PNG 64MiB까지 지원한다. 투명도는 보존하며 PNG에는 EXIF 등 원본 부가 메타데이터를 복사하지 않는다. GIF 등 움직이는 이미지는 크롭 시 첫 프레임의 정지 이미지가 된다.

`게시글ID.zip`에는 원본 첨부 뒤에 편집 PNG와 MP4도 생성 순서대로 포함한다. 파일 이름은 기존 순번을 이어 `03.png`, `04.mp4`처럼 정하고 `게시글정보.txt`의 계정명·수집일·원문 주소·캡션은 유지한다. 누락·손상된 편집 파일이나 읽을 수 없는 편집 기록은 일부만 내보내지 않도록 차단한다.

## 검증

임시 합성 자료를 사용하는 자동 검사로 비율·경계·정수 좌표, EXIF 방향 적용 크롭, 캡처 PNG 정규화, 재편집 순서와 재조회, 원본·기존 DB 행 보존, 오류·취소·경합과 ZIP 구성을 검증한다. TypeScript 257개와 Python 246개 테스트, lint·typecheck·format 검사를 통과했다. Mac Electron의 별도 합성 자료에서 원본 비율 기본값, 1:1 선택, 모서리 크기 조절·영역 이동, 크롭 저장, 정지 프레임과 재생 중 프레임 캡처, 재생 유지, 원본 뒤 추가, 새로고침·앱 재실행 후 보존, EXIF 방향 적용을 확인했다. UI로 저장한 ZIP에서 원본 2개·편집 PNG 3개·게시글정보.txt 구성, 원본/편집 파일과 ZIP 내용의 바이트 일치, 원본·Excel 해시 불변을 확인했다. Windows 실기 검증은 최종 단계에 남는다.

## 삭제

그리드에서 편집본 미디어 우측 하단의 삭제 아이콘으로 확인 후 해당 파일을 삭제한다. 그 편집본에서 만든 다른 편집본은 유지한다. 게시글 전체 삭제는 원본과 모든 편집본을 함께 삭제한다. [삭제와 Excel 기록 계약](media-deletion.md)을 따른다.

## 영상 구간 처리

로컬 ffmpeg·ffprobe를 사용하며 원격 요청은 없다. H.264 영상과 원본의 첫 오디오 트랙을 AAC로 다시 인코딩해 시작점을 맞춘다. 결과 영상의 길이는 프레임 경계와 오디오 인코딩 지연만큼 차이가 날 수 있다. 음성이 없는 원본에는 소리를 추가하지 않는다. 메타데이터·챕터·자막은 출력하지 않는다.

원본과 결과를 검증하고 임시 결과 파일을 단독 생성한 뒤 등록한다. 기존 이미지 편집 테이블은 첫 구간 저장 트랜잭션에서 `trim`과 `trim_start/trim_end`를 지원하도록 확장한다. 기존 편집 ID·생성 순서·값, 원본·Excel·다운로드 이력은 유지한다. 구간 편집 저장 중에는 추가 저장·첨부 이동·상세 닫기를 막으며, 앱 종료 요청은 인코더를 취소하고 미완성 파일을 정리한다. 영상 분석은 단계당 30초, 인코딩은 30분, 전체 worker는 32분, 결과는 8GiB 상한이다. 기존 이미지 저장과 다운로드의 제한 시간은 바꾸지 않는다.

## 2026-09-22 영상 구간 검증

TypeScript 351개와 Python 304개 검사 및 lint·typecheck·format을 통과했다. Mac 별도 Electron 합성 자료에서 상세 진입·첨부 전환·새 영상 선택 시 자동재생, 2~4초 미리보기 후 정지, 새 MP4 캐러셀 추가, 새 영상 캡처, 전체 길이 기본값 재편집을 확인했다. 합성 5초 영상의 2~4초 결과는 영상 스트림 2.000초이며 AAC 소리도 유지됐다. ZIP의 원본·편집 MP4·캡처 PNG가 저장 파일과 바이트 단위로 일치하며 원본/Excel 해시는 그대로다. AAC 마지막 패킷 때문에 HTML 영상 길이가 조금 긴 경우도 다시 편집 가능하도록 검사했다. 실제 사용자 영상 편집·원격 요청과 Windows 실기 검증은 수행하지 않았다.
