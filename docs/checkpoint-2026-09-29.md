## 완료한 기능

| 영역      | 현재 동작                                                                                                                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 수집      | 요청마다 계정당 새 미디어 원글 2개가 기본이다. 사용자가 요청별 건수를 바꿀 수 있고 하루 수집 횟수 상한은 없다. 플러그인은 Excel 확정까지 담당한다.                                                                  |
| 다운로드  | 앱이 미완료 첨부를 내려받고 비정상 종료 뒤 명시적 재개를 제공한다. 첫 이미지·영상의 SHA-256을 먼저 비교하고, 불일치하면 첫 이미지의 pHash를 최근 50개와 비교해 중복인 새 글 전체를 제거한다. 기존 작업이 있는 글은 자동 삭제하지 않는다.        |
| 편집      | 이미지 크롭, 영상 프레임 캡처, 구간 자르기와 음소거를 제공한다. 종료(초) 오른쪽의 음소거는 기본 해제이며 선택 시 새 편집본에서 오디오 트랙을 제거한다. 전체 길이에 적용할 수도 있고 원본은 보존한다.                |
| 등록·캡션 | 한 원글 안에서 원본·편집본을 선택·정렬하고 캡션과 댓글 정보를 저장한다. 영어·한국어·일본어 캡션은 각 언어의 Threads 구어체와 원문 근거를 사용하며 자동 게시하지 않는다. AI 이미지 생성은 개발 실행 전용이다.        |
| 계정      | API 토큰만 입력한다. 저장된 실제 만료 시각이 없을 때 `debug_token`과 계정 정보를 확인하고 OS 암호화 저장한다. 토큰 교체·해제와 만료 전 갱신을 제공한다.                                                             |
| 파일 서버 | 관리자가 발급한 연결 코드를 설정에 저장한다. 미디어를 독립 파일 서버로 전송하고 반환 URL을 Threads에 전달한다. 앱에서 개발자 AWS 키·S3 환경변수를 사용하지 않는다.                                                  |
| API 게시  | 저장된 원글과 텍스트 댓글을 별도로 확인 후 전송한다. 댓글은 앱에서 게시한 원글의 직접 답글이다. 성공 ID와 이력을 보관하고 중복·결과 불명 자동 재전송을 차단한다.                                                    |
| 진행·알림 | 게시글·댓글 업로드와 수동 통계 조회는 잠금 레이어를 사용한다. 성공·실패·입력 오류는 중앙 상단 토스트다. 등록 완료·댓글 완료 배지를 목록과 상세에 즉시 반영한다.                                                     |
| 통계      | 현재 계정으로 앱에서 게시한 최신 원글 5개의 조회·좋아요·댓글 수만 조회한다. 앱 시작 시 오늘 미조회이면 백그라운드에서, 계속 켜져 있으면 현지 오전 10시에 조회한다. 수동 조회도 가능하며 게시 직후 자동 조회는 없다. |
| 보관·복구 | 수집과 등록은 독립 삭제한다. 한쪽에라도 남으면 선택하지 않은 원본을 포함한 전체 미디어를 유지한다. 마지막 삭제에서 원본·편집본·검증된 AI 파일을 정리하고 실제 Threads 게시글·댓글과 API 이력은 유지한다.            |

## 데이터와 운영 경계

- Excel은 수집 원본, `state/state.db`는 로컬 작업 상태, `media/`는 파일, JSONL은 수집 중 임시 복구 자료다. 수집 플러그인은 앱 DB를 변경하지 않는다.
- Threads 토큰·파일 서버 코드·게시 이력은 앱 userData의 OS 암호화 저장소에서 관리한다. 라이브러리 DB 복원이 원격 게시 이력을 되돌리지 않는다.
- 파일 서버의 링크 유효기간은 1시간이며 서버는 시작 시 및 3시간마다 만료 파일을 정리하도록 구성했다. 앱은 로컬 전송용 복사본을 정리하고 원격 삭제를 요청하지 않는다. 프록시 캐시의 동작과 원격 물리 삭제는 이 소스 검사의 범위가 아니다.
- 수집에 이미지 3개, 등록 선택에 2개가 있는 경우 수집만 삭제해도 원본 3개와 편집본을 모두 유지한다. 등록에서 미디어를 다시 선택할 수 있으며 마지막 등록 삭제에서만 정리한다.
- 공개 소스에는 토큰·연결 코드·개인 `.env`·Excel·DB·미디어·세션·테스트 결과물을 포함하지 않는다. `.env.example`에는 인증값 없는 설명만 둔다.

## 2026-09-29 추가 검증: 로컬 pHash 중복 정리

- 기존 전체 저장 글의 첫 이미지·첫 영상 SHA-256 검사를 유지하고, 불일치한 첫 이미지만 계정 구분 없이 최근 수집한 첫 이미지 50개와 비교한다. pHash는 64비트 완전 일치만 인정한다.
- Python 표준 라이브러리와 기존 Pillow로 앱 내부에서 실행한다. AI 모델·Codex·외부 API·추가 설치 의존성은 필요 없다. 캐시는 버전·SHA-256별로 저장하고 삭제 직전 두 파일의 해시를 다시 계산한다. [세부 계약](media-deletion.md)을 따른다.
- Python 전체 **513개**, TypeScript 전체 **32개 파일 / 1,024개** 테스트와 타입·린트·포맷 검사를 통과했다. Python에는 재압축·리사이즈, 계정 간 비교, 최근 50개 경계, 그보다 오래된 SHA-256 중복, 캐시 오염·파일 변경·기존 작업 보호 검증을 추가했다.
- 사용자 요청으로 이미 다운로드한 새 게시글 **8개**에 실제 앱의 다운로드 후 중복 정리 함수를 실행했다. SHA-256 중복 0개, pHash 중복 **1개**를 찾아 새 게시글 전체와 첨부 이미지 **2개**를 삭제했다. 새 글 7개와 기존 비교 글을 보존했고 수집 목록은 **24개 → 23개**가 됐다.
- 실행 전 Excel·DB·삭제 대상 파일을 자료 폴더에 백업했다. 기존 나머지 파일 해시, 계정 Excel, 원문·수집 기준·등록·편집·요청·대기·다운로드 이력의 불변과 삭제 표식·저널 완료를 확인했다. 검증 중 Python의 네트워크 연결·외부 프로그램 실행을 차단했으며 추가 다운로드나 AI 호출은 없었다.
- Windows 실기·설치·업데이트 검증은 아직 수행하지 않았다.

- 기존 Windows CI 성공 수치는 이 추가 변경 이전의 결과다. 새 내장 CLI의 Windows 실행과 실제 브라우저 로그인·생성·업데이트 후 유지 검증은 남아 있다. [상세 계약](chatgpt-connection.md)을 따른다.

## 2026-09-29 수정: Mac 앱 전용 CLI와 캡션 인증

- Mac 개발 앱도 Windows와 같은 버전의 앱 전용 Codex CLI를 사용한다. `pnpm start`가 공식 arm64/x64 파일을 해시 검증해 준비하고, 전역 Homebrew/PATH 실행기를 사용하지 않는다. Mac 설치 파일 배포 범위는 변경하지 않았다.
- 로그인 상태는 연결됨이지만 캡션 요청에 인증이 실리지 않는 401 오류를 재현했다. 인증 설정을 `exec` 다음으로 이동해 해결했다. 기존 앱 전용 로그인과 OS 보안 저장소, 읽기 전용 실행·도구 제한을 유지한다. 이 인자 수정은 Windows 캡션에도 적용된다.
- Mac arm64의 실제 앱 전용 CLI와 기존 로그인으로 `CaptionGenerator`의 전체 생성 경로를 실행해 합성 이미지에서 한국어 제안 **3개**를 확인했다. 합성 원본·Excel·DB 작업 이력을 보존했다. Windows·Intel Mac 실제 실행 성공으로 확대 해석하지 않는다.
- 추가 수정 후 Mac 전체 검사: TypeScript **1,084개**, Python **528개**, 린트·타입·포맷 통과. 앱을 재실행해 기존 ChatGPT 연결과 수집 23개·등록 3개가 유지됨을 확인했다.

이번 체크포인트는 사용자 요청에 따라 소스·테스트·문서만 GitHub에 올린다. 빌드 실행 파일·인증정보·사용자 자료는 제외한다. 커밋의 `[skip ci]`로 자동 CI·설치 후보 생성을 건너뛰며, 최신 변경의 Windows 검증과 Release 배포는 다음 작업으로 남긴다.

## 다음 배포 단계

기능 개발 완료와 Windows 배포 준비 완료는 구분한다.

1. Windows에서 Python·Pillow·ffmpeg·ffprobe·Codex CLI 의존성 및 앱 경로·잠금·종료·OS 암호화·기존 자료 보존 검증.
2. Windows 런타임 번들과 Squirrel installer 생성·내장 실행기 자동 검사는 완료했다. 새 설치·제거/재설치, 자동 업데이트 구현과 버전 간 갱신 검증이 남아 있다. [Windows 검증](windows-validation.md)을 따른다.
3. 검증 뒤 별도 버전 결정과 설치 파일·GitHub Release 배포. 이번 작업은 소스 체크포인트이며 버전 `0.1.0`을 유지한다.

현재 배포 가정은 같은 Meta 앱의 Threads 테스터 계정이다. 일반 외부 사용자 지원 시 토큰 검사·앱 검수 구성은 [API 계약](phase-3-threads-api.md)을 다시 확인한다. 자연 만료·철회·OS별 보안 저장·원격 정리의 장기 운영 전체를 한 번의 실제 게시 시험으로 검증했다고 해석하지 않는다.

2026-09-29 사용자 결정으로 DB 백업·복원은 컴퓨터 이전용으로 한정한다. 작업 폴더 전체와 백업을 함께 옮겨 기존 파일을 다시 받지 않고 사용한다. 복원 때문에 다운로드 보류를 새로 만들지 않으며 원래 요청·대기·중단은 유지한다. 구버전의 복원 보류만 검증된 폴더 재연결·복원에서 해제한다. 게시 완료·결과 불명 이력은 작업 폴더의 이전 파일을 통해 보존하고 Threads 토큰·파일 서버 연결코드는 새 PC에서 다시 입력한다. 유실 자료 재구성·별도 이력 검토 및 보류 해제 화면은 잔여 업무에서 제외했다. [컴퓨터 이전 절차](database-maintenance.md)를 따른다.

다음 대화에서는 이 문서를 기준으로 작업 범위를 정하고, 개인 자료와 실제 Threads 게시물은 명시적 요청 없이 변경하지 않는다.
