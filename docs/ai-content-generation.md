# AI 이미지와 제품 홍보 초안

2026-09-22 사용자가 API 연동 전에 요청한 로컬 시험 기능이다. 개발 실행에서만 제공하며 배포 앱에서는 비활성화한다. 기존 등록 폼의 **AI 캡션**과 별도로, 수집 상세 화면 왼쪽 아래 **AI 생성**에서 원본 이미지와 원문 캡션을 분석하고 새 이미지와 Threads 캡션을 함께 만든다.

## 제품 홍보 설계

제품명이 없는 입력이 대부분이라는 사용자 결정을 기본값으로 적용한다. 이름이 없다는 이유로 질문하거나 중단하지 않는다. 이미지와 캡션에서 제품군, 소비자의 고민, 보여주려는 변화, 원본의 홍보 흐름을 읽고 이름 없는 제품 홍보로 작성한다. 제품명·성분·가격·효능 수치를 임의로 만들지 않는다.

원본은 비율·대략적인 촬영 거리와 구도·피사체 비중·핵심 제품 홍보 컨셉의 참조로만 사용한다. 얼굴이 보이면 일부만 보이는 경우도 원본과 다른 얼굴의 가상 인물로 만들고, 의상·배경·포즈도 모두 분명히 바꾼다. 신체 일부나 사물 클로즈업은 동작 또는 배치와 배경을 바꾼다. 원본의 인물·옷·장소를 유지한 보정이나 거의 같은 사진은 목표가 아니다. 색감·조명·작은 화각 변화만으로는 충분하지 않다.

분석·캡션·실행 규칙과 이미지 생성용 문구를 구분한다. Codex는 유지할 컨셉과 변화 의도를 `concept`에 간단히 설명하고, 이미지 도구에는 홍보 용도·유지할 촬영 범위·해당 사진에 적용되는 필수 변화 전체를 영어 100단어 이내의 짧은 문단으로 전달하도록 요청한다. 구체적인 얼굴 생김새·옷 종류·장소·포즈는 지시하지 않고 이미지 모델이 선택하게 한다. 사용자가 매번 변주 방향을 정할 필요가 없어야 한다. 원본 세부를 장황하게 다시 묘사하거나 특정 게시글의 해법을 공통 지침에 고정하지 않는다.

- 인물과 신체 일부는 25세 이상의 가상 성인 여성으로 설정한다. 얼굴은 원본 촬영 범위에 맞으면 허용하고, 신체 일부 클로즈업을 인물 전경으로 바꾸지 않는다.
- 원본이 강조하는 제품 관련 시각적 매력과 홍보 흐름을 유지한다. 제품과 무관한 인물 사진이나 일반적인 일상 문구로 흐르지 않도록 요청한다.
- 캡션은 제품군과 홍보 포인트가 드러나는 자연스러운 Threads 구어체이며 부드러운 행동 유도를 포함한다. 입증되지 않은 치료·발모 효과, 가상의 실제 사용 후기, 매장 추천 사실을 만들지 않는다.
- 영어가 기본이고 결과 화면에서 한국어·일본어를 선택해 다시 생성할 수 있다. 캡션은 앱의 이번 시험 기준으로 450 Unicode 문자 이내다. 실제 Threads API 제한 검증을 의미하지 않는다.

## 개발 실행과 작성 화면

AI 이미지 기능은 Electron main의 `app.isPackaged === false`를 기준으로 활성화한다. Renderer는 main의 capability를 확인하기 전에는 버튼과 AI 후보를 표시하지 않는다. 배포 앱은 AI 생성·조회·폴더 열기·캡션 복사 요청과 AI 전용 미리보기를 차단하고, 이미지 준비·등록·ZIP worker에도 AI 허용 플래그를 전달하지 않는다. `NODE_ENV`나 renderer 입력으로 이 제한을 해제하지 않는다. 기존 등록 화면의 AI 캡션 생성 기능은 이 이미지 시험 기능과 별개로 유지한다.

개발용 작성 화면은 **원본 → 편집본 → AI 생성본** 순서로 같은 원글의 자료를 표시한다. 완료된 AI 버전은 생성 시각 순서로 모두 표시하며 각 버전 안에서는 이미지 순서를 유지한다. 새 생성 직후에도 작성 화면에서 읽을 수 있다. 자동 선택·캡션 적용·등록은 하지 않는다.

AI 생성본은 `Post.aiImages`로 구분하며 기존 원본이나 편집본으로 복사하지 않는다. 게시글 폴더·생성 ID·파일명에서 계산한 고정 미디어 ID로 등록 선택을 저장한다. 등록 조회·순서 변경·선택 이미지의 AI 캡션 입력·등록 ZIP에 사용할 수 있으며 재생성이나 재시작 후에도 기존에 선택한 버전을 유지한다. 일반 수집 ZIP과 AI 이미지 생성의 원본 전용 입력은 계속 원본·편집본 및 원본만이라는 각자의 기존 범위를 유지한다.

Manifest의 원글·원본 ID·생성 ID·생성 시각·이미지 목록과 해시, 제한된 상대 경로를 검증한다. 심볼릭 링크·하드링크·다른 원글의 생성본·변조 파일은 채택하지 않는다. 파일이 사라져도 등록된 ID를 조용히 삭제하거나 다른 버전으로 바꾸지 않는다. 배포 앱에서 개발용 AI 이미지를 선택한 등록을 열면 ID는 보존하며 해당 미디어는 사용 불가로 표시한다.

SQLite 스키마 변경은 없다. DB 복원은 해당 원글의 AI 파일 소유권과 해시도 확인한다. DB 백업에는 AI 이미지 파일이 포함되지 않는다. AI 초안 폴더는 별도 보관 자료로 유지하므로 원글 삭제나 등록 삭제가 생성 이력을 함께 삭제하지 않는다.

## 입력과 실행

Renderer는 게시글 키와 언어만 전달한다. Main과 Python은 해당 원글의 `attachments`에서 이미지 전체를 원래 순서로 선택하며 `edits`와 영상은 제외한다. 일부 원본이 누락되면 생성을 막고, 이미지 20장 입력 상한을 넘으면 일부를 조용히 생략하지 않는다. 영상 프레임 추출은 없다.

기존 이미지 준비 실행기로 크기와 총 용량을 제한하고 메타데이터를 제거한 임시 사본을 만든다. Codex에는 이 이미지들과 원문 캡션만 전달한다. 수집 폴더·Excel·DB·원문 URL·사용자 인증 정보를 프롬프트에 넣지 않는다. 원문과 이미지 안의 명령은 신뢰하지 않는 참조 데이터로 취급한다.

Codex CLI의 기존 로그인을 사용한다. `--ignore-user-config`, 읽기 전용 sandbox, ephemeral 모드와 JSON schema를 사용하며 이미지 생성 도구만 활성화한다. 셸·브라우저·웹 검색·앱·플러그인·다중 에이전트·메모리 등은 비활성화한다. API 키를 전달하지 않고 API 방식으로 자동 대체하지 않는다. 실행은 인자 배열과 stdin을 사용하며 셸 문자열로 캡션을 실행하지 않는다.

이번 시험은 원본 이미지 한 장이면 결과 한 장, 두 장 이상이면 결과 두 장을 만든다. 결과 1·2는 각각 원본 1·2의 구도에 대응하며 나머지 원본은 보조 맥락으로 분석한다. 준비한 원본 경로와 대응 순서를 명시하고, 각 이미지 생성 도구 호출에 해당 원본을 시각 참조로 포함하도록 요청한다. 사진별 세로·가로 방향과 대략적인 비율을 유지하며 일괄 4:5 크롭을 강제하지 않는다. 동시 작업·중복 클릭을 막고, 준비 2분·생성 10분 제한 및 창 닫기·앱 종료 시 취소와 임시 입력 정리를 제공한다. 모델의 종료 코드만으로 성공 판정하지 않는다. 새 파일 경로, 생성 시각, 파일 크기·형식·디코딩, 결과 개수, 캡션 형식을 검증한다.

## 초안 저장과 확인

완성된 결과는 연결한 작업 폴더의 `ai-drafts/<게시글 키 해시>/<생성 ID>/`에 보관한다.

- `01.png`, `02.png` 등: 실제 생성 파일. 지원 형식은 PNG/JPEG/WebP다.
- `caption.txt`: Threads 캡션 초안.
- `draft.json`: 원글 키와 원본 이미지 ID, 생성 시각, 언어, 분석·컨셉·프롬프트, 파일 해시, AI 생성·검토 대기 표시.
- 상위 `latest.json`: 마지막 완성 초안의 ID. 파일 저장을 마친 뒤 교체하며 재생성 시 이전 초안은 보존한다.

이미지 미리보기, 캡션 복사, 초안 폴더 열기와 다시 생성을 제공한다. 같은 원글에서 AI 생성을 다시 열면 저장된 최신 초안을 읽으며, 재생성은 **다시 생성**을 눌러야 실행한다. 파일 누락·변경을 성공으로 표시하거나 자동 재생성하지 않는다.

미리보기는 검증한 이미지 바이트만 `threads-media://ai/<생성 ID>/<순서>`로 제공한다. 원격 URL과 임의 파일 경로는 허용하지 않는다. 저장된 초안을 읽을 때도 파일 해시와 디코딩을 확인한다.

AI 초안은 기존 SQLite `post_drafts` 등록과 별도다. 원문·원본·편집본·기존 등록 내용을 덮어쓰지 않으며 자동 등록·Threads 게시·API 연결을 수행하지 않는다. 이번 기능은 생성 품질과 로컬 초안 흐름의 검증 단계다. DB 단독 백업에는 AI 초안 파일이 포함되지 않으므로 이전 시 작업 폴더 전체를 함께 옮긴다.

- 원본 전체·편집본 제외·영상 제외·입력 상한·명령 데이터 구분·취소·중복 실행·CLI 성공 후 이미지 누락·원본 재사용 거절·손상 파일·심볼릭 링크·저장 후 재조회·해시 변경을 검사했다.
- 두 번째 헤어케어 게시글의 원본 이미지 2장과 캡션으로 실제 CLI 사전 시험을 수행했다. 홍보 메시지와 매끄러운 모발 표현을 보완한 뒤 별도 Electron 창에서 상세 버튼 → 실제 Codex 생성 → 새 이미지 2장과 영어 캡션 → 로컬 저장 → 미리보기 → 재열기 → 캡션 복사를 확인했다.
- 같은 초안을 다시 열었을 때 생성 ID가 유지되며 추가 생성 호출이 없었다. 540px 화면에서 본문과 모달의 가로 넘침이 없었다. renderer의 외부 네트워크 요청과 JavaScript 예외는 0건이었다. Codex CLI의 생성 통신은 별개다.
- 기존 개발 앱에 미저장 입력·진행 중 다운로드가 없음을 확인한 뒤 재시작했다. 새 main/preload에서 저장된 같은 생성 ID와 이미지 2장을 불러왔으며 추가 생성 없이 결과 화면을 열어 두었다.
- 실제 수집 폴더의 기존 33개 파일 SHA-256이 모두 동일했다. Excel·DB·원본·편집본·기존 등록 내용을 보존했고 새 AI 초안의 5개 파일만 추가했다.
- 결과는 4:5 이미지 2장과 캡션으로 구성된다. 첫 장은 욕실의 모발 고민, 둘째 장은 창가의 매끄럽고 윤기 있는 긴 머릿결이며 인물은 가상 성인 여성으로 생성했다. 제품명이 없는 헤어케어 트리트먼트 카테고리 홍보 초안이다.

### 원본 구도 유지 보정

같은 날 사용자는 두 번째 모발 사진의 컨셉은 적절하지만 첫 번째가 손 클로즈업에서 인물 전경으로 바뀌어 원본의 힘이 약해졌다고 평가했다. 이 피드백에 따라 광범위한 장면·구도 변경 지침을 없애고, 사진마다 `COMPOSITION TO KEEP`·`SNS EMPHASIS`·`LIMITED VARIATION`을 명시하도록 변경했다. 원본 순서와 이미지 생성 참조 경로도 함께 전달한다.

첫 사진만 `codex exec`로 다시 생성해 젖은 손바닥·빠진 머리카락·욕실 배경 구도가 유지되고 모발의 대비와 물기가 강화된 것을 시각 검토했다. 결과는 941×1672 PNG이며, 사용자가 선호한 두 번째 생성 사진과 기존 AI 초안은 교체하지 않았다. 이 단일 사진 시험은 앱의 두 장 전체 재생성 시험과 구분한다.

관련 TypeScript 69개 테스트·타입 검사·변경 파일 lint·format·diff 공백 검사를 통과했다. 기존 작업 폴더 38개 파일의 해시가 모두 동일했다. 비교 이미지, 실제 생성 프롬프트, 요청, 결과와 검증 기록은 Git에서 제외된 `outputs/ai-composition-test-2026-09-22/`에 보관한다. CLI 이벤트에는 이미지 도구 인자가 노출되지 않으므로 참조 경로 전달과 생성 결과 구도까지 확인했으며 내부 도구 인자 검증으로 표현하지 않는다.

### 동작·형태·장소 변주 보정

위 손 클로즈업 후보는 사용자 검토에서 원본과 거의 동일하다는 평가를 받았다. 당시 기준은 촬영 거리·화각·피사체 비중과 홍보 컨셉은 유지하되, 동작·형태·배치 중 적어도 하나를 눈에 띄게 바꾸는 것이다. 다른 장소·배경도 허용하며 빛·색감만 바꾸는 변주는 충분하지 않다. 프롬프트를 `FRAMING TO KEEP`·`VISIBLE CHANGES`·`SNS EMPHASIS`로 나누고, 원본 이미지는 촬영 방식의 참조로 사용하면서 변경할 형태를 구체적으로 지정한다.

이번에는 첫 사진만 `codex exec`로 생성해 한 손에서 양손을 모은 동작으로 바뀌고, 머리카락의 배치와 밝은 세면대 배경이 달라진 것을 시각 검토했다. 촬영 거리와 손·머리카락 중심의 세로 클로즈업은 유지했다. 비교 후보는 941×1672 PNG이며 `outputs/ai-composition-test-2026-09-22/v3/`에 실제 프롬프트·요청·결과·검증 기록과 함께 보관했다. 기존 작업 폴더 38개 파일, 사용자가 선호한 두 번째 사진과 이전 비교 후보는 보존했다. 관련 69개 테스트·타입 검사·변경 파일 lint·format·diff 검사를 통과했다. 앱에는 새 지침을 반영하되 기존 저장 초안은 교체하지 않았다.

### 자동 변주와 짧은 이미지 지시

이 단계의 사용자 요구는 매 게시글에 양손·장소 같은 방향을 직접 지정하지 않아도 자동으로 변주가 적용되는 것이다. 공통 실행 지침에서 특정 손·모발·욕실 예시를 제거하고, Codex가 원본에 적합한 변화를 스스로 선택해 영어 100단어 이내의 이미지 지시로 작성하도록 단순화했다. 이전 양손 후보는 구체적인 동작과 배경을 별도 지정한 시험이었으며 자동 선택의 근거로 사용하지 않는다.

공통 지침, 원본 이미지 2장과 원문 캡션만 전달한 단일 사진 시험에서 Codex는 손을 옆으로 기울여 오므리는 동작과 대각선 모발 배치를 자동 선택했다. 이미지 지시는 86단어였다. 하지만 실제 이미지 도구가 HTTP 400 `moderation_blocked`, 출력 단계 안전 필터 차단을 반환해 새 이미지 파일은 없었다. 자동 선택·짧은 프롬프트 작성까지 검증했으며 이미지 생성 성공이나 품질 검증으로 기록하지 않는다. 앱은 빈 이미지 결과를 실패로 처리하며 기존 초안을 교체하지 않는다.

관련 69개 테스트·타입 검사·변경 파일 lint·format·diff 검사를 통과했다. 기존 작업 폴더 38개 파일의 해시가 동일했다. 요청·자동 선택 결과·실제 프롬프트·오류 로그·검증 기록은 `outputs/ai-composition-test-2026-09-22/v4-auto/`에 보관한다. 참고 원칙은 [OpenAI 이미지 프롬프팅](https://developers.openai.com/api/docs/guides/image-prompting)의 유지 조건과 변경 사항 구분, 참조 이미지 역할 지정이다. 100단어 기준은 이 앱의 간결한 지시를 위한 설계 선택이다.

### 사용자 요청에 따른 기존 생성물 정리

사용자가 기존 생성물을 지우고 다시 시험하도록 요청했다. 해당 게시글의 AI 이미지 6종에 한정해 앱 초안·비교 후보·CLI 생성 캐시의 중복 사본을 포함한 이미지 10개와 초안 메타데이터 3개를 휴지통으로 옮겼다. 각 대상은 초안 manifest, 실제 생성 결과 경로와 SHA-256 일치로 출처를 확인했다. 수집 원본·편집본·DB·기존 등록 등 33개 파일은 해시가 동일했다. 과거 시험의 이미지 링크는 정리되어 더 이상 활성 결과를 가리키지 않으며, 텍스트 검증 기록과 화면 캡처는 당시 이력으로 남긴다. 정리 대상·이동 경로·해시는 Git에서 제외된 `outputs/ai-regeneration-test-2026-09-22/cleanup.json`에 기록한다.

정리 후 실제 앱의 AI 생성 버튼으로 원본 2장과 원문 캡션을 전달해 새 이미지 2장과 영어 캡션의 생성·저장·미리보기에 성공했다. 손·장소에 관한 별도 지시를 추가하지 않았고, Codex가 첫 사진의 손가락 자세·모발 배치와 두 번째의 어깨 각도·모발을 들어 올리는 동작을 자동 선택했다. 이미지 프롬프트는 각각 83·86단어였다. 이미지 크기는 941×1672, 1346×1168이며 원본 비율과의 차이는 각각 0.1% 미만이었다. 새 파일의 디코딩·해시·최신 초안 포인터를 확인했고, 원본·편집본·DB 등 기존 33개 파일은 모두 그대로였다. ### 얼굴·의상·배경·포즈를 모두 바꾸는 범용 재구성

앞선 자동 변주 결과는 사용자 검토에서 얼굴·의상·배경이 너무 비슷해 사용하기 어렵다는 평가를 받았다. 변주를 1~2개만 고르던 규칙을 제거하고, 원본의 참조 범위를 비율·대략적인 촬영 거리와 구도·피사체 비중·홍보 컨셉으로 좁혔다. 보이는 얼굴은 일부만 보이더라도 다른 얼굴 특징으로 생성하며, 의상·배경·포즈도 모두 바꾸도록 요청한다. 신체 일부와 사물은 동작 또는 배치와 배경을 바꾼다. 구체적인 외모·옷 종류·장소·동작은 지정하지 않고 이미지 모델이 선택한다.

실제 앱의 첫 재생성은 완성된 이미지 목록 없이 실패했다. 생성 캐시에서 부분 결과 한 장을 확인했으나 실패 원인은 앱 응답만으로 구분할 수 없어 특정 안전 필터나 사용 한도 문제로 단정하지 않았다. 같은 지침으로 한 번 더 실행해 두 장과 영어 캡션의 생성·저장·미리보기를 완료했다. 실패 기록과 부분 결과도 별도로 보존했다.
