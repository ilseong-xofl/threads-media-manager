# 2026-09-22 소스 체크포인트

Phase 2의 로컬 게시글 작성과 다운로드 복구·라이브러리 관리를 구현한 시점의 정리다. 소스 저장소는 공개 [ilseong-xofl/threads-media-manager](https://github.com/ilseong-xofl/threads-media-manager)이며 이번 작업 브랜치는 `codex/phase-2-registration`이다. GitHub 소스 보관과 설치 파일·Release·자동 업데이트 배포는 구분한다.

## 완료한 구현

| 범위           | 현재 동작                                                                                                                                                        |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 수집과 열람    | 플러그인은 날짜별 Excel 수집까지 담당. 앱은 모든 첨부의 다운로드가 완료된 게시글을 표시하며 검색·계정·날짜 필터, 최대 4열, 12개/24개 페이지와 무한 스크롤 제공   |
| 로컬 편집·삭제 | 이미지 비율 크롭, 영상 프레임 캡처·초 단위 구간 편집. 확인 후 편집본/게시글 파일 삭제와 Excel 삭제 표시. 원본과 편집본을 구분하고 ZIP에 포함                     |
| 게시글 작성    | 한 원글의 원본·편집본에서 선택·캐러셀 확인·순서 변경. 원글당 하나의 등록 내용을 SQLite에 저장하고 조회·수정·삭제·선택 순서 ZIP 제공                              |
| AI 캡션        | 로컬 Codex CLI에서 영어(기본)·한국어·일본어 제안 3개 생성·재생성. 원본 캡션의 의미·말투·흐름이 우선이며 이미지만 보조 자료로 전달. 영상 전용 선택은 비활성       |
| 등록 댓글      | 등록 게시글 상세에 댓글 캡션·링크 저장·수정. 링크는 외부 브라우저로 열기. 수집 상세에는 댓글 대신 수집·파일 정보 표시                                            |
| 다운로드 복구  | 사용자 중지 버튼 제거, 실행 중 정상 종료 차단. 비정상 종료 뒤 상태 조회와 명시적 이어서 다운로드. 완료 파일·기존 시도·대기·요청 이력을 보존하며 남은 대상 재검증 |
| 폴더 설정      | 기억된 작업 폴더가 없으면 시작 시 폴더 선택창을 한 번 표시. 선택 후에는 저장 경로 사용. 상단 폴더 연결 제거, 이후 설정의 폴더 재연결에서 선택·검증·경로 갱신     |
| DB 관리        | SQLite 일관 백업, 복원 전 자동 백업, 정상 DB와 유실·손상 DB를 구분한 복원. 동일 라이브러리 UUID와 파일을 검증하고 경로 변경 지원                                 |

등록은 API 게시 전의 로컬 준비 상태다. 여러 원글의 미디어를 섞는 기능과 영상 비율 크롭은 기능 목록에서 제외했다. AI는 원본에 없는 질문·구매 유도·과장을 추가하지 않고 Threads에 맞는 자연스러운 구어체를 요청한다. 생성 결과를 자동으로 등록하거나 게시하지 않는다.

수집 결과가 추가되면 같은 작업 폴더에서 **새로고침**하여 새 Excel을 반영한다. 미완료 게시글이 있으면 다운로드 버튼이 활성화된다. 진행이 중단된 기존 회차에는 새 게시글을 자동 편입하지 않으며 기존 잔여분을 먼저 처리한다.

## 데이터 보존과 복원 경계

Excel이 수집 원본이고 SQLite는 다운로드·편집·삭제·등록·댓글 상태다. JSONL은 수집 중 임시 기록으로만 사용한다. 개인 수집 Excel·DB·미디어·인증 정보·로컬 설정은 GitHub에 올리지 않는다.

DB 백업에는 실제 이미지·영상과 Excel이 들어가지 않는다. 컴퓨터 이전 시 작업 폴더 전체를 함께 옮긴 뒤 설정에서 새 경로를 선택해야 한다. 정상 DB가 포함된 폴더의 재연결은 기존 상태를 보존한다. DB 유실·손상 뒤 전체 복원은 자료 조회·등록 관리를 복구하지만, 다운로드는 백업 이후 이력 불명으로 `database_restored` 보류 상태가 된다. 이력 확인·해제 기능은 아직 없다. 새로운 실제 컴퓨터에서의 종단간 검증은 이번 범위에 포함하지 않았다.

## 검증과 남은 단계

Mac 자동 검사와 합성 자료를 사용한 Electron main/preload/renderer·Python 통합 검증을 수행했다. 최신 검사 결과와 검증하지 않은 범위는 [다운로드 복구 검증 기록](download-recovery-verification.md)에 구분한다. 이전 기능 문서의 테스트 수는 각 변경 시점의 기록이다.

다음 기능 단계는 **API 관련 작업 묶음**이다. 계정 연결, 게시글·답글 전송, 답글 이미지 실제 첨부, 미디어 전달, 결과 이력과 실패 복구를 함께 다룬다. 현재 게시글·댓글의 API 업로드 버튼은 비활성 자리 표시자다.

그 다음은 **Windows 실제 기능·설치·자동 업데이트·데이터 보존 검증과 배포**다. updater와 설치 배포는 아직 구현·검증하지 않았으며 이번 소스 체크포인트로 Release나 배포 준비 완료를 선언하지 않는다.
