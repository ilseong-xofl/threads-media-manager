## 2026-09-22 최신 변경

앱에 기억된 작업 폴더가 없으면 최초 실행 때 폴더 선택창을 한 번 연다. 선택 후에는 해당 위치를 기억하고 상단 폴더 연결 버튼을 표시하지 않는다. 이후 폴더 변경은 **설정 → 폴더 재연결**에서 새 위치를 선택하면 경로 갱신까지 처리한다. 처음 선택을 취소하면 빈 화면의 설정 열기에서 다시 선택한다.

상세의 저장 수 배지를 제거하고 게시글 시각(KST)을 계정명 오른쪽에 배치했다. 수집 상세에서는 원문 주소 다음에 수집·파일 정보를 기본으로 펼쳐 보여준다. 댓글 정보는 등록 게시글 상세의 캡션 아래에서 등록·수정하며 캡션과 링크를 SQLite에 저장한다. 상세 하단과 댓글 수정 오른쪽의 API 업로드 버튼은 아직 비활성 상태이며 실제 Threads 게시글·답글을 전송하지 않는다. 원문·댓글 링크는 클릭하면 외부 기본 브라우저로 연다. [댓글 정보 계약](post-comments.md)을 따른다.

그리드 이미지 우측 하단에서 편집본을, 카드 하단 왼쪽에서 게시글 전체를 삭제한다. 확인창 승인 후 실제 대상 파일을 삭제하며, 게시글 삭제는 관련 Excel의 `삭제여부`·`삭제시각(KST)`에 기록하고 재등장·재다운로드를 막는다. 기존 요청·중단·대기 이력은 유지한다. [삭제·실패 복구 계약](media-deletion.md)을 따른다.

상세의 현재 선택 영상은 자동재생한다. 상세 우측 하단 편집에서 이미지 크롭(기본 원본 비율), 영상 현재 프레임 캡처, 시작·종료 초를 지정한 영상 구간 자르기를 지원한다. 이미지 PNG와 영상 MP4 편집본은 원본 캐러셀 뒤에 생성 순서대로 추가하고 SQLite에 별도로 저장하며 게시글 ZIP에도 포함한다. 원본 첨부·Excel·기존 다운로드 상태는 보존한다. [편집 동작과 저장 계약](media-editing.md)을 따른다.

목록에는 첨부가 모두 저장된 게시글만 표시한다. `다운로드 (n)`은 전체 미완료 게시글 수이며0이면 비활성이다. 클릭 한 번으로 회차 다운로드를 시작하고 중앙 토스트에서 진행·대기·오류를 안내한다. 정상 완료는3초 뒤 닫힌다. 저장 필터·카드 저장 수·단일 파일 준비 패널은 제거했다. ZIP 내보내기와 전체 첨부 기준 미디어 배지는 유지한다. [현재 구현과 남은 범위](phase-1e-download.md)를 먼저 읽는다. 아래1D 실물 다운로드 기록은 과거 검증 근거다.

다운로드 상태 토스트는 상세 열기·닫기, 검색, 개별 ZIP 안내와 독립적으로 유지한다. 새로고침과 폴더 선택 취소·실패·같은 폴더 재연결로 초기화하지 않으며 연결 폴더의 저장된 상태를 읽어 반영한다. 완료 안내의3초 타이머는 화면 조작으로 재시작하지 않는다. 진행 중 ZIP 내보내기를 막는 기존 작업 가드는 유지한다.

중단·오류·보류 안내는 자동으로 사라지지 않으며 우측 상단 X로만 닫는다. X는 안내만 숨기고 다운로드의 중단·대기·복구 상태를 변경하지 않는다. 닫은 안내는 폴링이나 화면 조작으로 다시 뜨지 않으며 새 실행의 오류는 다시 표시한다. 진행 중에는 X를 표시하지 않고 정상 완료만3초 뒤 자동으로 닫는다.

게시글 그리드는 최대 4열이며 창이 좁아지면 3열로 줄어든다. 저장한 게시글은 기본 페이지당 12개이며 목록 하단 중앙에 페이지 번호와 이전·다음 버튼을 둔다. 같은 줄 우측의 표시 방식에서 12개·24개·스크롤을 선택한다. 스크롤은 하단 접근 시 12개씩 이어서 표시하며, 상세 모달이 열려 있을 때는 추가 표시를 멈춘다. 한 페이지만 있어도 네비게이션을 표시한다. 검색·필터·표시 방식 변경 시 목록 상단으로 이동하고, 페이지 모드는 첫 페이지로, 스크롤 모드는 첫 12개로 돌아간다. 페이지 이동과 표시 방식은 다운로드 대기 수·진행 상태를 바꾸지 않는다.

검색창 우측의 날짜 범위는 카드에 표시하는 게시글 등록일(KST)을 기준으로 양 끝 날짜를 포함해 필터링한다. 기본은 오늘부터 달력상 한 달 전까지이며, 이전 달에 같은 일이 없으면 말일을 사용한다. 계정·검색어 조건과 함께 적용하며 기간 변경 시 첫 페이지/첫 12개로 돌아간다. 새로고침은 선택 기간을 유지하고 폴더 전환·필터 초기화는 최근 한 달로 돌아간다. 날짜 필터는 전체 다운로드 대기 수나 진행 상태를 변경하지 않는다. 시작일·종료일은 삭제 항목이 없는 앱 캘린더에서 선택한다. 월 이동·오늘 선택·키보드 탐색을 지원하며 시작일과 종료일의 순서를 유지한다.

## 최신 화면 변경

사용자 요청으로1E 전에 local-video-manager의 카드·보라색 포인트·밝은 배경·모달 스타일을 참고해 UI를 바꿨다. 기본 화면은 이미지 중심 그리드이며 카드를 누르면 상단 미디어·하단 캡션/정보의 상세 모달이 열린다. 여러 첨부는 양쪽에서 순환 캐러셀로 보여주고 첨부 위치를 공유한다. ESC·바깥 클릭·닫기 버튼·키보드 포커스 복귀를 지원한다. 수집 세부 정보는 원문 주소 다음에 기본으로 펼쳐 둔다. 다운로드 버튼은 준비 패널 없이 회차 처리를 바로 시작한다. 상세한 검증은 [화면 기록](gallery-ui.md)을 따른다.

2026-09-22 카드 하단의 기존 `일부 확인` 자리에 게시글 ZIP 다운로드 아이콘을 추가했다. 저장 대화상자의 기본 파일명은 사용자 최종 결정에 따라 **`게시글ID.zip`**이며 날짜·계정명을 붙이지 않는다. 게시글의 현재 첨부가 전부 로컬에 저장돼 있어야 하며 원본·편집본 이미지·영상과 `게시글정보.txt`를 묶는다. 수집 당시 캐러셀 전체 수를 확정하지 못한 `partial` 자체는 차단하지 않는다. 원격 요청·DB 쓰기 없이 저장된 파일을 복사하는 기능이다. ZIP 최초 구현 당시 남아 있던 1E 정상 회차 다운로드는 이후 구현했으며, 비정상 종료·오류 후 재개도 구현했다. [파일 구성과 검증 범위](post-export.md)를 따른다.

앱은 전용 userData의 `view-settings.json`에 기억한 작업 폴더를 읽는다. 홈 `.threads-media-manager/settings.json`의 수집 폴더 설정은 최초 선택창의 기본 위치로만 사용한다. 개인 경로·자료·서명 URL·DB·세션을 코드에 넣지 않는다. 앱은 게시글 삭제 확인 시 Excel의 삭제 표시·시각만 갱신하며, 원문·서명 URL을 DB에 복제하지 않는다. 활성 수집과 다운로드는 공통 잠금을 존중한다.

## 저장과 복구

`collection_source.py inspect`는 결과 Excel에서 기준과 최근 시도(부분 수집 포함)를 읽는다. `commit-source --input ... --journal ... --lock-token ...`은 결과 Excel을 임시 작성·재열기 검증·교체하고 accounts를 갱신한 뒤 전달한 두 임시 파일만 정리한다. 실행기록의 `수집입력SHA256`으로 정확한 재시도를 확인한다. accounts 저장 실패는 재수집 없이 같은 입력으로 복구한다. 추가 열·메모·서식·이전 실행·최신 부분 상태와 이전 완전 캡션의 확인 시각을 보존한다.

기존 daily-v1 Excel은 변환 없이 읽는다. 과거 JSONL은 활성 원본으로 읽지 않고 자동 fallback도 하지 않는다. 동등한 Excel을 확인하기 전 과거 JSONL을 삭제하지 않는다. `legacy_jsonl.py`는 이전 형식 비교용 읽기 전용 검증기다. 수집 플러그인은 SQLite·Pillow·ffprobe·다운로드를 호출하지 않는다. 기존 단독 수집 스킬은 변경하지 않는다.

## 앱 환경과 검증

`pnpm start`, `pnpm check`를 사용한다. local-video-manager에서 확인한 Node 24.18.0, pnpm 10.28.1, Electron 43.3.0, Forge 7.11.2, Webpack 5.109.2, React 19.2.8, TypeScript 5.9.3을 유지했다. Vite 구성이 아니다. 독립 app ID/userData/protocol과 제한된 IPC를 사용하고 기존 로그인·서비스·앱 DB·updater는 재사용하지 않는다.

1D 실물 검증 당시 자료는10게시글·20첨부(이미지19/영상1)이며20개 전부 저장됐다. 사용자가 검증1개에서 멈추지 말고 전체를 받으라고 지시해 기존2개는 유지하고 남은18개를 기존 Electron 앱의 다운로드 명령으로 순차 처리했다. 요청18회 추가/합계20회, 전부HTTP200·오류0·HEAD0·재시도0·수집0이었다. 기존 비DB10파일의 SHA-256과 기존 작업·첨부·요청 행을 보존했다. 아래 수치와 테스트 수는 당시 기록이며 현재 자료 수나 최신 전체 재검증을 뜻하지 않는다.

파일마다 저장 완료 후의 DB 대기 시각을 확인하고 다음 전송을 시작했다. 마지막 회차75.112초·계정22.126초 대기 시각도 앱의 State 실행기를 통해 저장했다. 요청당 무응답30초·파일 시도 총600초를 유지했다. 전체20파일의 hash/크기, 이미지19개 verify/load, H.264 영상720×960·2.9초의 ffprobe·실제 앱 재생을 확인했다. 앱 저장20/20, 미완료파일0·중단없음·잠금해제다. 최신 검증은 [진행 기록](progress.md)과 [1D 문서](phase-1d-download.md)를 확인한다.

이번 전체 처리는 고정된18개 대상을 앱의 기존 단일 파일 명령에 순차 전달한 실행이다. 제품의 전체 다운로드 버튼·회차 계획 UI를 구현한 것으로 보고하지 않는다. 이후1E에서 이 반복 제어와 회차/계정 대기를 앱에 통합했으며 최신 검증은 phase-1e-download.md를 따른다. 사용자 전체 다운로드 요청을 파일1개 확인만으로 완료 처리하지 않는다.

## 기존1D 실물 검증 기록

`local-runtime`의 검증된 파일 하나 실행기를 앱에 연결했다. Mac 실제 앱에서 준비·시작·모의 전송과 실제 전체 전송·저장20/20·이미지 표시와 영상 재생을 검증했다. TypeScript31개·Python185개와 lint/typecheck/format을 통과했다. 원본 변경 차단·첫 오류 중단·중복 시작 방지·앱 종료 취소·강제 종료 후 WAL/잠금 복구를 확인했다. 기존 `source_type=jsonl` 완료 작업은 그대로 파일에 연결하고 재다운로드하지 않는다. 미완료 과거 작업은 Excel로 몰래 교체하지 않고 전송 전 중단·확인이 필요하다. 새 작업은 `source_type=xlsx`다. 기존 UUID·요청 소비·중단·대기·파일을 보존한다.

사용자는24시간1회 상한을 없애라고 명시했다. 현재 local-download-v2에는 일일 횟수 제한이 없다. 기존 정책은 첫 쓰기에서 메타데이터만 원자적으로 이관하며 요청 이력·파일·UUID·중단·대기는 보존한다. 다른 횟수 상한을 새로 넣지 않는다. 현재1E 실행은 계정별 오래된 미완료 글부터 첨부 순서대로 처리하고35–45첨부의 게시글 묶음·완료 후3–10초·회차60–120초·계정10–30초 대기·첫 오류 전체 중단을 유지한다. 새 수집은 다운로드 중단·소비량을 초기화하지 않는다.

Mac에서 기능을 개발·검증한다. Windows 실제 기능·설치·자동 업데이트는 최종1G이며 아직 완료가 아니다. 업데이트한 수집 플러그인 스킬은 현재 작업에 로드돼 있다. 이번1D는 수집 플러그인 변경이 아니다.
