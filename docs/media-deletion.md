# 편집본과 게시글 삭제

## 화면에서 확인하는 수동 삭제

- 그리드에서 현재 이미지·영상이 편집본이면 미디어 우측 하단에 삭제 아이콘을 표시한다. 원본 이미지·영상에는 이 아이콘이 없다.
- 카드 하단의 ZIP 다운로드와 같은 줄 왼쪽에는 게시글 삭제 아이콘을 표시한다.
- 누르면 계정·게시글 ID·삭제 파일 수를 보여주는 확인 창을 연다. 기본 선택과 ESC는 취소이며, 삭제를 확인해야 실행한다. 확인창이 열린 사이 대상이 바뀌면 삭제를 진행하지 않고 다시 확인하도록 안내한다.

편집본 삭제는 해당 PNG 또는 MP4만 삭제한다. 원본과 그 편집본을 바탕으로 만든 다른 편집본은 유지한다. 삭제 후 캐러셀 위치는 가능한 한 같은 파일을 유지하며 현재 파일을 삭제한 경우 인접 파일로 이동한다.

게시글 삭제는 앱이 관리하는 원본 이미지·영상과 모든 편집본 파일을 삭제한다. 이전에 사용자가 다른 폴더에 내보낸 ZIP은 대상에 포함하지 않는다. 삭제한 글은 목록·대기 수·이후 다운로드에서 제외한다.

## 수동 삭제의 Excel과 SQLite

게시글이 나타나는 모든 결과 Excel의 `게시글` 시트에 `삭제여부`와 `삭제시각(KST)` 열을 추가하거나 갱신한다. 대상 행에는 `Y`와 한국 시각의 삭제 일시를 표시한다. 원문·캡션·미디어 행·수집 실행·계정 기준·추가 열과 서식은 보존한다. 편집본 하나만 삭제할 때에는 게시글 삭제로 표시하지 않는다.

SQLite의 별도 삭제 기록과 Excel 표식 중 하나라도 삭제를 나타내면 앱에서 제외한다. 과거 날짜 Excel에 같은 글이 남아 있거나 이후 다시 관찰되어도 삭제 기록을 우선한다. 기존 다운로드 작업·미디어 연결·요청 이력·중단·대기 정보는 기록으로 보존하며, 삭제한 파일을 손상된 다운로드로 오인하거나 다시 받지 않는다.

새 미디어를 쓰지 않는 삭제 기능이지만 파일·Excel·SQLite를 함께 변경하므로 수집·다운로드·편집 저장·ZIP·폴더 전환과 동시에 실행하지 않는다. 미완료 다운로드 계획이 남아 있어 Excel 변경이 계획의 원본 검증에 영향을 줄 수 있으면 게시글 삭제를 차단하고 이유를 표시한다.

## 수동 삭제의 실패와 복구

확인 전 준비는 읽기 전용이다. 확인 후에도 대상과 해시를 재검증하고 공통 잠금을 획득한다. 삭제 파일은 같은 루트의 임시 작업 폴더로 옮긴 뒤 Excel과 삭제 기록을 반영하며, 반영 전 실패·취소 시 복원한다. 반영 후에는 격리 파일을 실제로 제거한다.

앱 강제 종료 등으로 작업이 남으면 화면의 **삭제 작업 복구**로 처리한다. 앱이 기록한 저널과 SQLite 기록이 일치하는 작업만 복원하거나 정리하며, 다른 실행의 잠금이나 임의 파일을 삭제하지 않는다. 복구 전에는 충돌하는 쓰기 작업을 막는다. 성공 뒤 목록 갱신만 실패한 경우에는 삭제를 다시 요구하지 않고 새로고침을 안내한다.

삭제 검증에는 실제 사용자 게시글을 사용하지 않는다. 임시 합성 자료에서 취소·확인 전 대상 변경·선택 범위·실제 파일 제거·Excel 표시·재시작·ZIP·다운로드 제외·실패 복구를 확인한다. Windows 실기 검증은 최종 단계에 남는다.

## 앱의 불완전 수집 글 정리

2026-09-23 정책의 `cleanup-source`는 앱 시작·새로고침과 새 다운로드 시작 전에 불완전 수집 기록만 논리적으로 삭제하는 별도 동작이다. 대상은 `source_not_ready`·`attachment_not_ready`로 판정된 글 중 다운로드나 사용자 작업이 전혀 없는 글이다. 완전성은 게시글별 캡션·첨부 수집 상태와 실제 첨부·URL 연결로 판단한다. 상위 수집 실행이 중단되거나 `partial`이어도 해당 글이 완전하면 정상 다운로드 대상으로 유지한다. `post_deletions`에 멱등 기록하고 앱 목록·대기 수·후속 계획에서 제외하며 일반 상태와 정리 수 `cleanedPosts`를 반환한다. 정리한 불완전 글 수는 `cleanedPosts`, 정상으로 확인해 제외를 해제한 글 수는 `releasedPosts`로 구분한다.

Excel의 삭제 열·수집 기준·원본 해시는 변경하지 않는다. 정리 대상은 삭제할 앱 소유 다운로드 파일이 없는 수집 기록이므로 파일을 제거하거나 HTTP 요청을 보내지 않는다. 기존 `meta.download_exclusions` 중 게시글별 검사로 정상인 글은 제외를 해제한다. 실제 불완전하고 같은 보호 조건을 충족하는 작업 없는 글만 삭제 기록으로 이관한다.

jobs·부분 파일·다운로드 파일·AI 생성본·등록·편집 등 기존 작업이 하나라도 있으면 이후 원본이 불완전해져도 자동 정리에서 보호한다. 정상 수집 글이 다운로드 중 실패하거나 강제 종료됐다는 이유로 삭제하지 않는다. 실패·일부 저장·미시작 정상 글과 기존 파일·계획·작업·요청 이력·대기를 유지하고 명시적 이어서 다운로드로 복구한다. `status`는 읽기 전용, `recover`는 로컬 복구, `resume`은 명시적 전송이라는 계약을 유지한다.

정리는 합성 자료에서 두 판정 코드의 작업 없는 글만 처리하는지, 중단/partial 실행의 완전한 글을 보존하고 정상 글의 legacy 제외를 해제하며 실제 불완전 글만 안전하게 이관하는지, 반복 실행의 멱등성, 기존 작업 보호, Excel 해시 불변과 HTTP/파일 삭제 0을 검증한다. 아래 수동 삭제 검증 기록은 이 정리 동작의 완료 근거가 아니다.
