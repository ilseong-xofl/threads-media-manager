# 개인 Codex 계정용 수집 플러그인 배포

상태: 설계 초안 / 2026-09-21. 플러그인은 계정 설정·브라우저 수집·영구 Excel 원본까지만 담당한다. 다운로드는 별도 로컬 앱의 기능이다. 검증된 단일 파일 파일럿은 `local-runtime/`으로 옮겨 보존하며 플러그인에 다운로드 명령을 배포하지 않는다. 이동은 앱·배치 기능 완성을 뜻하지 않는다. 미완성 배치 초안은 별도 임시 경로에 보존하고 90회 정책은 적용하지 않는다. 현재 검증 범위는 [진행 기록](progress.md), 로컬 실행기는 [별도 계약](local-download-runner.md)을 따른다.

## 1. 대상과 배포 원칙

- 멤버는 각자의 개인 Codex 계정과 로그인된 내부 브라우저를 사용한다. 회사 workspace·공유 로그인·중앙 DB·자동 일일 실행을 전제로 하지 않는다.
- Windows 멤버 PC에 배포한다. Mac은 작성자의 개발·검증용이며 설치 파일을 배포하지 않는다.
- 수집 플러그인과 로컬 앱은 Mac·Windows 기능을 지원한다. 1A–1F는 Mac에서 개발·검증하고 최종 1G에서 Windows 설치·전체 기능·업데이트를 확인한다.
- 멤버가 도우미 안내와 Codex UI로 설치하도록 설계한다. Node·Python·Git CLI의 수동 설치나 터미널 입력을 표준 절차로 삼지 않는다.
- 공개 GitHub marketplace·플러그인 방향은 유지하되 소유자·URL·정식 배포 식별자는 배포 전에 확정한다. 이 문서 변경으로 외부 저장소·Release를 생성하지 않는다.
- 최초 플러그인 식별자는 `threads-collector`, 버전은 `0.1.0`이다. 개발용 repository-local marketplace `personal`은 사용자 홈의 기본 personal marketplace와 다른 명시적 소스다. 동명 소스를 덮어 등록하지 않는다.
- 공개 패키지에는 코드·빈 양식·합성 자료만 넣는다. 실제 계정·쿠키·JSONL·Excel 결과·서명 URL·미디어·DB·개인 경로는 제외한다. `sample` 예제 accounts 양식은 기존 사용자 파일을 덮어쓰지 않는다.

## 2. 공식 기능과 구현할 도우미

기존 확인의 공식 근거는 [OpenAI 플러그인 제작 문서](https://developers.openai.com/plugins/build/plugins)와 [설치 안내](https://learn.chatgpt.com/docs/plugins#install-and-use-a-plugin)다. 배포 구현 시 최신 지원 범위를 다시 확인한다.

| 구분 | 범위 |
|---|---|
| marketplace 등록 | Git 기반 개인 marketplace 등록 경로 `codex plugin marketplace add owner/repo [--ref]` |
| marketplace 갱신 | 등록한 배포 목록 갱신 경로 `codex plugin marketplace upgrade marketplace-name` |
| 설치·로드 | Codex Plugins UI 설치와 새 대화 로드를 구분 |
| 미확인 보장 | 등록만으로 즉시 설치·로드·자동 업데이트가 전부 완료된다고 전제하지 않음 |
| 도우미 목표 | 설치 상태·버전 비교·목록 갱신·필요 준비·Codex UI 안내를 한 흐름으로 제공 |

도우미는 우선 배포 목록 갱신과 새 버전 안내를 목표로 한다. 실제 설치·활성화까지 전자동이라고 표현하지 않는다. Windows 명령과 설치 후 반영은 개인 계정 실기 검증을 거쳐 확정한다.

## 3. 패키지와 소유권

플러그인은 수집 지침·배포 양식·설치 점검·초기 설정 helper·임시 JSONL·Excel 저장 도구를 포함한다. helper는 로컬 위치 설정과 양식 준비만 하고 state/media·다운로드 DB를 선행 생성하지 않는다. 플러그인은 CDN 다운로드·다운로드 실행 명령·DB migration·다운로드 중단 해제를 제공하지 않는다.

로컬 앱은 `local-runtime/`의 검증된 파일럿을 기반으로 다운로드 기능을 개발한다. 앱의 실행기 한 곳만 state.db·미디어·예산·중단 상태를 관리하고 Electron main/renderer에 중복 다운로드 엔진을 두지 않는다. 실행 의존성은 앱 배포물 또는 검증된 사용자 범위 준비 절차로 제공한다. 준비 실패 시 누락 항목과 복구 방법을 표시한다.

수집과 다운로드의 공유 계약은 daily-v1 Excel 형식·수집 루트·공통 실행 잠금이다. 플러그인은 앱 DB나 다운로드 오류 상태를 읽지 않는다. 앱은 원본 Excel을 읽고 계정 목록·수집 기준을 수정하지 않는다. 앱/플러그인 버전은 각각 확인하고 Excel·잠금 호환성을 검사한다.

## 4. 수집과 다운로드의 별도 흐름

1. 플러그인은 시작 시 accounts의 활성 계정·순서를 고정한다.
2. 로그인된 내부 브라우저의 허용된 도구로 수집한다. 쿠키·세션을 로컬 실행기에 복사하지 않는다.
3. 계정별 Excel 원본·accounts 표시를 저장하고 검증 후 임시 JSONL을 정리한다. 수집 계정 간 대기 후 다음 계정을 수집하고 종료한다.
4. 사용자는 별도로 앱에서 자료를 새로고침하고 다운로드 대상을 확인·시작한다. 수집 완료만으로 다운로드를 실행하지 않는다.

수집 오류는 수집 실행의 후속 계정을 중단한다. 다운로드 오류는 앱의 후속 파일·회차·계정 다운로드를 중단한다. 앱 오류로 이미 확정한 수집 결과·기준을 되돌리지 않는다. 이후 사용자가 별도로 요청한 수집은 자체 가드와 잠금 조건을 만족하면 진행할 수 있다. 새 Excel·URL·계정은 앱 중단 해제나 자동 재시작 조건이 아니다.

활성 수집과 다운로드는 같은 `_work/collector.lock`을 사용해 겹치지 않게 한다. 소유자·토큰이 다른 잠금은 제거하지 않는다. 단순 앱 열기나 마지막 정상 화면 조회는 잠금을 독점하지 않는다. 실제 작업을 종료하면 잠금을 해제하되 앱 DB의 실패·휴식·예산은 보존한다.

## 5. 사용자 데이터

| 대상 | 보관·접근 원칙 |
|---|---|
| 수집 폴더 위치 | 사용자 홈 `.threads-media-manager/settings.json`에 위치만 보관 |
| 영구 수집 원본 | 선택 루트의 결과 Excel, 플러그인 helper가 저장·검증. 앱은 읽기 전용 |
| Excel/accounts | 수집기의 보고·상태 표시와 사용자 계정 입력. 앱이 다운로드 상태를 덧쓰지 않음 |
| state.db·미디어 | 플러그인 캐시 밖 사용자 경로. 앱 로컬 실행기가 단독 관리 |
| 앱 상태 | 작업·계정·회차·원본 참조·파일 연결·소비·예약·휴식·중단·버전 호환 정보 |

플러그인 캐시 삭제·재설치·업데이트로 사용자 JSONL·Excel·미디어·DB가 사라지지 않아야 한다. 원문 캡션·등록일·전체 서명 URL은 DB에 복제하지 않는다. Mac 개발 데이터는 Windows 운영 자료와 분리한다.

## 6. 멤버 설치·실행 흐름

1. 목표 Windows 설치 도우미에서 Codex·런타임·marketplace 준비를 안내하고 Plugins UI에서 설치한다. Windows 도우미는 아직 미구현이다.
2. 새 대화에서 “Threads 초기 설정해줘”를 요청한다. 초기 설정은 실제 로드 버전·브라우저·Spreadsheets·로컬 도구를 점검한다.
3. 수집 폴더를 한 번 선택한다. helper는 기존 accounts를 보존하거나 샘플 양식을 만들고 위치만 기억한다. 반복 설정이나 업데이트로 기존 파일에 예제를 다시 추가하지 않는다.
4. `Y | sample | https://www.threads.com/@sample` 예제를 삭제하고 수집 계정을 A:D열에 입력·저장·닫기한다. Codex 내부 브라우저에서 본인의 Threads 계정으로 로그인한다. 예제 계정이 활성 상태면 실제 수집 전에 중단·안내한다.
5. “Threads 수집 시작해줘”로 수집·Excel 저장·임시 기록 정리을 진행한다. 다운로드는 시작하지 않는다.
6. 별도 로컬 앱에서 같은 폴더를 연결하고 확정 원본을 새로고침한다. 앱의 다운로드 기능이 구현·검증된 뒤 계획·예산을 확인하고 시작한다.

CLI·필수 도구가 없으면 구체적인 준비 안내로 복구한다. 동의 없이 관리자 권한·전역 설정·보안 설정을 변경하지 않는다. 기존 단독 스킬은 임의 삭제·덮어쓰기하지 않는다.

## 7. 버전과 업데이트

플러그인의 배포 목록 최신 버전·설치 캐시·현재 대화 로드 버전과 로컬 앱/실행기 버전을 구분한다. 미확인 값은 미확인으로 표시한다. 최신 저장소 커밋을 실행 버전이라고 표시하지 않는다.

- 활성 작업의 코드·정책은 고정한다. 수집·다운로드 중 업데이트로 교체하지 않는다.
- 도우미는 새 패키지를 별도로 준비·검증하고 작업이 없을 때 교체한다. 목록 갱신·실제 설치·새 대화 로드는 각각 확인한다.
- 고정 ref는 목록 갱신만으로 자동 변경된다고 가정하지 않는다. Windows 버전 반영 절차는 최종 검증에서 확정한다.
- 플러그인 업데이트는 다운로드 DB를 열거나 migration하지 않는다. 앱의 DB 변경은 앱 실행기의 정상 백업·호환성 검증을 거친다.
- 앱 업데이트로 소비·휴식·중단·파일 연결을 초기화하지 않는다. DB 변경 후 구버전 실행 가능성을 가정하지 않고 검증된 복구 또는 중단을 유지한다.

개인 계정 무인 업데이트나 다른 대화의 즉시 버전 변경은 약속하지 않는다. 플러그인과 Windows 앱의 업데이트 경로는 별도로 검증한다.

## 8. Windows 최종 확인

- 개인 Codex 계정에서 플러그인 설치·새 대화 로드·초기 설정·수집·Excel 저장·임시 기록 정리을 소량 검증한다.
- 별도로 앱 설치·같은 폴더 연결·Excel 새로고침·다운로드·로컬 표시·자동 업데이트를 검증한다.
- 한글/공백 경로·도구 누락·의존성 실패·기존 스킬 공존·공통 잠금 충돌에서 안내와 중단을 확인한다.
- 수집 오류와 앱 다운로드 오류의 범위를 구분한다. 첫 다운로드 오류 후 추가 GET은 0이며 나중의 별도 수집이 앱 DB를 읽거나 중단 상태를 해제하지 않아야 한다.
- 업데이트 중 작업 교체 금지, JSONL·Excel·state.db·미디어 보존, 새 대화 버전 반영과 앱 migration 실패 복구를 확인한다.
- 비기술 멤버가 안내만으로 설치·갱신 가능한지 확인하고 배포 범위를 확대한다.

개발 검증은 [진행 기록](progress.md), Windows 확인은 [별도 절차](windows-plugin-check.md)에 구분한다. 이 문서는 실제 외부 게시·설치·수집·다운로드를 실행한 결과가 아니다.
