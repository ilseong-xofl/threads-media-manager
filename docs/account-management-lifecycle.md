# 계정 관리와 삭제

2026-10-19 최종 결정: **Threads 계정의 이관·중지·재개 기능을 모두 폐기한다.** 이전의 중지·재개·수락 방식 이관 정책은 더 이상 유효하지 않다. 실제 사용자 계정의 이관·중지·재개는 실행하지 않았다.

## 제공하는 기능

- 상단은 `새로고침 → 다운로드 → 세로 구분선 → 닉네임 → 설정 아이콘`이다. 메뉴는 계정 관리·설정·비밀번호 변경·로그아웃 순서다.
- 계정 관리는 독립 테이블 모달이다. 추가·서버 동기화·정보 수정·토큰 교체·삭제와 저장 보류 재시도/취소만 제공한다.
- 2026-10-20 정보 수정: 선택 계정 작업의 `토큰 교체` 앞 `정보 수정`에서 Meta 앱 이름과 Threads 계정 이름을 바꾼다. 서버 `POST /api/v1/threads/accounts/:id/profile`(desktop, 상태·소유권 버전 확인)에 먼저 반영한 뒤 이 PC의 암호화 사본을 갱신한다. 토큰·revision·휴대폰 확인 상태와 휴대폰 연결은 바꾸지 않으며, 같은 이름 재요청은 변경 없이 성공한다. 삭제 대기·서버 목록에 없는 계정은 수정할 수 없고, 토큰 교체 보류 중에도 이름은 수정할 수 있다. 휴대폰은 다음 계정 조회 때 새 이름을 표시한다.
- 표에는 앱 이름, Threads 계정 이름/확인 ID, 휴대폰 토큰 확인, 앱 연결 확인, 보고된 만료 일시를 표시한다. 서버 저장 성공을 휴대폰 검증 완료로 표시하지 않는다.
- 추가·정보 수정·토큰 교체·삭제는 부모 표를 유지하는 별도 모달로 연다. 확인창은 대상과 영향을 설명하고, 취소·Escape 후 부모 표와 포커스를 유지한다. 처리 중에는 닫기를 막는다.
- 계정별 중지/재개, 이관, 직원 선택, 받은/보낸 요청, 수락·거절·취소, 상태 변경 보류 작업 화면은 없다. 해당 API·Electron IPC·실행 경로도 제공하지 않는다.
- 관리자에 의한 서비스 사용자 사용 중지와 권한 검사는 기존대로 유지한다. 이번 폐기는 개별 Threads 계정의 중지·재개 기능에 해당한다.

## 삭제 정책

담당자는 본인 계정 연결만 삭제할 수 있다. 삭제 확인창에서 다음 내용을 명확히 안내한다.

- 이 서비스의 계정 연결과 서버에 저장된 토큰을 제거한다.
- 연결된 휴대폰과 해당 서비스 세션을 해제한다.
- 아직 시작하지 않은 게시 대기 글과 미게시 댓글은 취소한다.
- 전송 중·결과 불명 원글이나 댓글이 있으면 삭제할 수 없다.
- 실제 Threads 계정·게시물과 기존 완료 이력은 삭제하지 않는다.
- 다시 사용하려면 장기 토큰을 새로 등록하고 휴대폰을 다시 연결해야 한다.

사용자가 확인하면 소유권·세션·버전을 서버에서 검사하고 위 정리를 한 트랜잭션으로 처리한다. 계정 식별 행과 당시 행위자·감사 기록은 보존한다. 관리자에게 직원의 토큰을 다른 직원에게 넘기는 기능을 추가하지 않는다.

## 재시도와 암호화 사본

삭제 요청에는 확인 당시 토큰 revision·상태/소유권 버전을 고정해 보낸다. 삭제 의도를 로컬에 먼저 암호화 저장하고, 결과를 확인한 뒤에만 사본을 정리한다. 응답 유실 후에는 조회로 결과를 확인하며 원격 변경을 자동 재전송하지 않는다. 버전이 바뀌면 이전 삭제 의도를 재사용하지 않고 새 확인을 요구한다.

로그인·접속 확인 시 계정 관리 창을 열지 않아도 명시적인 삭제 결과를 받아 일치하는 연결의 암호화 사본을 정리한다. 단순 목록 누락·404·통신 실패는 삭제 근거가 아니다. 로컬 자료·완료 이력·수집 원본은 계정 연결 삭제 때문에 지우지 않는다.

기존 v1/v2/v3/v4 암호화 저장 형식을 읽고 보류 토큰·등록·교체·삭제 의도를 보존한다. 폐기된 이관·중지·재개 작업은 읽을 때 제외하고 어떤 재접속·재시도 경로에서도 전송하지 않는다. 다음 저장 시 폐기된 작업 기록을 정리한다. renderer에는 계정 메타데이터만 전달하고 토큰·암호문·인증 Bearer를 반환하지 않는다.

## 삭제 후 재등록

새 장기 토큰을 수동 등록하고 새 등록 ID·휴대폰 연결로 시작한다. 삭제된 연결의 예전 등록 요청은 되살리지 않는다. 서버가 폐기한 토큰, 이전 휴대폰 세션, 취소된 게시 대기도 복원하지 않는다.

이름만으로 과거 연결과 합치거나 다른 직원의 토큰·완료 이력을 가져오지 않는다. 본인에게 남아 있는 과거 완료 이력은 보존하며, 서비스 사용자 간 계정 소유권 변경 기능은 없다. Meta 앱별 실제 계정 ID 범위와 중복 판정은 [모바일 전환 설계](mobile-publishing-migration.md)의 실증 범위를 따른다.

## DB 이력과 구현 범위

이미 적용한 `0002_account_deletion.sql`과 `0003_account_lifecycle.sql`의 SQL·Drizzle hash·snapshot은 수정하거나 되돌리지 않는다. `0003`의 중지·이관 관련 테이블·필드는 과거 schema 호환용으로만 보존하고 해당 기능을 실행하는 데 사용하지 않는다. 기존 계정·토큰·연결·감사 기록을 지우는 추가 migration은 수행하지 않는다.

`publication_ledger`는 삭제 시 미시작 작업 취소와 진행 중·결과 불명 작업 보호를 위한 최소 영속 모델이다. 게시 스냅샷·S3 전송·모바일 실행기·완료 이력 화면은 후속 단계다. 현재 계정 기능 검증이 실제 Android 게시 검증을 대신하지 않는다.

## 적용·검증 기록

- 개발 DB: `threads_admin_dev` / `threads_admin_dev_user`, PostgreSQL `11.22-rds.20250508`, migration 적용 4개·대기 0개.
- `0002`→`0003` 격리 PostgreSQL 11 보존 검사 21개로 기존 credential 바이트·계정·휴대폰·세션·감사 기록·FK가 유지됨을 확인했다.
- 개발 DB의 이관 요청·대기·소유권 변경·이관된 휴대폰 연결·이관 작업·중지 계정·중지 작업·재개 작업은 읽기 전용 건수 확인에서 8개 항목 모두 0개였다.
- 최종 Electron 테스트 53개 파일·1,334개, 관리자/API 테스트 98개가 통과했다. 양쪽 타입 검사·lint와 관리자/API production build도 통과했다. 폐기된 서버 API 9개는 빌드 경로에서 제외되었다.
- Mac 개발 앱을 재실행해 계정 선택 후 토큰 교체·삭제 버튼과 삭제 경고를 확인하고 취소했다. 중지·재개·이관 UI는 없으며 실제 계정과 토큰은 변경하지 않았다. Windows·Android 실기 검증은 이번 범위에 포함하지 않았다.
- 실제 사용자 계정 상태 변경·삭제·토큰 변경·Meta 호출·운영 DB·AWS 배포는 검증 목적으로 실행하지 않는다. 참고 프로젝트는 변경하지 않는다.
