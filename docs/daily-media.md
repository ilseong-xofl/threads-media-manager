# 일상 글 이미지·영상 첨부 계약

2026-11-24 사용자 결정. 수집 → 등록 탭 → [등록] 창의 이미지·영상 첨부를 일상의 수동 등록·초안 수정 창에 그대로 가져왔다. 편집 기능은 없고 첨부, 순서 바꾸기, 빼기만 한다. AI가 만든 초안도 초안 수정 창에서 첨부를 더하거나 뺄 수 있다. 같은 날 등록 완료 글도 이 PC에서 지울 수 있게 했다.

## 결정 (2026-11-24, 사용자)

- **넣는 곳:** 수동 등록 창과 초안 수정 창(같은 창 `src/renderer/DailyPostDialog.tsx`)이다. 답글 창에는 없다.
- **위치:** 창의 맨 위다(수집 [등록] 창과 같다). 그다음이 (일본어·영어 페르소나의 새 글이면) 작성 언어 → 토픽 → 브랜드·제품 → 멘트 → 본문이다(토픽을 브랜드 위로 — 사용자 결정).
- **본문:** 첨부가 1개 이상이면 본문을 비워도 된다(0~500자). 첨부가 없으면 지금처럼 1~500자다.
- **보관은 수집 [등록]과 같다**("수집의 수동등록처럼 관리"): 고른 파일을 작업 폴더에 복사해 원본 그대로 계속 보관한다. 등록 완료 카드에서도 원본으로 미리보기와 영상 재생이 된다. 파일은 글 삭제, 첨부 빼기, 페르소나 삭제 때 지운다.
- **카드:** 첨부가 있으면 카드 맨 위에 캐러셀이 있다. 첨부가 여러 개면 좌우 화살표는 마우스가 첨부 위에 있을 때만 보이고 벗어나면 사라진다(키보드로 옮겨 가도 보인다). 수집 카드의 규칙은 그대로다.
  - 초안 카드는 첨부를 눌러도 본문을 누른 것처럼 초안 수정이 열린다. 화살표는 그림만 넘긴다. 본문 버튼처럼 ChatGPT가 쓰는 동안과 다른 저장 중에는 열리지 않는다. 영상은 재생 표시만 보이고 초안 수정 창의 미리보기에서 재생한다.
  - 휴대폰 대기·등록 완료 카드는 열 창이 없어서 카드에서 바로 영상을 재생한다.
  - 첨부 칸의 높이는 가로의 80%다(2026-11-26 사용자 요청 — 정사각형에서 20% 낮췄다). 그림은 칸을 채우므로 세로로 긴 그림은 위아래가 조금 더 잘린다. 수집 카드와 글 창의 큰 미리보기(수집 [등록] 창과 같은 규칙)는 그대로다.
- **등록 완료 글도 지울 수 있다:** PC에서만 지운다. Threads 글과 서버·휴대폰의 기록은 그대로다. 페르소나 삭제가 등록 완료 기록을 PC에서 지우는 것과 같다.

## 서버·모바일은 바꾸지 않는다

서버는 일상과 수집을 같은 게시 경로와 같은 표로 받는다.

- `POST /api/v1/publications`의 `media`는 0~20개이고, 본문은 첨부가 없을 때만 필수다. `publication_media`는 출처를 가리지 않는다.
- 그래서 migration과 서버 코드 변경이 없다.
- 첨부가 있는 게시는 `uploading`으로 생긴 뒤 `upload-urls` → S3 PUT → `complete`로 `ready`가 된다.

모바일 웹과 Android 앱은 일상 카드에도 `PostMediaCarousel`을 그리고, `media.length`로 TEXT / 단일 IMAGE·VIDEO / CAROUSEL을 나눠 게시한다. 토픽은 단일 원글과 캐러셀 부모에 붙는다. 일상 글에 첨부가 없어서 지금까지 보이지 않았을 뿐이다. 바뀌는 것은 이 PC뿐이다.

## 첨부하기

- **고르기:** [파일 선택](파일 창)이나 끌어다 놓기로 고른다. 끌어다 놓은 파일은 preload가 `webUtils.getPathForFile`로 실제 경로만 넘긴다.
- **한도:** 글당 20개다(Threads 한도).
- **첨부할 때 검사한다**(보낼 때 실패하지 않게). 한 번에 넣은 파일 중 하나라도 안 되면 그 묶음 전체를 거절하고, 이유에 파일 이름을 넣어 토스트로 알린다.
  - 이미지: jpg·jpeg·png·webp. 열어서 크기를 읽지 못하면 손상 파일로 거절한다. WebP는 PNG로 바꿔 저장한다. 저장하는 이미지는 8 MiB 이하, 가로 320 이상, 가로세로비 10:1 이하여야 한다.
  - 영상: mp4·mov, 1 GiB 이하. 수집 보내기의 `checkVideo` 조건(5분, H.264/HEVC + AAC)에 23~60fps와 가로세로비 0.01~10을 더해 본다. 수집의 `checkVideo`는 바꾸지 않았다.
  - GIF·WEBM과 그 밖의 형식은 거절한다.
- **작업 폴더가 없을 때:** 첨부 칸이 꺼지고 "작업 폴더를 지정하면 이미지·영상을 첨부할 수 있습니다."를 보인다. 이미 있는 첨부를 둔 채 본문만 고치는 것은 된다.
- **창을 닫을 때:** 가져오는 중에도 창을 닫을 수 있고, 닫으면 저장하지 않은 첨부를 버린다.

## 보관

- **파일 위치:** `<작업 폴더>/daily-media/<구획>/media/files/<창 번호>/<첨부 id>.<확장자>`.
  - 구획은 `daily.json`과 같은 서비스 주소·사용자 단위다(sha256 앞 32자). 그래서 개발·운영 앱이나 다른 사용자가 같은 작업 폴더를 써도 섞이지 않는다.
  - 수집 미디어 폴더, state.db, Python worker와는 따로 있다.
- **`daily.json`:** 글에 선택 필드 `media: [{ id, kind, relativePath, size, sha256, name }]`를 둔다. 배열 순서가 올라가는 순서이고, `sha256`·`size`는 저장한 바이트(WebP는 PNG로 바꾼 뒤)의 값이다.
- **형식 번호:** 첨부가 있거나 본문이 빈 글이 하나라도 생기면 파일을 `version: 2`로 쓴다. 한 번 2가 되면 2를 유지한다(취소한 첨부 전송이 서버에 남아 있기 때문).
  - 0.1.15 이하는 2를 읽지 못하는 파일로 보고 덮어쓰지 않는다.
  - 그래서 이전 버전이 첨부를 빼고 본문만 보내는 일은 없다. 대신 이전 버전에서는 일상 탭이 열리지 않는다(사용자가 받아들임).
- **미리보기:** `threads-daily://file/<id>`. 일상 전용 `MediaRegistry`가 파일을 해시하지 않고 등록하고(바이트 검사는 보낼 때 한다), 파일이 없는 첨부는 "파일 없음"으로 보인다.
  - 다른 두 scheme과 같은 로그인 관문, 요청 필터(`src/main/security.ts`), 개발 CSP(`forge.config.ts`)를 거친다.
  - 로그아웃·사용자 전환·화면 새로고침 때 등록을 비운다.
- **정리:**
  - 저장한 뒤 창에서 넣었지만 쓰지 않은 파일, 뺀 첨부, 지운 글·페르소나의 파일은 `daily.json`을 저장한 뒤 지운다.
  - 창 폴더에는 만들 때 `.pending` 표시를 두고 저장하면 지운다.
  - 앱이 그 사이 꺼져 `.pending`이 남은 폴더는 일상 화면을 처음 읽을 때(페르소나 동기화보다 먼저) 정리한다. 이때 `daily.json`이 있고 정상으로 읽혀야 하며, 글이 가리키는 파일은 남긴다. `daily.json`이 없으면 아무것도 지우지 않는다.
  - 폴더를 지울 때는 실제 경로인지 확인하고 이 모듈이 만든 이름의 파일만 지운다. 링크로 바뀐 폴더는 따라가지 않는다.

## 보내기

1. 첨부가 있으면 일상 등록부에 다시 등록하고, `prepareThreadsMedia`로 올릴 바이트를 출력 폴더(`userData/mobile-outbox/<요청 id>`)에 고정한다. WebP 변환, 영상 검사, 8 MiB·20개 한도가 수집 보내기와 같다.
2. 서버용 manifest는 파일마다 새 UUID로 만든다.
3. 요청 전체를 `daily.json`에 먼저 저장한 뒤 `create`를 부른다.
4. `uploading`이면 파일마다 `upload-urls`를 새로 받아 그 파일 하나를 PUT한다. 주소 수명이 15분이라서다.
5. 마지막으로 `complete`를 부른다. 서버가 파일마다 HEAD → COPY → HEAD를 하므로, 시간 제한은 15초 + 파일당 30초다.

- **진행:** 그 글 카드와 보내기 확인 창 버튼에 "첨부 올리는 중 n/m"을 보인다. 올리는 동안 앱의 다른 일상 작업과 종료·로그아웃·업데이트는 지금처럼 기다린다. 출력 폴더는 끝나면 지운다.
- **다시 보내기:** 저장된 요청으로 `create`를 부르면 서버가 같은 행을 돌려준다. `uploading`이면 파일을 다시 준비해 크기·SHA-256을 보낸 manifest와 순서대로 비교한 뒤 업로드를 잇는다. 바뀌었으면 "첨부 파일이 보낼 때와 달라졌습니다. 전송을 취소한 뒤 다시 보내세요."
- **취소:** 지금처럼 `recall`·`cancel-request`를 쓴다(서버가 `uploading`도 받는다).
- **응답 검사:** 글의 모든 전송 기록(취소된 이전 전송 포함)은 형식만 검사한다. 지금 요청과 같은 요청 번호의 기록, 그리고 `create`·`complete`의 응답은 보낸 본문·manifest와 같아야 한다.
- **서버 S3가 꺼져 있을 때(503 `STORAGE_NOT_CONFIGURED`):** "서버의 파일 업로드 설정이 꺼져 있습니다. 관리자에게 확인해 주세요."를 띄운다.
  - `create`에서 받으면 서버에 그 요청이 없으므로 초안으로 되돌린다.
  - `upload-urls`·`complete`에서 받으면 서버에 요청이 있으므로 전송을 그대로 둔다(전송 확인 필요).
- **본문이 빈 글:** 한국어 뜻을 만들지 않고, AI 글 생성에 넘기는 최근 글 목록에서도 뺀다.

## 받아들인 한계

- 취소한 전송을 휴대폰이 이미 올린 경우, 그 뒤에 고친 첨부가 PC 카드에 보일 수 있다. 본문에도 있는 같은 종류의 어긋남이다.
- 일상 첨부를 올리는 동안 수집의 다운로드는 막지 않는다. 올릴 바이트는 시작할 때 출력 폴더로 복사되어 수집 파일과 겹치지 않는다.
- 등록 완료 글을 지우지 않으면 원본은 계속 쌓인다(수집 [등록]과 같다).
