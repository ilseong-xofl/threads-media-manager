# 로컬 앱의 다운로드 회차와 중단 정책

실행 정책 v7 / 2026-09-22. **플러그인은 수집 전용이고 로컬 앱이 다운로드를 시작·관리한다.** 수집과 다운로드를 계정마다 자동 연결하던 설계는 종료한다. 검증된 단일 파일 파일럿은 `local-runtime/`으로 옮겨 보존한다. 파일 하나 앱 UI는1D에서 연결했다. 35–45첨부 회차는 앱에 연결했고, 비정상 종료·오류 후 명시적 재개를 제공한다. 사용자 중지 기능은 없으며 다운로드 중 일반 창 닫기·앱 종료는 차단한다. 현재 버튼/토스트 흐름은 [구현 계약](phase-1e-download.md)을 따른다. 사용자 결정으로 다운로드 일일 횟수 제한은 없다. 미완성 배치 초안과 90회 정책은 적용하지 않는다. 현재 범위는 [로컬 실행기 계약](local-download-runner.md)을 따른다.

## 1. 분리된 시작과 상태 소유권

```text
Codex 플러그인: A 수집 → 임시 기록 종료·Excel 확정·기준 표시 → 수집 계정 간 휴식 → B 수집 → 종료
로컬 앱: 확정 Excel 새로고침 → 다운로드(n) 클릭·계획 고정 → A 다운로드·회차 휴식 → 계정 간 휴식 → B 다운로드
```

사용자가 수집과 다운로드를 각각 요청한다. 플러그인은 다운로드 실행기·state.db·다운로드 중단 상태를 읽거나 쓰지 않는다. 앱은 Threads 페이지에 접속하거나 수집을 시작하지 않는다. 앱 실행·폴더 연결·새로고침만으로 다운로드를 시작하지 않는다.

| 구분               | 기준                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------- |
| 수집 기준          | 최초 미디어 원글 10건, 이후 이전 기준 ID까지 최대 20건. 일일·탐색·중단 규칙은 수집 계약 유지 |
| 수집 원본          | 결과 Excel의 확정 실행. Excel/accounts는 보고·표시용이고 다운로드 결과를 덧쓰지 않음         |
| 다운로드 계정 순서 | 버튼 클릭 시 연결 폴더의 계정명 순서로 고정. 여러 계정의 글을 전역 게시일순으로 섞지 않음    |
| 계정 내 순서       | 선택한 계정의 미완료 게시글 중 오래된 글부터, 게시글 안에서는 첨부 순서대로                  |
| 회차               | 같은 계정의 남은 첨부 합계에 맞춘 게시글 묶음. 정상 진행은 수집된 첨부 전부 저장             |
| 전송               | 파일 1개씩 순차 진행. 파일·회차·계정 사이 대기 유지                                          |
| 첫 오류            | 앱 다운로드 전체 중단. 다음 첨부·회차·다른 계정의 다운로드도 시작하지 않음                   |
| 재개               | 중단 사유·원본·계획·대기 재확인 후 명시적 이어하기. 성공 파일 보존                           |
| 상태 소유자        | 앱의 로컬 실행기만 state.db·media를 갱신. 플러그인에 다운로드 DB를 만들지 않음               |

다운로드 오류나 파일/서버 대기는 이후 사용자가 별도로 요청한 수집을 자동 금지하지 않는다. 수집 자체의 오류·제한·일일 가드는 그대로 적용한다. 새 Excel·새 URL·새 계정이 생겨도 앱의 중단·요청 이력·휴식을 해제하거나 자동 재시작하지 않는다.

## 2. 잠금과 원본 읽기

수집 루트의 공통 실행 잠금 `_work/collector.lock`으로 활성 수집과 활성 다운로드를 겹치지 않게 한다. 두 기능이 같은 잠금의 소유자·토큰을 확인하며 타 실행의 잠금을 임의 제거하지 않는다. 앱을 단순히 열거나 마지막 정상 화면을 보는 동안 잠금을 독점하지 않는다. 다운로드 오류를 기록하고 활성 작업을 종료하면 잠금은 해제하되 DB의 중단 상태는 보존한다. 플러그인은 이 DB를 열 필요가 없다.

수집기는 임시 JSONL을 정규화하여 결과 Excel과 accounts를 저장·검증한 뒤 임시 기록을 정리한다. 저장 실패 시 임시 기록을 보존하고 같은 입력으로 재수집 없이 복구한다. 앱의 새로고침과 계획 확정은 활성 수집이 끝난 뒤 공통 잠금 아래 확정 원본을 안정적으로 읽는다. 손상 Excel·진행 중 실행·원본 충돌은 채택하지 않고 사유를 표시한다. 기존 daily-v1 Excel은 변환 없이 읽는다.

앱은 시작·사용자 새로고침·명시적 재개 때 검증된 Excel을 읽고 전체 검증 후 메모리 모델을 교체한다. 파일 크기·수정 시각은 힌트이며 내용 SHA-256으로 원본 버전을 식별한다. 동일 파일명도 변경 여부를 확인한다. 읽기 도중 변경되면 해당 스캔을 채택하지 않는다. 자동 폴더 감시는 Phase 1 필수 범위가 아니다.

다운로드를 시작할 때 계정·게시글·첨부 키, 원본 참조·hash, 순서, 정책과 회차를 고정한다. 새 자료를 진행 중인 계획에 자동 추가하지 않는다. 전송 직전에도 선택한 원본 버전을 확인하고 예상 밖 변경이면 앱 다운로드를 중단한다. 다음 사용자 새로고침에서는 새 확정 실행을 별도로 검증할 수 있지만, 기존 실패 작업을 성공으로 바꾸거나 중단을 해제하지 않는다. 이미 완료한 파일은 URL·원본 hash가 달라졌다는 이유로 지우거나 다시 받지 않는다.

## 3. 게시글과 첨부 판정

게시글 키는 `(계정명, 게시글ID)`, 첨부 키는 여기에 순서를 더한다. ID는 대소문자를 구분하는 문자열이다. 모든 일별 Excel을 키로 병합하고 로컬 완료 파일에 연결한다. 미완료 게시글은 목록에서 숨기고 다운로드 버튼 수로 표시한다. 이번 대상은 사용자가 버튼을 누른 시점의 유한 계획으로 한정한다. 기존 오류 계획을 새 정상 계획에 몰래 편입하지 않는다.

준비된 게시글은 등록일 오름차순이며 미상이면 가장 이른 수집일, 동률이면 문자열 게시글 ID로 고정한다. ID 크기를 시간으로 해석하지 않는다. 5개 중 3개가 이미 저장돼 있으면 남은2개만 회차 계획에 센다.

시작 전에 게시글의 **남은 첨부 전부**에 유효한 원본 참조와 허용된 HTTPS 후보가 있어야 한다. blob·주소 없음·원본 미연결·수집 진행 중·순서 충돌로 일부 첨부를 받을 수 없으면 게시글 전체를 사전 보류한다. 보류 수·사유를 표시하고 정상 대상만 계획에 넣을 수 있다. 실제 다운로드 오류를 사전 보류로 바꾸어 다음 항목을 진행하지 않는다.

게시글 다운로드 완료는 **선택한 원본 버전에서 수집된 첨부 전부의 저장 완료**다. 수집 partial을 complete로 승격하거나 실제 Threads의 전체 첨부를 확인했다고 표시하지 않는다. 파일 저장과 미리보기 코덱 지원도 구분한다.

## 4. 같은 계정의 게시글 묶음

1. 준비된 게시글을 오래된 순서로 나열한다. 초기 운영 범위는 남은 첨부 **35–45개**, 상한을 넘지 않는 가장 긴 연속 게시글 묶음이다.
2. 앞 13게시글이 39파일, 다음 글이 5파일이면 14게시글·44파일을 모두 받는다. 그다음 4파일은 48이 되므로 다음 회차로 둔다. 파일 수를 맞추려고 게시글을 쪼개거나 뒤의 작은 글을 앞당기지 않는다.
3. **계정의 마지막 묶음은 35개 미만이어도 처리한다.** 10게시글·30파일이면 30개로 끝내고 다른 계정 자료로 채우지 않는다.
4. 단일 게시글이 45개를 초과하거나 게시글 경계상 중간 묶음을 범위 안에 만들 수 없으면 해당 경계에서 `회차 범위 확인 필요`로 대기한다. 앞에서 성립한 회차는 처리할 수 있지만 문제 경계나 계정을 건너뛰지 않는다.
5. 회차 시작 전 **묶음 전체 대상**을 고정하고 남은 첨부의 원본·주소·저장 상태를 확인한다. 일일 횟수 제한이나 잔여 요청량 검사는 없다.
6. 선택한 첨부가 원본에서 사라져도 계획을 완료로 바꾸지 않는다. 재시작·새 계획으로 회차를 잘라 대기를 초기화하거나 요청 이력을 지우지 않는다.

20게시글×3첨부는 15게시글·45파일 → 회차 휴식 → 5게시글·15파일 → 계정 간 휴식 → 다음 계정 다운로드다. 이 흐름에서 브라우저 수집은 발생하지 않는다.

## 5. 요청 기록과 대기

파일 저장·검증 완료 후 무작위 **3–10초**, 회차 종료 후 **60–120초**, 다운로드 계정 종료 후 **10–30초**를 초기 운영값으로 둔다. 수집 스크롤 간격과 별도 정책이다. 전송·저장·검증 시간을 추가 대기에서 차감하지 않는다. 경계에서 한 번 뽑은 허용 시각을 보존하며 여러 조건이 겹치면 가장 늦은 시각을 적용한다. 서버의 더 긴 Retry-After가 우선한다. 마지막 회차·계정 뒤에도 다음 실행의 허용 시각을 보존한다.

사용자 결정으로 **다운로드 일일 횟수 제한은 없다.** 개발용1회/24시간 설정은 제거했으며90회 등 다른 일일 상한으로 대체하지 않는다. 사용자가 시작한 유한한 대상 계획과 파일/회차/계정 대기, redirect·timeout·첫 오류 중단을 적용한다.

앱 실행기는 전송 전에 요청을 SQLite에 기록하며 실패·중지·종료로 이력을 되돌리지 않는다. 기록 실패 시 전송하지 않는다. 최근24시간 요청 수는 진단용 통계일 뿐 전송 허용 조건이 아니다. 계정·새 Excel·업데이트·앱 재시작으로 요청 이력·대기·중단을 초기화하지 않는다.

앱은 남은 게시글·파일·회차와 저장된 대기 또는 중단 사유를 안내한다. 요청 잔여량·일일 한도 소진 표시는 없다. 서버 대기시간이 미상이면 완료 시각을 만들어내지 않는다. 시간 경과만으로 오류 중단을 자동 해제하거나 뒤의 다른 계정을 먼저 진행하지 않는다.

## 6. 중단과 복구

HTTP 오류·timeout·연결 끊김·예상 밖 응답·파일 검증·크기·redirect·원본·디스크·DB 오류는 첫 발생에 **앱 다운로드 전체를 중단**한다. 자동 재시도·실패 항목 건너뛰기·다른 URL 추측은 없다. 다른 계정의 다운로드도 중단한다. 완료 파일과 Excel·수집 기준은 보존한다.

사용자 중지는 제공하지 않는다. 앱/실행기 강제 종료·컴퓨터 종료·절전 복귀 후 자동 네트워크 재개는 없다. 명시적 이어하기에서 중단 원인·원본·정책·대기를 확인하고 기존 미완료 회차의 남은 첨부 전체를 먼저 확인한다. 남은 수가 35개 미만이어도 복구 회차로 허용하며 새 게시글로 채우지 않는다. recover는 추가 HTTP 없이 검증된 저장 단계만 복구한다. 명시적 resume은 로컬 복구 뒤 기존 대상만 재검증하며 이전 실패 시도·부분 파일·대기·요청을 보존하고 미완료 파일만 새 시도로 받는다. 새 수집 게시글은 기존 회차에 추가하지 않는다.

다운로드 오류로 수집을 자동 재실행하지 않는다. 사용자가 나중에 별도로 요청한 수집은 수집 계약과 잠금 조건에 따라 진행할 수 있다. 플러그인은 다운로드 DB의 오류를 검사하지 않는다. 앱은 새 수집 결과를 받아도 기존 중단·거절 URL·성공 파일·소비 기록을 유지한다. 과거 만료 주소는 일반 증분 수집으로 반드시 갱신되는 것이 아니며, 별도 허용된 브라우저 재확인이 필요한 항목으로 표시한다.

## 7. 사용자 안내와 검증

앱은 별도 준비 화면 없이 시작하며 중앙 토스트에서 게시글·파일·회차 수, 보류, 대기와 중단 사유를 보여준다. 실제 저장된 원본에서만 수량을 계산한다. 진행 예: `A 20게시글·60파일 / 2회차(45+15), 이후 B 다운로드`. 오류 예: `A의 4번째 게시글에서 오류가 발생해 앱 다운로드를 멈췄습니다. 저장한 파일과 수집 결과는 보존했습니다.`

모의 검증은 게시글 비분할·마지막 작은 회차·유한 계획 고정·첫 오류 후 추가 GET 0회·중복 전송 0회·원본 변경·잠금 충돌·재시작 보존을 포함한다. 앱 다운로드 중 수집은 공통 잠금으로 대기하고, 작업 종료 후 별도 수집은 앱 DB에 접근하지 않는지 확인한다. 새 Excel 확정으로 다운로드 중단이 풀리거나 작업이 자동 재개되지 않아야 한다. 검증된 파일럿, 미완성 배치, 앱 미구현 범위를 구분해 보고한다.
