# 라이브러리 재연결과 DB 백업·복원

2026-09-22 구현. 상단 설정 버튼에서 현재 연결 대상 폴더를 확인하고 실행한다. 화면에 남아 있는 이전 정상 목록과 현재 연결 대상이 다를 수 있으므로 설정은 main의 현재 폴더를 별도로 조회한다. 각 작업은 main의 작업 가드와 Python의 수집 루트 공통 잠금으로 직렬화한다. 수집·다운로드·편집·삭제 등 실행 중에는 시작하지 않는다.

## 최초 폴더 지정과 재연결

앱에 기억된 작업 폴더가 없으면 최초 실행 때 폴더 선택창을 자동으로 한 번 연다. 수집 플러그인의 폴더 설정은 선택창의 기본 위치로만 사용하며 선택을 대신하지 않는다. 선택한 폴더는 다음 실행부터 자동으로 불러온다. 취소하면 빈 화면의 **설정 열기**에서 다시 선택할 수 있다. 상단에는 폴더 연결 버튼을 표시하지 않는다.

이후 위치 변경은 **설정 → 폴더 재연결 → 새 작업 폴더 선택**으로 처리한다. 기존 DB가 있으면 같은 동작 안에서 새 경로로 재연결하고 목록을 갱신한다. 별도의 사전 폴더 연결은 필요하지 않으며 선택창 취소는 기존 연결을 유지한다. 기존 폴더가 없어졌거나 첫 설정을 취소했어도 설정에서 폴더를 선택할 수 있다.

기존 수집 폴더 전체(Excel, `state`, `media` 포함)를 옮겼다면 새 위치를 선택한다. DB가 없는 첫 폴더는 연결만 하며 DB·미디어 식별 파일을 자동 생성하지 않는다. 복원이 필요한 기존 자료 폴더도 선택한 뒤 같은 설정에서 DB 복원을 진행할 수 있다.

DB와 `media/.library.json`의 library UUID, 지원 스키마, 완료 파일·편집본의 경로·크기·SHA-256을 확인한 뒤 DB의 루트 경로만 변경한다. 파일 이동이나 DB 초기화는 수행하지 않는다. 기존 다운로드·대기·삭제·등록·댓글 정보는 보존한다. 미완료 `running`/`staged`와 부분 파일은 유지해 이후 다운로드 복구가 처리한다. 확실히 죽은 다운로드 실행기/유지관리 프로세스의 잠금만 회수하며 활성·수집·알 수 없는 잠금은 보존하고 거부한다.

## DB 백업

**DB 백업**을 누르고 저장 파일을 선택한다. SQLite online backup으로 WAL을 포함한 일관된 스냅샷을 만든다. 앱 이름·앱 버전·스키마 버전·library UUID·생성 시각·스키마 해시를 기록하고 무결성·외래 키·허용된 스키마 및 재시도 연결을 검증한 후 임시 파일을 확정한다.

백업에는 다운로드 작업·요청·대기·중단·삭제 이력, 편집본 메타데이터, 등록글·댓글이 들어간다. **실제 이미지·영상과 수집 Excel은 포함되지 않는다.** 이 파일은 수집 폴더와 함께 따로 보관해야 한다. 백업으로 원문이나 삭제한 미디어를 재생성하지 않는다.

## DB 복원

같은 라이브러리의 앱 생성 백업을 선택하고 확인한다. 다른 library UUID, 지원하지 않는 버전, 손상·잘못된 스키마·외래 키·재시도 이력·누락 미디어는 덮어쓰기 전에 거부한다. 현재 DB·미디어 경로에 백업 파일을 저장하거나 열린 SQLite 파일을 복원 입력으로 쓰지 않는다.

| 현재 상태    | 복원 방식                                                                                                                                                                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 정상 DB      | 복원 전 DB를 `state/backups/before-restore-*.sqlite`로 자동 백업한다. 등록글·댓글을 백업 시점으로 되돌리며 다운로드·요청·대기·중단·미디어·편집본·삭제 이력은 현재 값을 유지한다. 삭제된 게시글은 되살리지 않는다. 등록글 revision은 증가시켜 열려 있던 오래된 수정 요청을 거부한다. |
| DB 유실·손상 | 같은 미디어 marker와 유효한 백업의 전체 상태를 복원한다. 손상 DB와 sidecar가 있으면 raw 파일을 먼저 자동 보관한다. 복원 파일을 별도로 준비·검증한 뒤 원자 교체한다. 백업 이후 이력을 확인할 수 없으므로 `database_restored` 중단을 추가한다.                                        |

전체 복원 후 자료 조회·등록 관리는 가능하지만, 다운로드는 검토 필요 상태로 남는다. 일반 **이어서 다운로드**, 시간 경과, 폴더 재연결로 이 보류를 해제하지 않는다. 백업 이후 다운로드 이력을 자동 추정하는 기능과 이력 확인 후 해제 기능은 제공하지 않는다. 손상 DB의 raw 자동 보관본은 조사·복구 자료이며 정상 백업처럼 바로 다시 복원할 수 있다는 뜻이 아니다.

확인창 취소는 파일을 변경하지 않는다. 작업 도중 일반 창 닫기는 이미 시작한 작업의 완료를 기다린다. 강제 종료 시 SQLite 트랜잭션·임시 파일·안전 보관본으로 기존 자료를 보존하며 다음 요청에서 소유자가 확실히 종료된 유지관리 잠금만 회수한다. 이 설정은 다른 라이브러리로 데이터 가져오기나 동기화 기능이 아니다.

검증 범위는 [다운로드 복구 통합 검증](download-recovery-verification.md)에 기록한다.
