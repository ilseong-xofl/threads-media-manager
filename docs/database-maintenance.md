# 컴퓨터 이전과 DB 백업·복원

2026-09-29 사용자 결정: 이 기능은 **작업 폴더 전체를 새 컴퓨터로 옮겨 그대로 사용하는 용도**다. 기존 파일을 다시 다운로드하거나 유실된 자료를 재구성하는 기능이 아니다. 백업 DB와 실제 파일의 동일성을 확인한 뒤 새 경로로 연결하며 복원 때문에 별도의 다운로드 보류를 추가하지 않는다.

## 컴퓨터 이전 순서

1. 기존 컴퓨터에서 수집·다운로드·게시 작업을 마친 뒤 설정의 **DB 백업**으로 `.sqlite` 파일을 저장한다. 게시 완료·댓글 게시·결과 불명·통계 이력도 작업 폴더의 `state/publication-transfer.json`에 함께 저장한다.
2. 앱을 종료하고 **작업 폴더 전체와 DB 백업 파일**을 같은 시점의 자료로 새 컴퓨터에 복사한다. `accounts.xlsx`, `results`, `state`, `media`, `_work` 등 폴더 안의 파일과 숨김 식별 파일을 함께 옮긴다.
3. 새 컴퓨터의 앱에서 옮긴 작업 폴더를 선택하고 **DB 복원**으로 함께 보관한 백업을 선택한다. 정상 `state/state.db`까지 폴더에 포함되어 있으면 폴더 지정만으로도 기존 자료를 사용할 수 있다.
4. **Threads 토큰과 파일 서버 연결코드는 새 컴퓨터에서 다시 입력**한다. PC별 OS 암호화 자격증명은 이전 파일에 포함하지 않는다. 이후 기존 글 조회·편집·등록 관리와 새로운 수집분 다운로드를 정상적으로 사용한다.

복원과 폴더 연결은 HTTP 요청을 실행하지 않는다. 완료된 첨부는 저장 파일 그대로 사용하고 이후 다운로드 버튼은 새 미완료 첨부만 대상으로 삼는다. 원래의 서버 대기·다운로드 오류·중단 상태가 있으면 이를 보존한다. 백업·폴더 복사 중 기존 PC에서 작업을 계속해 서로 다른 시점의 자료를 섞지 않는다.

## 폴더 지정과 재연결

앱에 기억된 작업 폴더가 없으면 최초 실행 때 폴더 선택창을 한 번 연다. 수집 플러그인의 폴더 설정은 선택창 기본 위치의 힌트이며 선택을 대신하지 않는다. 이후 위치 변경은 **설정 → 폴더 재연결**에서 진행한다. 취소는 기존 연결을 유지한다.

DB와 `media/.library.json`의 library UUID, 지원 스키마, 완료 파일·편집본의 경로·크기·SHA-256을 확인한 뒤 DB의 루트 경로만 갱신한다. 이전 PC의 Windows 또는 POSIX 절대 경로는 이전 위치 식별 정보로만 읽고 새 컴퓨터의 실제 선택 경로로 바꾼다. 파일 이동·초기화·재다운로드는 하지 않는다. 등록·댓글·편집·삭제·요청·대기 이력은 보존한다.

DB가 없는 첫 폴더는 연결만 하며 DB·미디어 식별 파일을 자동 생성하지 않는다. 기존 자료와 백업이 있는 폴더도 먼저 선택한 뒤 DB 복원을 실행할 수 있다. 미완료 `running`/`staged`와 부분 파일은 유지하며, 별도의 명시적 다운로드 복구가 처리한다. 활성·수집·소유자 미상 잠금은 보존하고 거부한다.

## DB 백업

SQLite online backup으로 WAL을 포함한 일관된 스냅샷을 만든다. 앱·스키마 버전, library UUID, 생성 시각과 스키마 해시를 기록하고 무결성·외래 키·지원 스키마·재시도 연결을 검증한 뒤 확정한다.

DB에는 다운로드·요청·대기·중단·삭제 이력, 편집본 정보, 등록글·댓글과 pHash 파생 캐시가 들어간다. **이미지·영상·수집 Excel은 DB 백업에 포함되지 않는다.** 따라서 작업 폴더 전체도 함께 복사해야 한다. 게시 이력 파일 저장까지 성공해야 앱이 DB 백업 완료를 안내한다.

## DB 복원

같은 라이브러리의 앱 생성 백업을 선택한다. 다른 UUID·지원하지 않는 버전·손상된 백업·잘못된 스키마나 재시도 연결·필요한 미디어 누락은 덮어쓰기 전에 거부한다. 현재 DB·미디어 경로를 백업 저장 대상으로 사용하지 않는다.

| 현재 상태 | 복원 방식 |
| --- | --- |
| 정상 DB | 현재 DB를 `state/backups/before-restore-*.sqlite`로 자동 보관한다. 등록글·댓글은 백업에서 가져오고 현재 다운로드·요청·대기·중단·미디어·편집·삭제 이력은 유지한다. 새 폴더 경로도 같은 작업에서 반영한다. 최종 삭제된 글은 되살리지 않고 수집에서 삭제된 글의 마지막 등록·댓글 참조도 보존한다. 등록글 revision을 증가시켜 오래된 수정 요청을 거부한다. |
| DB 없음·손상 | 동일한 미디어 식별 정보와 필요한 파일을 검증한 뒤 백업의 전체 DB를 새 위치에 원자 교체한다. 손상 DB와 sidecar는 먼저 별도 보관한다. 백업의 실제 요청·대기·중단 상태를 유지하며 `database_restored` 같은 추가 보류를 만들지 않는다. |

구버전에서 만들어진 `database_restored`·`restored_history_review` 보류는 검증한 명시적 폴더 재연결 또는 DB 복원에서만 해제한다. 그 안의 원래 서버 오류·중단 사유와 대기는 유지하며 기존 검토 메타데이터는 이력으로 남긴다. 일반 상태 조회·다운로드 재개는 여전히 이 보류를 임의로 해제하지 않는다.

백업에 수집 전용 삭제 기록이 없는 경우 Excel의 `Y`만으로 최종 삭제와 구분할 수 없는 글을 되살리지 않는다. 없는 이미지·영상이나 백업 이후 사라진 DB 기록을 추정해 복원하지 않는다. 그런 재해 복구·자동 재다운로드·별도 이력 검토 화면은 이 기능의 범위에서 제외한다.

## 게시 이력의 이전

API 게시 이력은 라이브러리 DB 복원과 별도로 유지한다. DB 백업 시 해당 library UUID의 게시 원글·댓글, 원격 ID, 결과 불명 상태와 통계 조회 시각을 `state/publication-transfer.json`에 저장한다. 이 파일은 토큰·연결코드를 포함하지 않는 이전용 자료다. 새 PC의 폴더 연결·DB 복원에서 형식과 UUID를 검증하고 새 PC의 OS 암호화 저장소로 합친다.

현재 PC에 이미 있는 게시 성공·결과 불명 기록을 오래된 이전 파일로 되돌리지 않는다. 복사된 진행 중 게시 기록은 결과 불명으로 유지하고 자동으로 게시하지 않는다. ID·원글·계정이 충돌하면 기존 이력을 보존하고 오류를 안내한다. 이전 파일이 없는 구버전 폴더는 로컬 자료 연결을 계속 지원하지만, 게시 완료 이력까지 옮기려면 기존 PC의 최신 앱에서 DB 백업을 다시 실행해야 한다.

모든 유지관리는 앱 작업 가드와 공통 폴더 잠금을 사용한다. 취소는 파일을 변경하지 않고, 작업 중 일반 종료는 완료를 기다린다. Windows 실제 PC 이전·OS 암호화·설치 검증은 최종 배포 단계에서 별도로 수행한다.
