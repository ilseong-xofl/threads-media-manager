# Excel 원본 읽기 계약: daily-v1

기준은 수집 플러그인의 [daily-v1 계약](../plugins/threads-collector/skills/threads-collect/references/excel-contract.md)과 [저장 helper](../plugins/threads-collector/references/collection-source.md)다. 날짜별 Excel이 유일한 최종 원본이다. accounts.xlsx는 계정 입력과 수집 기준 표시이며 SQLite에는 앱 작업 상태만 저장한다. 수집 JSONL은 임시 기록이다. 기존 daily-v1 파일은 변환 없이 읽고, 알 수 없는 형식은 추정하지 않는다.

## 파일과 키

- 사용자가 선택한 `results/` 아래 `YYYY/MM/threads-YYYY-MM-DD.xlsx`만 대상으로 한다. 심볼릭 링크로 루트 밖에 나가지 않는다.
- `accounts.xlsx`, Excel의 `~$` 잠금 파일, 양식, backups, _work는 대상이 아니다.
- `게시글`, `미디어`, `실행기록` 시트의 A3는 `형식 버전`, B3는 `daily-v1`, 6행은 헤더, 7행부터 데이터다.
- 열 위치 대신 헤더 이름으로 읽는다. 추가 열·서식은 무시하며 원본 파일은 수정하지 않는다. 아래 계약 열 누락·중복 헤더는 오류다.
- 게시글 키는 `(계정명, 게시글ID)`, 미디어 키는 `(계정명, 게시글ID, 순서)`, 실행 키는 `(계정명, 실행ID)`다.
- ID는 대소문자를 유지한 문자열이다. 숫자로 바꾸거나 크기로 최신 여부를 비교하지 않는다. 계정명은 앞뒤 공백 제거 외 임의 정규화·개명 추정 병합을 하지 않는다.
- 행 번호는 오류 위치 안내용이며 데이터 ID가 아니다. 첨부 순서는 1부터 시작하는 정수다.

## 게시글 시트

| 열 | 앱 해석 |
|---|---|
| 계정명, 게시글ID, 원문URL | 원글 키와 원문 링크 |
| 등록일(KST) | 절대 게시 시각. 비어 있으면 미상 |
| 수집일(KST) | 해당 일별 파일에 처음 기록한 시각 |
| 최근확인시각(KST) | 그 행을 실제 마지막으로 관찰한 시각 |
| 캡션 | 줄바꿈 포함 원문 텍스트; HTML로 실행하지 않음 |
| 이미지 수, 영상 수 | 관찰된 첨부 수. 전체 수 보증 아님 |
| 캡션 상태, 첨부 상태 | 각각 complete / partial / unknown |
| 확인실행ID | 해당 계정의 실행기록에 연결 |

`complete`는 확인 완료, `partial`은 일부/전체 수·순서 확인 미완료, `unknown`은 판단 근거 부족이다. 캡션 없는 것이 확인되면 빈 캡션+complete가 정상이다. 첨부 partial은 다운로드 실패를 뜻하지 않는다.

## 미디어 시트

| 열 | 앱 해석 |
|---|---|
| 계정명, 게시글ID, 순서 | 첨부 키 |
| 종류 | image / video |
| 다운로드URL | 관찰된 HTTPS 파일 후보. 쿼리 포함 원문 보존 |
| 관찰주소 | DOM에서 관찰한 주소. 다운로드URL 대체 용도로 자동 사용하지 않음 |
| URL확보시각(KST) | 후보 주소를 실제 관찰한 시각 |
| 만료추정시각(KST), 만료근거 | 참고 정보; oe_hex_unverified / unknown |
| 주소상태 | http_candidate / blob_unresolved / missing |
| 선언 폭(px), 선언 높이(px) | 수집 당시 선언값. 다운로드 후 실측값과 구분 |
| 추출위치, 비고 | 후보 선정 근거와 한계 |
| 확인실행ID | 해당 계정의 실행기록에 연결 |

`http_candidate`는 아직 다운로드 성공을 확인하지 않은 후보다. `blob_unresolved`와 `missing`은 다운로드 실행기에서 직접 받을 주소가 없는 상태다. 만료 시각이 비어 있다고 무기한으로 보거나 추정 시각을 넘었다고 확정 실패로 보지 않는다. blob 문자열은 별도 앱에서 재사용할 파일 URL이 아니다. [MDN 설명](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/blob).

## 실행기록 시트

계약 열: 실행ID, 수집일자(KST), 계정명, 시작(KST), 종료(KST), 방식, 기존기준ID, 다음기준ID, 최하단확인ID, 기준발견, 대상확인수, 신규저장수, 결과, 누락상태, 특이사항, 이전반영실행ID.

| 결과 | 앱에서의 처리 |
|---|---|
| running | 이 실행을 확인실행ID로 참조하는 행은 보류. 다운로드하지 않음 |
| initial_complete, anchor_reached, cap_reached, end_reached | 유효한 저장 행 사용. 별도 누락 경고를 보존 |
| partial | 저장된 유효한 행 사용 가능. 수집 미완료 표시 유지 |
| skipped_daily | 신규 관찰 근거로 쓰지 않음. 아래 전이 규칙에 따라 오늘의 기존 정상 수집 실행과 연결 |
| skipped_invalid | 신규 관찰 근거로 쓰지 않음. 활성 계정 설정 오류를 표시하고 전체 실행 중단 |

행의 실행 참조가 없거나 알 수 없는 상태이면 해당 행을 보류한다. 앱이 running을 partial로 고치거나 수집 기준 ID를 복구하지 않는다. 같은 파일 안에서 다른 계정의 확정된 행은 표시용으로 읽을 수 있지만, 다운로드는 앱에서 확정한 계정 순서와 앱의 중단 상태를 따른다.

`possible_gap` 경고는 과거 수집 누락 가능성이다. 이후 `boundary_reached`가 있어도 과거 경고가 해소됐다고 지우지 않는다. `partial` 실행의 종료 시각이 비어 있는 경우에는 시각을 만들어내지 않는다.

## 날짜·값 검증

시각은 KST(UTC+09:00) 의미로 해석하고 내부 비교는 절대 시각으로 한다. Windows의 로컬 시간대가 달라도 결과가 같아야 한다. Excel 날짜 셀은 통합 문서의 1900/1904 날짜 체계를 확인해 해석한다. 문자열은 명시된 형식만 허용하고 애매한 날짜는 오류로 알린다.

필수 키·실행 참조가 비어 있으면 보류한다. `http_candidate`에는 다운로드URL과 URL확보시각이 필요하다. `blob_unresolved`/`missing`에서 이 두 값이 비어 있는 것은 정상이며 입력 오류가 아닌 `직접 URL 필요`로 표시한다. 등록일·만료추정·미확인 크기 등 허용된 빈 값은 0이나 현재 시각으로 채우지 않는다. 핵심 필드의 수식 셀은 계산하거나 캐시 결과를 신뢰하지 않고 오류로 표시한다. rich text 캡션은 표시 텍스트와 줄바꿈을 보존한다.

한 파일 안 동일 키의 완전히 동일한 중복 행은 한 번만 사용하고 알린다. 서로 다른 내용의 동일 키는 임의로 마지막 행을 선택하지 않는다. 원글 없는 미디어, 알 수 없는 종류, 잘못된 순서는 해당 항목을 보류한다.

파일 구조 오류는 그 파일만, 논리 키/행 오류는 해당 항목만 제외한다. 정상 파일의 데이터를 함께 버리거나 기존 다운로드 파일을 삭제하지 않는다. 파일명 날짜는 수집 실행일이지 게시일·마지막 관찰 시각이 아니다.

## 과거 Excel 이관과 현재 인계의 구분

수집 인계는 임시 JSONL 정규화 → 임시 Excel 검증·원자 교체 → accounts 갱신·검증 → 전달한 임시 입력·journal 정리 순서다. 실패 시 임시 기록을 보존하고 같은 입력으로 저장부터 복구한다. 결과만 저장된 경우 Excel의 입력 해시로 정확한 재시도를 확인하여 accounts 갱신만 처리한다.

앱은 Excel을 직접 읽는다. 과거 JSONL 쓰기와 `import-excel`은 제거했다. 기존 JSONL은 정상 읽기·다운로드 경로에서 사용하지 않으며 동등한 Excel이 확인된 뒤 백업으로 옮길 수 있다. running·불명 실행·중복 충돌·저장 중 변경은 자동 확정하지 않는다. 기존 실패 작업의 대상과 중단 상태를 새 계획으로 초기화하지 않는다.

로컬 앱 개발용 파일 하나 파일럿은 partial 수집을 다운로드하지 않는다. 표시용 부분 읽기와 다운로드 적격 판단은 별개다. 선택 원본 검증 실패·전역 중단은 앱의 다운로드 실행을 멈추며 별도 수집 요청을 제어하지 않는다. 다운로드 상태·파일 경로·요청 소비는 단일 state.db에서 관리하고 Excel 원본에 덧쓰지 않는다.
