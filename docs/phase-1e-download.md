# 다운로드 버튼과 게시글 회차 처리

2026-09-22 사용자 요청에 따라 준비 패널을 없애고 `다운로드 (n)` 한 번으로 현재 대기 중인 게시글을 순차 처리하도록 연결했다. 이 문서는1D의 단일 파일 UI와 종전의 다운로드 전 확인 화면을 대체한다.

## 화면

- 목록에는 첨부가 하나 이상이고 모든 첨부가 검증된 로컬 파일로 연결된 게시글만 표시한다. 일부 파일만 저장된 게시글은 완료 목록에 넣지 않는다.
- `다운로드 (n)`은 연결한 폴더 전체의 미완료 게시글 수다. 검색·계정 필터와 독립적이다.0이면 비활성, 대상이 있으면 약한 강조 효과를 표시한다. 동작 줄이기 설정에서는 효과를 끈다.
- 시작 시 현재 대상을 고정해 바로 처리한다. 진행 중 버튼 숫자는 마지막으로 확인한 목록 기준이며, 상단 중앙 토스트의 게시글·파일·회차 수가 현재 진행을 보여준다. 작업 종료 뒤 목록과 버튼 수를 갱신한다.
- 중앙 토스트는 전송·검증·파일/회차/계정 대기 동안 유지한다. 정상 완료는 `다운로드 완료`를3초간 표시한다. 보류·오류·복구 필요 안내는 자동으로 닫지 않는다. 중지와 로컬 저장 복구를 같은 위치에서 제공한다.
- 카드의 반복적인 저장 수와 저장 상태 필터는 제거했다. 게시글 ZIP 내보내기는 유지한다.

## 실행과 보존

`startDownload()`는 main의 `startAll()`과 Python `command: batch`를 호출한다. renderer가 다운로드 주소나 임의 대상을 전달하지 않는다. 같은 루트의 수집 잠금은 배치 전체 동안 유지하며, 기존 전송 함수를 공유한다.

계정명 순서, 계정 내 오래된 게시글 순서, 첨부 순서를 시작 시 고정한다. SQLite `download_batch` 메타데이터에는 원본 파일 참조·해시·대상 ID·순서·정책·회차·진행 위치를 저장한다. 캡션과 서명 URL은 복제하지 않는다. 새 Excel을 진행 중인 계획에 추가하거나 원본 변경을 자동 수용하지 않는다.

같은 계정의 남은 첨부35–45개를 게시글 전체 단위로 묶고, 마지막 묶음은35개 미만도 허용한다. 범위에 맞지 않는 경계에서 게시글을 쪼개거나 다른 계정을 먼저 처리하지 않는다. 주소 없음·원본 미확정 등 시작 전 받을 수 없는 게시글은 보류 수와 이유로 남긴다. 실제 전송 오류를 보류로 바꾸어 건너뛰지 않는다.

파일 저장·검증 후3–10초, 회차 후60–120초, 계정 후10–30초를 적용한다. 완료 파일·진행 위치·회차/계정 대기를 같은 트랜잭션에 기록하고 마지막 회차와 계정의 대기도 다음 실행에 남긴다. 여러 대기가 겹치면 가장 늦은 허용 시각을 적용한다. 전송 시간이 길었다고 완료 후 대기를 차감하지 않는다. 무응답30초·파일 시도 총600초와 첫 오류 전체 중단을 유지한다. 일일 횟수 제한은 없다.

작업 중지·HTTP/파일/원본 오류는 기존 파일과 계획을 보존하고 중단한다. 버튼을 다시 눌러 오류 중단을 자동 해제하지 않는다. 오류 없이 파일 사이에서 실행기가 종료된 계획은 명시적인 다음 클릭에서 동일 원본·대기·계획을 검증한다. running/staged 작업은 먼저 로컬 복구가 필요하다. 복구는 이미 받은 파일만 검증하며 재전송하지 않는다. 오류 후 재전송/중단 해제 UX는 별도 후속 범위다.

앱 시작·새로고침·폴더 연결만으로 전송하지 않는다. 전체 자료가 이미 저장됐다면 실행기는 읽기 전용0건 결과를 반환하고 새 배치나 DB를 만들지 않는다. 배치의 총 실행 시간에 단일 파일 제한을 씌우지 않으며, main은 유효한 진행 이벤트 사이의 실행기 응답 시간을 감시한다.

## 검증

가상 시계와 모의 전송으로 게시글 비분할·복수 계정·마지막 작은 회차·대기 보존·중복 실행·첫 오류 이후 추가 요청0회·취소·원본 변경·기존 파일 보존을 검증한다. 화면 검증은 별도 모의 앱에서 미완료 숨김·버튼 수·직접 시작·대기·완료3초·오류 유지 흐름을 확인한다. 실제 라이브러리는 기존10게시글·20첨부가 모두 저장돼 있어 추가 CDN 다운로드 없이0건 상태를 확인한다. Windows 실기 검증은1G에 남아 있다.

Mac 자동 검사에서는 TypeScript119개·Python228개와 lint/typecheck/format이 통과했다. 실제 renderer를 사용하는 네트워크 차단 모의 앱에서 완료1개/미완료2개 표시, 한 번 클릭, 대기 토스트 유지, 종료 후 완료3개와 비활성 `다운로드 (0)`, 완료 안내 소멸, 오류 중단 안내 유지를 확인했다. 모의 백엔드는 메모리 자료만 사용하며 실제 수집·CDN 다운로드 검증으로 간주하지 않는다.
