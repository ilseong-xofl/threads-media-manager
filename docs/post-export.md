# 게시글 ZIP 내보내기

2026-09-22 사용자 요청으로 카드 하단에 게시글별 다운로드 아이콘을 추가했다. 이 기능은 앱에 저장된 첨부·편집본과 게시글 정보를 ZIP으로 내보낸다. 원격 첨부 다운로드는 [1E 회차 실행](phase-1e-download.md)에서 처리한다.

## 사용과 파일 구성

카드 하단 오른쪽의 다운로드 아이콘을 누르면 저장 대화상자가 열린다. 기본 위치는 시스템 다운로드 폴더, 기본 파일명은 **`게시글ID.zip`**이다. ID는 원문 게시글의 ID이며 날짜와 계정명을 붙이지 않는다. 사용자가 저장 위치를 선택하고 같은 파일이 있으면 대화상자에서 덮어쓰기를 확인한다.

ZIP에는 게시글의 현재 첨부를 순서대로 넣는다. 파일명은 `01.jpg`, `02.mp4`처럼 첨부 순번과 저장된 파일 확장자를 사용한다. 이미지와 영상이 섞여 있어도 원래 순서를 유지한다. 크롭·영상 캡처로 만든 [편집 PNG](media-editing.md)는 원본 뒤에 생성 순서대로 포함하고 번호를 이어 붙인다. 편집본을 읽을 수 없거나 파일이 누락·손상되면 일부만 내보내지 않는다.

`게시글정보.txt`는 UTF-8이며 다음 정보를 담는다.

```text
계정명: @account
수집일: 2026-09-22 14:09:00 KST
원문 주소: https://www.threads.com/@account/post/AbC_01

캡션
원본 캡션
```

수집일은 게시글의 `collectedAt`을 KST로 표시한다. 캡션의 줄바꿈과 빈 값은 그대로 보존한다. 수집일 원본이 없는 보존 자료에는 `확인되지 않음`으로 표시한다.

## 저장 조건과 처리

- 현재 게시글에 첨부가 있어야 하며 모든 첨부가 검증된 로컬 저장 파일로 연결돼 있어야 한다. 미저장·누락·검토 필요 파일이 있으면 일부만 ZIP으로 만들지 않는다.
- 캐러셀 전체 수가 확정되지 않은 수집 상태 `partial` 자체는 차단 조건이 아니다. ZIP에 포함되는 범위는 앱이 현재 보유한 게시글 첨부 전체다.
- 저장 전 최신 Excel·읽기 전용 SQLite 상태를 확인하고, 각 첨부의 크기와 SHA-256을 검증하며 ZIP에 기록한다. 게시글 정보나 파일이 작업 중 변경되면 완료하지 않는다.
- 결과 ZIP은 수집 폴더 밖에 저장한다. 안전한 일반 파일 경로만 허용하며 임시 ZIP을 완성한 뒤 최종 파일로 교체한다. 실패·취소 시 기존 결과 ZIP을 보존한다.
- 중복 저장 요청과 다운로드·폴더 전환 등 충돌 작업을 막고 완료·오류를 화면에 표시한다. 저장 대화상자 취소는 파일을 만들지 않는다.
- 저장 완료 안내는3초 뒤 자동으로 사라진다. 새 안내가 표시되거나 수동으로 닫으면 이전 타이머를 정리하며, 오류 안내는 자동으로 닫지 않는다.
- 원격 요청·자동 다운로드·재수집·DB 쓰기를 하지 않는다. Excel·SQLite·저장 미디어와 기존 다운로드 대기·타임아웃은 유지한다.

## 검증 범위

자동 검사에서 TypeScript83개·Python204개 테스트와 lint/typecheck/format 검사를 통과했다. 내보내기 검증에는 이미지·영상 혼합과 순서, 텍스트·KST 날짜·UTF-8·빈 캡션, 파일 무결성·경로 제한, 원본/목적지 변경, 기존 ZIP 보존·덮어쓰기, 중복 요청·취소와 worker 실행을 포함한다.

Mac 실제 앱에서도 카드 아이콘으로 저장 대화상자를 열어 날짜 없는 게시글 ID 파일명, 취소 후 목록 복귀, 저장 완료 안내를 확인했다. 영상·이미지가 함께 있는 게시글을 임시 검증 폴더에 저장해 `01.mp4`, `02.jpg`, `게시글정보.txt` 구성과 ZIP CRC를 확인했다. 두 미디어의 SHA-256은 등록 원본과 일치했고 텍스트의 네 항목도 수집 원본과 정확히 일치했다. 기존 Excel·SQLite·미디어 등29개 파일의 SHA-256은 전후 동일했다.

Windows 실기 검증은1G에 남아 있다. Windows의 강제 worker 종료·시간 초과 때 임시 ZIP이 남는지와 정리 방법도 그 단계에서 확인한다.
