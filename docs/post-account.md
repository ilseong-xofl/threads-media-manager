# 등록 글의 계정과 페르소나

2026-11-18 사용자 결정으로 추가했다. 수집 글을 등록할 때 **작성 화면에서 계정을 먼저 고르고**, 그 계정에 일상 탭의 페르소나가 있으면 캡션과 댓글을 그 페르소나의 글로 만든다. 계획과 검토 반영 내용은 이 문서가 정본이다.

## 원칙

- 등록 글 하나는 계정 하나를 위해 쓴다. 한 수집 글을 여러 계정에 올리는 흐름은 없다.
- 작성 화면 순서: 미디어 선택 → 선택한 미디어 → **계정** → 캡션. 등록 글을 열면 맨 위에 계정과 현재 페르소나가 보인다.
- [모바일로 보내기]는 계정을 고르지 않는다. 글에 지정된 계정을 보여 주고 그 계정으로만 보낸다.
- 사용할 계정이 없으면 새 글 작성을 막고 계정 등록을 안내한다. 계정 목록을 불러오지 못한 것은 "계정 없음"과 구분해 다시 시도하게 한다.
- 전제: 한 작업 폴더는 한 사용자가 쓴다. 계정과 전송 이력은 로그인 사용자별이다.

## 저장: `userData/draft-notes.json`

- 계정은 로그인한 서비스 사용자의 것이고 라이브러리 DB는 사용자 구분이 없는 로컬 자료라, 계정 기록은 DB가 아니라 PC의 별도 파일에 둔다(`src/main/draft-note-store.ts`). `daily.json`과 같은 방식: 서비스 주소 + 사용자별 구획, 직렬 큐, 임시 파일 + rename, 읽지 못하는 파일은 덮어쓰지 않는다. **Python·DB 형식·백업은 바뀌지 않는다.**
- 항목: `{ libraryId, postKey, draftCreatedAt } → { revision, accountId, translation, comment }`.
  - `accountId`와 `translation`(캡션의 한국어 뜻)은 **저장 당시의 초안 수정 번호(`revision`)가 지금과 같을 때만** 유효하다. 초안은 저장됐는데 기록이 실패한 경우, 옛 백업을 복원한 경우(복원은 수정 번호를 올린다)는 모두 "기록 없음"이 된다.
  - `comment`(댓글의 한국어 뜻)는 저장된 댓글의 `updatedAt`이 같을 때만 유효하다.
  - `draftCreatedAt`이 키에 있어, 등록을 지우고 다시 만든 글은 옛 기록을 물려받지 않는다.
- 파일을 읽지 못하면(손상 등) 조용히 "기록 없음"으로 넘기지 않는다: 글을 열 때 오류를 알리고, **보내기는 거절한다**(어느 계정을 위한 글인지 확인할 수 없으므로). 읽지 못한 파일은 덮어쓰지 않는다.
- 기록은 PC 사이를 옮겨 가지 않고 DB 백업에도 들어가지 않는다. Windows 배포 검사의 금지 파일 목록에 `draft-notes.json`을 넣었다.

## 글의 계정을 정하는 순서

1. **같은 등록의 전송 이력**이 계정을 붙잡고 있으면 그 계정(`lockedPublicationAccount`, `src/shared/mobile-publications.ts`). 예전 방식으로 보낸 기존 글도 실제 보낸 계정으로 보인다.
2. 없으면 유효한 계정 기록.
3. 그것도 없으면 **보낼 수 있는 첫 번째 계정**이고, 화면과 보내기 창에 "자동 지정"으로 표시한다. 기존 등록 글과 직접 작성 글이 여기에 해당한다. 수정에서 그대로 저장하거나 다른 계정을 골라 저장하면 기록되고, 그대로 보내도 그 계정이 기록된다.

"같은 등록"은 `draftCreatedAt`이 같은 이력만이다.

## 계정 잠금

같은 등록의 이력 중 하나라도 아래에 해당하면 계정을 바꿀 수 없다.

- 이 PC에 보류된 전송이 있다.
- 전송본 상태가 `uploading`·`ready`·`started`·`published`.
- 원글 상태가 `sending`·`unknown`·`uncertain`·`published` — 전송본이 취소됐더라도 실제로 올라갔을 수 있다.

원글이 시작되지 않았거나(`queued`) 깨끗이 취소·실패한(`cancelled`·`failed`) 취소·만료 전송본은 잠그지 않는다. 예전 PC 직접 게시 이력은 계정 정보가 없어 잠금에 쓰지 않는다. 잠긴 글의 계정이 계정 관리에서 사라졌으면 "다른 계정을 고르세요"가 아니라 이미 보낸 글이라는 것만 알리고 다시 보내기를 막는다.

메인이 확인하는 곳:

- **초안 저장 전**(`DraftNotes.requireAccount`): 내 계정인지(서버 목록), 잠긴 글이면 같은 계정인지.
- **초안 저장 후**(`recordDraft`): 기록을 쓴다. 실패해도 저장 결과는 `saved`이고 `noteSaved: false`로 알린다(커밋된 저장을 오류로 바꾸지 않는다).
- **보내기**(`confirmSendAccount`): 이력의 계정·기록의 계정과 같아야 하고, 기록이 없으면 그 계정을 기록한 뒤 보낸다. 서버로 가는 `source`에는 계정을 넣지 않는다.

## 페르소나 기준 캡션

- 화면은 계정 id만 넘기고, 페르소나 이름·설명은 메인이 `daily.json`에서 읽는다(`DailyController.persona`). 2026-11-18부터 페르소나는 서버에도 보관하지만(휴대폰 표시용) 캡션·댓글 생성은 계속 이 PC의 파일을 읽는다 — [일상 탭 계약](daily-posts.md)의 "페르소나의 서버 보관". 페르소나는 계정에서 그때그때 찾는다. 그래서 화면의 페르소나는 **지금의** 페르소나이고, 예전에 저장한 캡션은 다른 설정으로 쓰였을 수 있다.
- `daily.json`을 읽지 못하면 조용히 페르소나 없이 만들지 않고 `caption_persona`로 멈춘다.
- **페르소나가 없는 계정도 같은 스레드 말투로 쓴다**(2026-11-18 사용자 결정 — 이전의 고정 문체는 정돈된 번역문처럼 나왔다). `plainCaptionPrompt`: 페르소나 캡션과 같은 구성에서 화자 설정만 뺀 것이다. 말투 조각은 `plainWording()`(일상 말투에서 페르소나의 말투·나라·이모지 개수 대신 언어별 기본을 쓴다 — 한국어 반말, 영어 미국식 구어), 언어는 화면에서 고른 언어, 400자 이내, 500자를 넘는 제안은 거른다. 영어·일본어는 페르소나가 없어도 한국어 뜻이 함께 온다. 이전의 지시문(`threadsCaptionStyle`, `captionArguments`의 기본 지시문)은 개발 전용 콘텐츠 생성기만 쓴다.
- 미디어는 한 장만 보낸다(2026-11-18 사용자 결정, 페르소나 유무와 무관): 첫 번째 이미지 → 영상만 골랐으면 첫 번째 영상의 화면 한 장(stdin에 `mediaNote`로 영상의 한 장면임을 알림) → 화면을 못 뽑으면 미디어 없이 원본 캡션만. 자세한 규칙은 `docs/phase-2-registration.md`.
- 페르소나가 있으면(`personaCaptionPrompt`, `src/main/caption-generator.ts`):
  - 언어는 페르소나 언어로 고정한다. stdin은 `{ sourceCaption, persona: { name, description } }`이고 페르소나 글은 명령 인자에 넣지 않는다.
  - 원본 캡션이 **무엇을 말할지**, 페르소나가 **누가 어떻게 말할지**를 정한다. 원본의 1인칭 경험은 화자의 경험으로 유지하고(기존 캡션 생성과 같은 전제), 원본 글쓴이의 신상은 페르소나와 어긋나면 버린다. 원본에 없는 제품 사실·사용 경험·가격·효과는 만들지 않는다.
  - 말투는 일상 글과 같은 조각을 쓴다(`src/main/persona-voice.ts`의 `wording()`: 언어별 말투, 폰 글 같은 거친 문장, 이모지와 페르소나의 이모지 개수). 일상 말투를 고치면 캡션도 함께 바뀐다. 다만 말투 규칙은 표현에만 적용하고, 질문 여부와 첫 줄은 원본이 정한다.
  - 일상 전용 규칙(일상 둘·질문 하나, 가게 실명, 계절)은 쓰지 않는다.
  - 제안은 500자를 넘으면 거른다(휴대폰 전송 한도).
- 영어·일본어 페르소나는 제안마다 **한국어 뜻**을 함께 받는다(`translations`). 고른 제안을 그대로 저장하면 뜻도 기록되어 등록 글의 캡션 아래에 보인다. 캡션을 손으로 고치면 뜻은 남기지 않는다.

## 댓글 AI 생성

- 등록한 글의 댓글 편집에서 [생성]을 누르면 제안 3개를 만든다(`generatePostComment`). 같은 글쓴이가 자기 글 아래에 덧붙이는 짧은 한마디이며, 링크는 지금처럼 사용자가 직접 넣는다.
- 메인이 새로 고친 보기에서 직접 읽는다: 원본 캡션, 저장한 캡션, 저장한 미디어 한 장(캡션 생성과 같은 규칙: 첫 번째 이미지 → 영상 화면 한 장 → 없으면 글만), 저장된 링크, 계정의 페르소나. 셋 다 비어 있으면 만들지 않는다.
- 페르소나가 있으면 그 언어와 말투로 쓴다. 없으면 저장한 캡션의 언어(비었으면 원본 캡션의 언어)를 글자로 판별해(`commentLanguage`: 가나 → 일본어, 한글 → 한국어, 그 밖 → 영어) 그 언어의 스레드 말투로 쓰고, 둘 다 비었으면 저장한 캡션을 따르라고만 한다. 한국어가 아니면 한국어 뜻이 함께 온다.
- 제안에 URL이 들어 있거나, 제안 + 줄바꿈 + 저장된 링크가 500자를 넘으면 거른다.
- 캡션 생성과 같은 잠금을 쓰므로 한 번에 하나만 돌고, 취소도 캡션 취소와 같은 경로다.

## 알려 둘 점

- 댓글 저장은 이미 보낸 게시본의 댓글도 고친다(기존 동작).
- 지우고 다시 등록한 글에서 댓글을 저장하면 댓글을 아직 받는 옛 게시본에 반영될 수 있다(댓글 동기화가 글 단위로 이력을 고른다). 이번 작업과 무관한 기존 동작이라 고치지 않았다.
- 수집 캡션 생성과 일상 글 생성은 서로의 실행 여부를 보지 않아 동시에 돌 수 있다(기존 동작).
- 직접 작성 글의 작성 창에는 계정 선택이 없다. 만들어지면 "자동 지정"으로 보이고 수정에서 바꾼다.
