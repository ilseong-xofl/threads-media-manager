# 최종 Windows 테스트 2 — 로컬 앱

수집 플러그인 테스트를 마친 **동일한 깨끗한 Windows x64 PC**에서 이어서 진행합니다. 첫 사용 흐름이 기준이며, 기존 Mac 자료 이전이나 DB 복원으로 시작하지 않습니다.

자동 업데이트가 포함된 **앱 0.1.2**의 `ThreadsMediaManager-win32-x64-Setup.exe`를 사용합니다. 이전 0.1.0에는 업데이트 코드가 없으므로, 이미 설치했다면 새 설치 파일을 한 번 실행해야 합니다. Windows 브라우저에서 [0.1.2 설치 파일 다운로드](https://github.com/ilseong-xofl/threads-media-manager/releases/download/v0.1.2/ThreadsMediaManager-win32-x64-Setup.exe)를 눌러 직접 받습니다. [Release 페이지](https://github.com/ilseong-xofl/threads-media-manager/releases/tag/v0.1.2)에서도 같은 파일을 받을 수 있습니다. 수집 플러그인은 [전용 GitHub 주소](https://github.com/ilseong-xofl/threads-collector)로 설치합니다. 이 후보는 내부 검수용이며 Windows에서 실제 설치·로그인·업로드한 결과는 아직 없습니다. Python·Pillow·ffmpeg·ffprobe·Codex CLI는 앱에 포함되어 있어 사용자가 터미널을 열거나 따로 설치하지 않습니다.

0.1.1에서 창만 보이고 내용이 비어 있었다면 앱을 닫고 0.1.2 설치 파일을 실행합니다. 0.1.2는 설치된 화면 파일 로딩과 Windows 주소 비교를 수정한 버전입니다. 기존 작업 폴더나 계정 정보를 삭제하지 않습니다.

## 시작 전에 준비할 것

- 앞 단계에서 수집 결과를 저장한 **작업 폴더**의 위치.
- AI 캡션용 본인 ChatGPT 계정.
- 실제 게시할 Threads 계정의 유효한 API 토큰. 현재 서비스의 Meta 앱 테스터 등 필요한 사용 자격과 게시 권한은 담당자가 미리 준비합니다.
- 담당자가 발급한 파일 서버 연결 코드(`tfs1.`으로 시작).
- 실제 Threads에 게시해도 되는 테스트 자료와 캡션 1건, 댓글 1건. 게시글·댓글 API 업로드는 실제 공개 동작이므로 내용을 확인한 사용자가 버튼을 누릅니다.

Codex 앱 로그인, 수집용 Threads 브라우저 로그인, 이 앱의 ChatGPT 로그인, Threads API 토큰은 각각 별개입니다. 토큰·파일 서버 코드는 앱 설정에만 입력하고 채팅·테스트 결과표에 붙이지 않습니다.

## 1. 설치와 폴더 지정

1. Windows에서 다운로드한 설치 파일을 더블클릭합니다. 정상 설치 후 **Threads Media Manager**를 실행합니다.
2. 첫 폴더 선택에서 플러그인이 만든 **작업 폴더**를 선택합니다. 플러그인 패키지 폴더나 그 안의 plugins 폴더를 선택하지 않습니다.
3. 필요하면 **설정 → 폴더 재연결 → 재연결**에서 같은 작업 폴더를 지정합니다. **새로고침**으로 원본을 읽습니다.
4. 다운로드 전에는 파일을 모두 저장한 게시글 카드가 아직 없을 수 있습니다. 다운로드 예정 대상은 수집 결과와 연결되어야 합니다.

통과 기준: 설치·첫 실행·폴더 연결이 완료되고 런타임 설치 요청이 없습니다. 보안 경고나 설치 차단이 나오면 정확한 문구를 기록합니다. 보안 프로그램을 끄거나 정책을 바꿔 통과시키지 않습니다. 서명 없는 후보의 경고와 앱 기능 오류는 구분합니다.

## 2. 설정 — ChatGPT·Threads·파일 서버

1. **설정 → ChatGPT · AI 캡션 → ChatGPT 로그인**을 누릅니다. 기본 브라우저에서 로그인하고 앱으로 돌아와 **연결됨**을 확인합니다. 로그인 중에는 설정창을 열어 둡니다.
2. **Threads 계정 → API 토큰**에 토큰을 입력하고 **저장**을 누릅니다. 게시 대상 계정과 실제 만료 일시가 맞는지 확인합니다.
3. **파일 서버 → 연결 코드**에 발급 코드를 넣고 **저장**을 누릅니다. 서버 주소와 **저장됨**이 표시되는지 확인합니다.

통과 기준: 세 설정이 저장되고, 연결한 Threads 계정이 실제 게시할 계정과 일치합니다. 파일 서버의 “저장됨”은 저장 성공이며 원격 업로드 인증 성공은 아래 실제 게시 단계에서 확인합니다.

## 3. 다운로드

1. **다운로드**를 누르고 확인창에서 대상 게시글·파일 수를 확인해 시작합니다.
2. 진행 중 게시글·파일·회차와 다음 다운로드 대기를 확인합니다. 대기는 기존 정책에 따른 정상 동작이며 앱을 강제 종료하지 않습니다.
3. 완료 후 다운로드 수와 중복 제거 수를 확인합니다. 카드·상세에서 이미지, 여러 첨부의 순서, 영상이 정상 표시되는지 확인합니다.
4. 새로고침 후 이미 완료한 파일을 다시 다운로드하지 않는지 확인합니다.

통과 기준: 다운로드 가능한 완전한 글이 표시되고 파일이 열립니다. SHA-256과 첫 이미지 pHash 중복 검사로 제거된 글은 저장 카드 수가 줄 수 있으므로 완료 수·중복 제거 수를 함께 기록합니다. 영상·여러 첨부가 이번 수집 결과에 없었다면 해당 항목은 통과가 아니라 “자료 없음”으로 남깁니다.

## 4. 등록 작성과 AI 캡션

1. 테스트할 수집 글의 상세를 열고 **작성**을 눌러 등록 화면을 엽니다.
2. 사용할 이미지·영상을 선택하고 선택한 순서와 미리보기를 확인합니다. 한 원글 안의 미디어를 사용합니다.
3. 이미지를 선택한 상태에서 **AI 캡션 → 한국어 → 생성**을 누릅니다. 제안 3개가 나오면 하나를 검토해 적용하고 필요하면 직접 수정합니다.
4. 캡션과 첨부를 확인한 뒤 **등록**으로 저장합니다. 등록 목록에서 다시 열어 선택·순서·캡션이 유지되는지 확인합니다.
5. 영상만 선택했을 때 AI 캡션 생성이 비활성화되는지 확인합니다. 배포 앱에는 개발용 AI 이미지 생성 기능이 없습니다.

통과 기준: 터미널 없이 앱 전용 ChatGPT 로그인으로 캡션을 생성하고, 저장한 등록 내용이 유지됩니다. 생성이나 등록 저장만으로 Threads에 게시되지 않습니다.

## 5. 게시글 API 업로드

1. 저장한 등록 글의 캡션·미디어·게시 계정을 최종 확인합니다.
2. 등록 글의 **API 업로드**를 한 번 누릅니다. 진행 화면이 끝날 때까지 기다립니다.
3. 게시 완료 표시와 생성된 게시글 링크를 확인합니다. 링크를 열어 실제 계정·캡션·미디어·첨부 순서를 확인합니다.
4. 같은 글의 중복 업로드가 차단되는지 화면에서 확인합니다. 중복 방지 시험을 위해 API를 반복 호출하지 않습니다.

통과 기준: 파일 서버 전송부터 Threads 게시까지 성공하고 실제 원글 1건이 확인됩니다. 결과 불명·확인 필요 상태가 나오면 자동 재시도하지 말고 링크/게시 이력과 오류 문구를 담당자에게 전달합니다.

## 6. 댓글 작성과 댓글 API 업로드

1. 게시 완료한 글의 **댓글 정보** 영역에서 입력 화면을 엽니다.
2. 댓글 캡션을 입력하고 필요한 경우 링크도 넣은 뒤 **저장**합니다.
3. 저장된 댓글 내용과 대상 원글을 확인한 뒤 댓글 영역의 **API 업로드**를 누릅니다.
4. **댓글 완료** 표시와 실제 원글 아래 답글 1건을 확인합니다.

통과 기준: 댓글이 다른 글이 아닌 방금 게시한 원글의 답글로 등록되고 내용·링크가 맞습니다. 댓글 저장만으로 원격 게시되지 않으며 완료한 댓글의 중복 게시가 차단됩니다.

## 7. 종료·재실행과 최종 기록

앱을 정상 종료하고 다시 실행합니다. 작업 폴더·다운로드 파일·등록·댓글·게시 완료 이력·세 연결 설정이 유지되어야 합니다. 재실행 때문에 다운로드·게시가 다시 일어나면 실패입니다.

- Windows 버전 / 앱 버전 / 테스트 일시: ______
- 설치·폴더 연결: 미검증 / 통과 / 실패
- ChatGPT 로그인·AI 캡션 3개: 미검증 / 통과 / 실패
- Threads 계정·토큰 만료 시각 확인: 미검증 / 통과 / 실패
- 파일 서버 코드 저장·실제 업로드 인증: 미검증 / 통과 / 실패
- 다운로드: 예정 __글 / 완료 __글 / 중복 제거 __글 / 실패 __글
- 이미지·여러 첨부·영상 표시: 미검증 / 통과 / 실패 / 자료 없음
- 등록 저장·선택 순서·캡션 유지: 미검증 / 통과 / 실패
- 원글 API 업로드: 미검증 / 통과 / 실패 — 게시 URL: ______
- 댓글 저장·API 업로드: 미검증 / 통과 / 실패 — 원글 URL: ______
- 정상 종료·재실행 후 자료·로그인·게시 이력 유지: 미검증 / 통과 / 실패
- 터미널 직접 사용·개발 도구 수동 설치: __회 (통과 기준 0회)
- 실패 단계 / 화면 오류 문구 / 재현 순서: ______

테스트 결과에 토큰·연결 코드·개인 인증정보는 적지 않습니다. 실제 원글과 댓글을 정리할 경우 Threads에서 사용자가 직접 삭제합니다.

## 8. Windows 자동 업데이트

0.1.1보다 높은 공개 버전이 준비된 뒤 두 번의 시험으로 확인합니다. 첫 배포 0.1.1만 있을 때 업데이트 안내가 없는 것은 정상이며 업데이트 시험 통과를 뜻하지 않습니다.

1. 앱을 실행하면 약 10초 후 최신 버전을 확인합니다. 계속 실행 중이면 1시간마다 다시 확인합니다. 새 버전은 백그라운드에서 내려받습니다.
2. 다운로드·게시·저장·캡션 작업 중이거나 작성/설정창이 열려 있으면 업데이트 재시작 안내가 보류되는지 확인합니다. 작업을 마치고 창을 닫으면 **업데이트 준비 완료**가 표시됩니다.
3. 첫 시험은 **나중에**를 선택합니다. 앱이 계속 실행되고, 같은 업데이트 안내가 반복되지 않아야 합니다. 정상 종료 후 다음 실행에서 새 버전으로 바뀌는지 확인합니다.
4. 또 다른 새 버전으로 두 번째 시험을 진행하고 **지금 재시작**을 선택합니다. 앱이 재실행되고 새 버전으로 바뀌는지 확인합니다.
5. 두 경우 모두 수집 폴더·기존 파일·등록·댓글·게시 이력과 ChatGPT·Threads·파일 서버 연결이 유지되어야 합니다. 이미 받은 파일을 다시 받거나 이미 게시한 글을 다시 올리면 실패입니다.

- 시험 전 → 후 버전: ______ → ______
- 백그라운드 다운로드·작업 중 안내 보류: 미검증 / 통과 / 실패
- 나중에 → 정상 종료·다음 실행 시 적용: 미검증 / 통과 / 실패
- 지금 재시작 → 적용 후 재실행: 미검증 / 통과 / 실패
- 기존 자료·연결·게시 이력 보존: 미검증 / 통과 / 실패

새 버전이 없거나 인터넷 연결이 끊겼어도 기존 로컬 앱은 사용할 수 있어야 합니다. Windows 설치 경고와 업데이트 기능 오류를 구분해 기록합니다. Mac은 개발 코드를 실행하므로 이 자동 업데이트 시험 대상이 아닙니다.

## 추가 기능과 배포 판정

기본 두 흐름을 마친 뒤 이미지·영상 편집, ZIP 내보내기, 삭제 확인, DB 백업·컴퓨터 이전은 필요한 기능별로 추가 확인합니다. 자료가 없어서 확인하지 못한 기능은 미검증으로 남깁니다. 컴퓨터 이전은 작업 폴더 전체와 같은 시점의 DB 백업을 새 PC로 옮겨 폴더 지정·DB 복원으로 사용하는 별도 시험이며, 완료된 파일을 다시 받을 필요가 없습니다.

**Windows 자동 업데이트 코드와 GitHub 배포 구성을 포함했습니다.** 위 업무 흐름과 별도로 8번의 실제 버전 간 갱신·자료 보존을 검증합니다. 이번 배포는 서명 없는 Windows 설치 파일이며 설치 경고를 기록합니다. 동일 Meta 앱의 테스터 외 사용자 배포 조건도 별도로 확인합니다.

배포 순서: 이번 깨끗한 Windows 최종 시험 → 발견 문제 수정·해당 항목 재시험 → 실제 사용자 1명 라이브 시험 → 결과와 남은 배포 항목 확인 → 일반 사용자 배포. 파일럿 사용자에게는 그 시점에 확인된 후보만 전달합니다.
