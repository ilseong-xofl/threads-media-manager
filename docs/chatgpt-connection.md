# 앱에서 ChatGPT 연결

2026-09-29 사용자 결정: Mac 개발 앱과 Windows 배포 앱 모두 앱 전용 CLI를 사용한다. Windows 사용자는 터미널을 한 번도 열지 않고 앱 설정에서 ChatGPT에 로그인한 뒤 AI 캡션을 생성한다. 수집 플러그인의 브라우저 로그인과 앱의 캡션 인증은 별도다.

## 사용자 흐름

1. 앱 설치 후 설정의 **ChatGPT 로그인**을 누른다.
2. 기본 브라우저에서 본인 ChatGPT 계정으로 로그인한다.
3. 앱의 **연결됨** 표시를 확인하고 기존 AI 캡션 생성 버튼을 사용한다.

로그인 취소, 로그아웃, 연결 상태 다시 확인을 같은 설정에서 제공한다. 로그인 중 설정창을 닫으면 대기를 취소한다. 앱 창 닫기·종료에서도 대기 프로세스를 정리하고 사용자의 브라우저는 종료하지 않는다. 로그인 기다림은 최대 5분이며 실패·취소 후 재시도할 수 있다. 인증이 원격에서 만료·철회되면 로그아웃 후 다시 로그인한다. 계정의 Codex CLI 사용 권한과 사용량 한도는 그대로 적용된다.

## 실행과 인증

- Windows 설치 앱에는 공식 Codex CLI **0.158.0** native 배포 파일을 원래 디렉터리 구조로 포함한다. Node/npm이나 전역 PATH, 사용자 Codex 설치를 요구하지 않는다. CLI와 보조 실행기, 동봉 DLL·라이선스를 ASAR 밖 `resources/runtime/codex`에 보관하며 실행 파일은 절대 경로로 호출한다.
- Mac 개발 실행은 `scripts/macos-codex.json`의 arm64/x64 공식 native 파일을 `build/codex/darwin-<arch>`에 준비한다. `pnpm start`의 Forge preStart에서 다운로드 SHA-256·원래 디렉터리 구조·실행 권한·라이선스·파일별 해시를 검사하며 준비된 정상 파일은 재사용한다. 로그인·상태 조회·캡션 모두 이 절대 경로를 사용하고 Homebrew/PATH의 Codex로 대체하지 않는다. Mac 설치 파일 배포는 범위에 넣지 않는다.
- Windows 버전·다운로드 SHA-256은 `scripts/windows-runtime.json`으로 고정한다. 빌드 때만 다운로드하고, 설치된 앱은 임의 최신 CLI를 자동 설치하지 않는다. CLI 변경은 앱 배포 때 별도로 검증한다.
- `codex login`, `login status`, `logout`과 기존 `codex exec`를 숨겨진 자식 프로세스로 실행한다. 별도 OAuth 구현이나 app-server에 의존하지 않는다. 비밀번호·토큰·OAuth URL을 renderer IPC에 전달하거나 로그로 출력하지 않는다.
- 인증 저장 위치는 Electron userData 아래 `codex`다. 로그인과 캡션 생성 모두 같은 `CODEX_HOME`과 `cli_auth_credentials_store="keyring"`, `forced_login_method="chatgpt"`를 사용한다. 외부 API 키·다른 Codex 홈·대체 인증 서버 환경변수는 전달하지 않는다. OS 저장소 오류를 평문 저장으로 우회하지 않는다.
- 고정 버전의 Windows 기본 구현은 전용 홈의 `secrets/codex_auth.age`에 인증 암호문을 저장하고 OS 자격 증명 저장소에 복호화 키를 보관한다. OS 저장소 항목은 전용 홈 경로 해시로 구분된다. Mac 개발 실행의 직접 keyring 저장도 홈 경로별로 구분된다. 일반 ChatGPT/Codex의 로그인 정보를 복사하거나 로그아웃하지 않는다.
- 인증은 DB 백업·작업 폴더에 포함하지 않는다. 앱 업데이트에서 userData 경로를 유지하고, 새 컴퓨터에서는 다시 로그인한다. Mac 실행기를 바꿔도 같은 앱 전용 홈과 OS 저장소를 사용하므로 기존 앱 로그인을 유지한다.
- 캡션 인증 설정은 `exec` 다음에 전달한다. CLI 0.158.0에서 루트 `-c` 인증 설정 뒤에 `exec -c web_search=...`를 전달하면 상태 조회는 연결됨인데 생성은 인증 없는 401로 실패하는 것을 재현했다. 동일 설정을 `exec` 안으로 옮겨 기존 로그인으로 실제 생성에 성공했다. `--ignore-user-config`, 읽기 전용 sandbox, 도구 차단은 유지한다.
- 로그인 상태 명령은 로컬 자격 증명의 존재를 확인한다. 원격 토큰 유효성·계정 사용 권한·잔여 한도까지 보장하지 않는다. 실제 생성 요청의 인증·권한·한도 오류는 별도로 안내한다.
- 기본 OAuth callback 포트가 다른 로그인에 사용 중이면 새 로그인을 시작하지 않고 해당 로그인 완료를 안내한다. CLI 자체의 고정 포트 동작 때문에 확인 이후 동시에 시작하는 외부 로그인까지 완전히 배제하지는 못한다.

선택 이미지·원문 캡션·출력 언어, 도구 차단·읽기 전용 실행, 제안 3개와 사용자 직접 선택은 기존 [등록 계약](phase-2-registration.md)을 유지한다. 로그인 자체는 모델 요청이나 게시를 실행하지 않는다.

## 검증 경계

- 모의 프로세스로 로그인·로그아웃·상태 확인, 전용 홈·암호화 설정 일치, 외부 키 제외, 중복 클릭, 취소·타임아웃·종료, 출력 한도·민감 출력 비노출, 생성 중 인증 변경 차단을 확인한다.
- renderer는 로그인 필요·연결·대기·취소·오류 상태, 닫기 취소·늦은 응답·재시도와 터미널 안내가 없는 표시를 검사한다.
- Windows 빌드는 공식 native 패키지의 경로·버전·필수 실행기·라이선스와 모든 포함 파일의 해시를 검사한다. 설치 후보 검사에서 사용자 홈과 PATH를 격리하고 내장 CLI 버전 및 미로그인 상태를 확인하도록 구성했다. 실제 브라우저 인증을 CI에 저장하지 않는다.
- 이 추가 구현은 기존 `b1f9f87` Windows CI 성공 기록에 포함되지 않는다. Codex가 포함된 새 Windows 설치 후보 실행, 브라우저 로그인 완료, 실제 캡션 생성, 재실행·업데이트 후 인증 유지와 기존 Codex 공존은 Windows 실기 검증으로 남긴다.

2026-09-29 Mac 최종 `pnpm check`: 린트·타입·포맷 검사, TypeScript **36개 파일 / 1,080개**, Python **523개** 통과. 실제 CLI 0.158.0을 새 임시 홈으로 실행해 미로그인 상태 조회를 확인했다. 최신 Electron 앱을 재실행하고 설정의 ChatGPT 로그인 버튼·로그인 필요 표시·상태 재확인을 확인했다. 수집 23개와 등록 3개가 표시된 기존 라이브러리는 유지했으며 실제 계정 로그인·모델 호출은 실행하지 않았다.
