# 일상 글의 댓글 조회와 답글 설계 (2026-11-21)

상태: **구현 완료(1·2단계, 2026-11-21) — 로컬에서 실제 요청 0건으로 끝까지 확인했고, 배포와 실제 확인(10장 마무리)은 하지 않았다.** 구현 기록과 설계에서 달라진 것은 13장에 있다. 설계는 2026-11-21에 끝냈다(사용자 확인). 2026-11-21에 두 리뷰어(Claude 새 눈, Codex)가 따로 검토했고, 코드에서 확인된 지적을 반영했다(12장). 사용자가 정한 것은 1장에, 정하지 않아 Claude가 판단한 것은 11장에 모았다. Meta에서 아직 확인하지 못한 것은 9장에 있고, 설계는 어느 쪽 결과가 나와도 되게 잡았다.

말: 이 문서에서 **댓글**은 올라간 일상 글에 달린 글(남이 쓴 것, 대댓글 포함)이고, **답글**은 그 댓글 하나에 우리 계정이 다는 글이다. 수집 글에 미리 써 두는 "댓글"(원글 뒤에 올리는 내 댓글 하나)과는 다른 기능이며 그 기능은 바꾸지 않는다.

## 1. 목표와 사용자 결정

올라간 일상 글의 댓글을 휴대폰에서 버튼으로 가져와 서버에 저장하고, PC에서 읽고 답글을 써서 휴대폰으로 보내면, 휴대폰이 답글을 하나씩 올린다.

1. 휴대폰 **등록 완료** 탭에서 글을 고르고 **[댓글 가져오기]**를 누른다. 끝나면 조회 시각과 건수를 뱃지로 보여 준다.
2. 대상은 **일상 글**이다. 수집 글도 요청이 오면 넓힐 수 있게 만든다(8장).
3. 댓글은 **대댓글까지 전부**(`GET /{글 번호}/conversation`), **최신순**, **한 번에 최대 100개**. 첫 조회는 최신 100개까지, 다음 조회부터는 저장된 것보다 새 댓글만 더한다(이때도 최대 100개. 그 사이 새 댓글이 100개를 넘으면 오래된 쪽은 들어오지 않는다).
4. 댓글은 **서버 DB에 저장**하고 PC에서 본다. PC에서 댓글 하나 또는 여러 개에 답글을 써서 **[모바일로 보내기]** 한다.
5. 휴대폰에 **"답글 전송 대기중 (n개)"**가 보이고, 글을 열면 답글 전송 버튼이 있어 **하나씩 순서대로** 올린다.
6. 권한이 없어 조회가 거절되면 토큰을 다시 발급하라는 안내를 띄운다. 토큰 가이드의 권한 5개는 문서에 반영했다(11-21). 가이드 사이트 빌드본에는 "네 가지 권한" 문구가 2곳 남아 있어 다음 가이드 게시 때 고친다.
7. 기능을 만든 뒤 가이드(모바일 앱, 로컬 앱)를 고쳐 게시한다(사용자).

2026-11-21 설계 시작 때 정한 것:

8. **PC의 답글 작성**: 댓글에 [한국어 뜻 보기], 답글은 직접 쓰거나 한국어로 써서 페르소나의 언어·말투로 바꾼다(일상 글의 뜻 보기·수동 등록과 같은 방식). AI 답글 초안 생성은 이번 범위가 아니며 이 구조 위에 다음 단계로 더한다.
9. **조회 기간**: 등록 완료 탭의 7일은 그대로 둔다. 다만 전송 대기 중인 답글이 있는 글은 7일이 지나도 답글을 다 올릴 때까지 탭에 남긴다.
10. **답글 사이 간격**: 답글 하나를 올린 뒤 다음 답글까지 30초 기다린다.
11. **Meta 미확인 항목은 가장 마지막에 확인한다**(9장). 사용자가 시험 글에 댓글·대댓글을 다는 것도 그때다. 구현은 확인을 기다리지 않고 진행하며, 어느 쪽 결과가 나와도 되게 만든다. 약관 확인은 하지 않는다.
12. **휴대폰에서도 댓글을 본다**(문서 검토 뒤 추가). 댓글이 몇 개뿐일 때 PC로 옮겨 가지 않아도 되게, 글 상세에서 댓글 목록을 따로 띄워 최신순으로 내려 보며 읽는다(끝에 닿으면 더 불러온다). 답글 쓰기는 PC에서 한다.

바뀌지 않는 규칙: 서버는 Meta를 호출하지 않는다. PC는 일상 기능에서 Meta를 호출하지 않는다(댓글 읽기와 답글 올리기는 모두 휴대폰 앱이 한다). 휴대폰의 요청은 사람이 버튼을 눌렀을 때만 나가고 자동 조회·자동 재시도는 없다.

## 2. 전체 흐름

```
[휴대폰 앱]  [댓글 가져오기] ──GET /conversation──▶ Meta
     │  받은 댓글(최대 100개)
     ▼
[서버]  댓글 저장(같은 댓글은 덮어씀) ──▶ 조회 시각·건수
     ▲                                   
[PC]  일상 탭 등록 완료 카드 [댓글 n] ─▶ 댓글 창: 뜻 보기, 답글 초안(이 PC에만)
     │  [모바일로 보내기]
     ▼
[서버]  답글 저장(휴대폰 대기)
     ▼
[휴대폰 앱]  "답글 전송 대기중 (n개)" ─▶ [답글 전송] ─▶ 답글마다: 생성 → 처리 확인 → 게시 → 결과 보고 → 30초
```

네 곳을 고친다.

| 곳 | 고치는 것 | 새 버전 |
| --- | --- | --- |
| 휴대폰 앱 | 다리가 `/conversation` 읽기 요청 하나를 더 통과시킴, `features`에 `replies` | 0.3.0 |
| 모바일 웹 | 가져오기, 뱃지, 답글 대기 표시, 순차 전송 | 새 이미지 |
| 서버 | 테이블 3개(migration 0011), 휴대폰·PC용 경로 | 새 이미지 |
| PC | 댓글 창, 뜻 보기, 답글 초안·변환, 보내기·취소 | 0.1.13 |

답글 올리기는 지금 다리의 POST 두 가지(`/threads`, `/threads_publish`)를 그대로 쓰므로 앱 0.2.0에서도 된다. 새 앱이 필요한 것은 댓글 가져오기뿐이다.

## 3. 서버 (threads-admin-api)

### 3.1 테이블 (migration 0011)

기존 테이블과 기존 응답은 바꾸지 않는다. 등록본 구조는 "글 하나에 댓글 하나"(`publication_snapshot.comment`, ledger의 `comment_*` 한 벌)라 여러 댓글·답글을 담을 수 없고, 구버전 PC는 등록본의 새 상태값과 일상 글의 `comment` 값에 깨진다(`mobile-publication-data.ts:94`, `daily.ts:224-233`). 그래서 새 테이블만 더한다. 페르소나(0010)와 같이, 테이블이 없으면 새 경로만 503 `MIGRATION_REQUIRED`이고 기존 경로는 그대로 돈다.

**`thread_reply`** — 가져온 댓글. 한 줄이 Threads의 댓글 하나.

| 열 | 내용 |
| --- | --- |
| `id` | uuid, PK |
| `publication_id`, `owner_id` | → `publication_ledger(id, created_by)` |
| `threads_id` | Meta의 댓글 번호(숫자). `(publication_id, threads_id)` 고유 |
| `parent_threads_id` | 이 댓글이 달린 글의 번호(`replied_to.id`). 원글에 바로 달렸으면 원글 번호 |
| `username`, `text`, `permalink`, `media_type` | Meta가 준 값. 본문은 500자까지이고 비어 있을 수 있다(그림만 있는 댓글) |
| `owned_by_me` | `is_reply_owned_by_me` — 우리 계정이 쓴 글(올린 답글 포함) |
| `posted_at` | Meta의 작성 시각 |
| `first_seen_at`, `last_seen_at` | 처음·마지막으로 조회에 나온 시각 |

저장하지 않는 것: 프로필 사진 주소(기한이 있는 CDN 주소이고 휴대폰·PC 어디에도 보여 주지 않는다), `has_replies`·`is_verified` 등 화면에 쓰지 않는 항목. Threads에서 지워진 댓글은 다음 조회에 나오지 않을 뿐 DB에 남는다(사용자 메모).

**`thread_reply_fetch`** — 글마다 한 줄. `publication_id`(PK), `owner_id`, `fetched_at`(마지막 조회 시각). 댓글이 0건이어도 "조회했음"을 남기려고 따로 둔다. 건수는 `thread_reply`에서 센다(`owned_by_me`는 빼고).

**`thread_answer`** — PC가 보낸 답글.

| 열 | 내용 |
| --- | --- |
| `id` | uuid, PK. **PC가 정한다** — 같은 id로 다시 보내면 같은 답글이다(응답을 잃었을 때의 중복 방지, 일상 글의 `requestId`와 같은 생각) |
| `publication_id`, `owner_id` | 위와 같음 |
| `reply_threads_id` | 답글을 달 댓글. `thread_reply(publication_id, threads_id)`에 있어야 한다 |
| `text` | 답글 본문, 500자까지 |
| `status` | `queued`(휴대폰 대기) · `failed` · `unknown`(올라갔는지 모름) · `published` · `cancelled`. 등록본 ledger의 값과 같은 뜻 |
| `threads_id`, `error_code`, `published_at` | 결과 |
| `created_at`, `updated_at` | |

제약: 댓글 하나에 끝나지 않은 답글(`queued`·`failed`·`unknown`)은 하나뿐(부분 고유 인덱스, PostgreSQL 11에서 지원). 올라간 뒤에는 같은 댓글에 새 답글을 또 쓸 수 있다.

관리자의 사용자 삭제는 페르소나처럼 이 세 테이블의 줄을 함께 지운다(`src/server/admin/service.ts`). 계정 삭제는 `queued` 답글을 `cancelled`로 닫고, `unknown` 답글은 그대로 두되 삭제를 막지 않는다(삭제된 계정은 휴대폰에서 고를 수 없으므로 그 답글은 `unknown`으로 남는다 — 한계).

### 3.2 휴대폰용 경로

| 경로 | 요청 | 응답·규칙 |
| --- | --- | --- |
| `POST /api/v1/mobile/publications/:id/replies` | `{ tokenRevision, replies: [{ threadsId, parentThreadsId, username, text, permalink, mediaType, ownedByMe, postedAt }] }` 최대 100개. Meta가 토큰을 거절했으면 `{ tokenRevision, tokenRejected: true }` | `{ added, closed, replies: { fetchedAt, count, waiting } }`. **가져오기 한 번에 한 번만 부른다.** 같은 `threads_id`는 덮어쓰고(`last_seen_at`, 고친 본문), 새것만 `added`에 센다. 빈 배열도 받는다(조회했으나 0건). `tokenRejected`면 아무것도 저장하지 않고 그 계정의 토큰을 무효로 바꾼다(게시 실패의 190과 같은 처리). 조건: 휴대폰 로그인, 내 글, 원글이 올라갔고 글 번호가 있음 |
| `POST /api/v1/mobile/answers/:id/results` | `{ tokenRevision, outcome: "published"(+threadsId) \| "failed"(+errorCode) \| "unknown" \| "confirmed" }` | 등록본 결과 보고(`reportMobileResult`)와 같은 규칙: `published`는 최종, 그 전에는 덮어씀, 계정 삭제·취소 뒤에도 저장, 190이면 토큰을 무효로. `cancelled`인 답글에 `published`·`confirmed`가 오면 `published`로 바꾼다(실제로 올라갔다) |
| `GET /api/v1/mobile/publications` (기존) | — | 항목에 `replies: { fetchedAt, count, waiting } \| null` 추가. **등록 완료 조건에 "또는 끝나지 않은 답글이 있음" 추가**(결정 9) |
| `GET /api/v1/mobile/publications/:id/replies?cursor=` | — | 저장된 댓글을 작성 시각 최신순으로 20개씩: `{ replies: [{ threadsId, parentThreadsId, parentUsername, username, text, permalink, mediaType, ownedByMe, postedAt }], nextCursor }`. 대댓글도 한 줄로 섞어 보내고 누구의 댓글에 단 것인지(`parentUsername`)를 붙인다. Meta를 부르지 않으므로 브라우저와 옛 앱에서도 된다 |
| `GET /api/v1/mobile/publications/:id` (기존) | — | 위 `replies`와 `answers: [{ id, replyThreadsId, replyUsername, replyText, replyPermalink, text, status, errorCode }]`(끝나지 않은 것만, 작성순) 추가 |

- 요청 본문 한도: 지금은 모든 경로가 16KiB다(`src/server/http/body.ts:14`). 댓글 100개는 본문만으로도 넘는다. `parseJsonBody`에 경로별 한도를 받게 하고 **댓글 저장 경로만 512KiB**로 둔다(구현하며 256KiB에서 올림 — 4바이트 글자 500자 본문과 긴 링크 100건이 256KiB를 넘는다. 이 경로는 로그인을 확인한 뒤에만 본문을 읽는다). 다른 경로는 16KiB 그대로다.
- 모바일 웹은 응답의 모르는 필드를 무시하므로(타입만 있고 엄격 검사 없음) 기존 응답에 필드를 더해도 옛 웹이 깨지지 않는다. PC는 휴대폰용 응답을 읽지 않는다.
- 새 테이블이 없으면 `replies`·`answers`를 빼고 보낸다(웹은 기능을 숨긴다). 웹은 `replies`가 있을 때만 새 경로를 부르므로 새 경로의 503이 휴대폰에 닿지 않는다 — 휴대폰은 503을 받으면 화면 전체를 잠그기 때문에(`App.tsx:283`) 검사에 넣는다.
- **내 답글로 자동 정리**: 댓글을 저장할 때, `unknown` 답글의 대상 댓글 아래에 내가 쓴 글(`ownedByMe`)이 같은 본문으로 있으면 그 답글을 `published`로 바꾸고 번호를 채운다(`closed`에 센다). 답글을 PC에서 보낸 시각 이후에 쓴 글만 맞춘다(시계 차이 1분 허용) — 예전에 Threads 앱에서 같은 말을 직접 단 적이 있어도 그 글로 닫히지 않는다. 직접 [등록 완료]로 바꿔 번호가 없는 답글도 같은 방법으로 번호를 채운다. 사람이 Threads 앱에서 남의 댓글 아래를 찾아 확인하는 일을 줄이고, PC 목록에 같은 답글이 두 줄로 보이지 않게 한다.
- 고유 제약 위반은 지금 모두 "이미 등록되었거나 연결된 계정입니다"로 바뀐다(`threads/service.ts:141-148`). 새 경로는 넣기 전에 직접 확인해 맞는 코드로 답한다.
- **등록 완료 목록의 한계**: 7일의 기준은 올라간 시각이 아니라 PC에서 보낸 시각이다(지금 그대로). 마지막 답글이 올라가면 7일이 지난 글은 탭에서 빠지므로 그 답글에 달린 대댓글은 가져올 수 없다. 7일이 지난 글은 올라간 시각 순서대로 목록 아래쪽에 온다.

### 3.3 PC용 경로

| 경로 | 내용 |
| --- | --- |
| `GET /api/v1/replies?libraryId=daily` | 댓글을 조회했거나 답글이 있는 글의 요약: `{ posts: [{ postKey, publicationId, fetchedAt, count, answers: { queued, failed, unknown } }] }`. PC는 일상 화면을 읽을 때 **이 한 번**만 부른다(글마다 부르지 않는다) |
| `GET /api/v1/publications/:id/replies` | 그 글의 댓글(`owned_by_me` 포함, 최신 500개까지)과 답글 전부: `{ fetchedAt, replies: [...], answers: [{ id, replyThreadsId, text, status, threadsId, errorCode, createdAt, publishedAt }] }` |
| `POST /api/v1/publications/:id/answers` | `{ id, replyThreadsId, text }` → `queued`. 같은 id·같은 내용이면 기존 것을 돌려주고, 같은 id·다른 내용이면 409. 그 댓글에 끝나지 않은 답글이 이미 있으면 409 `ANSWER_PENDING`, 삭제·종료된 등록본이면 409 `PUBLICATION_UNAVAILABLE`(휴대폰 목록에 나오지 않는 글이라 답글을 올릴 수 없다) |
| `POST /api/v1/answers/:id/cancel` | `queued`·`failed` → `cancelled`. 이미 `cancelled`면 그대로 성공으로 답한다(응답을 잃고 다시 보낸 경우). `unknown`·`published`는 409(휴대폰에서 확인해야 한다) |

기존 등록본 응답(`publicSnapshot`)은 그대로 둔다. PC 0.1.12 이하는 새 경로를 모르고 지금처럼 돈다.

## 4. 휴대폰 앱 (threads-mobile-android 0.3.0)

`Protocol.kt`의 읽기 검사에 한 가지를 더한다.

- 경로 `/v1.0/{숫자}/conversation`
- `query`의 항목은 `access_token`(필수), `fields`(필수), `limit`(1~100), `reverse`(`true`·`false`), `after`(쪽 넘김 표시)뿐. `fields`는 `id, text, username, permalink, timestamp, media_type, is_reply_owned_by_me, replied_to, root_post` 중에서만.
- `FEATURES = ["status", "replies"]`. 웹은 `hello`의 `features`에 `replies`가 있을 때만 가져오기를 켠다(지금 `status`와 같은 방식).

`MetaSender`는 바꾸지 않는다(GET 1회, 25초 기한, 응답 1MiB까지 — 댓글 100개는 그 안이다). `/replies` 경로는 쓰지 않으므로 열지 않는다. `versionCode` 3. Play 내부 테스트에 올리는 일은 사용자 승인 뒤에 한다.

## 5. 모바일 웹 (threads-mobile-web)

### 5.1 화면

등록 완료 탭, 일상 글에서만 보인다.

- **카드**: 조회한 글에 뱃지 "댓글 n · 11. 21. 14:02 조회", 끝나지 않은 답글이 있으면 "답글 전송 대기중 (n개)". 카드는 지금처럼 버튼 하나이고 누르면 상세가 열린다.
- **상세**: 원글 아래에 댓글 구역.
  - **[댓글 가져오기]**와 마지막 조회 시각·건수.
  - 댓글이 1건 이상이면 **[댓글 보기 (n)]**. 누르면 댓글 목록이 상세 위에 따로 뜬다(지금 상세·확인창과 같은 방식의 창, 닫으면 상세로 돌아온다). 최신순 한 줄 목록이고 아래 끝에 닿으면 20개씩 더 불러온다(목록 탭의 방식 그대로). 한 건에 `@이름`, 시각, 본문, 대댓글이면 "↳ @이름에게", 우리 계정이 쓴 글이면 "내 답글", 그림·영상이면 "[이미지]"·"[영상]", 그리고 "Threads에서 보기" 링크. 읽기만 한다 — 답글 쓰기와 한국어 뜻은 PC에 있다.
  - 답글이 있으면 목록(`@이름`의 댓글 한 줄 → 답글 본문)과 **[답글 전송 (n개)]**.
  - 거절된 답글에는 사유(Meta 코드)와 **[재등록]**이, 올라갔는지 모르는 답글에는 지금 원글·댓글과 같은 **[재등록]**·**[등록 완료]**와 "Threads에서 댓글 보기"(그 댓글의 링크)가 그 답글에 붙는다. [댓글 가져오기]를 누르면 올라간 답글은 자동으로 정리된다(3.2).
- 누를 수 없는 경우(지금 화면의 방식 그대로):
  - 글 번호가 없는 글(직접 [등록 완료]로 바꾼 글)은 버튼 대신 "글 번호를 받지 못해 댓글을 가져올 수 없습니다."
  - 앱이 0.2.0 이하면 [댓글 가져오기] 자리에 **[앱 업데이트]**(Play 설치 주소, `compat.ts`의 `APP_INSTALL_URLS`)가 온다. 답글 전송은 옛 앱에서도 된다.
  - 브라우저에서는 지금처럼 "글 등록은 앱에서만 됩니다" 안내만 있고 이 구역의 버튼은 없다.

### 5.2 댓글 가져오기

1. `GET /v1.0/{글 번호}/conversation?fields=…&reverse=true&limit=100&access_token=…`
2. 받은 것을 건별로 거른다: `root_post`가 이 글이 아닌 것, 번호·시각이 없는 것은 버린다. 본문은 비어 있어도 받고 500자를 넘으면 자른다. 버린 건수는 끝난 뒤 안내에 보인다. 댓글 한 건의 형식 때문에 전체가 실패하지 않게 한다.
3. 서버에 **한 번** 올린다(`…/replies`). 서버가 새것의 수와 자동 정리한 답글 수를 돌려준다.

- **매번 최신 100개를 읽는다.** 저장은 같은 댓글을 덮어쓰므로 "새것만 더한다"는 결과가 같고, 중간에 실패해도 서버에는 반쪽이 남지 않는다(다 읽은 뒤에만 올린다).
- **쪽 넘김을 넣어 둔다.** Meta 확인이 마지막이라 `limit=100`에 실제로 몇 개가 오는지 모르는 채로 만든다. 100개보다 적게 오고 다음 쪽이 있으면 100개가 될 때까지 이어 읽되 휴대폰에 모아 두었다가 한 번에 올린다. 가져오기 한 번의 Meta 요청은 5번을 넘지 않는다(쪽이 20개씩이어도 100개). 100개가 한 번에 오면 요청은 1번이다. 마지막 확인에서 쪽 크기를 보고 상한을 고친다.
- 읽기 요청이라 휴대폰 기록(전송 전 기록)이 필요 없다. 실패하면 안내만 하고 다시 누르면 된다.
- 지금의 작업 규칙을 그대로 따른다: 한 번에 작업 하나(`task`), 계정 잠금, 화면이 보일 때만(`guard`).
- `Meta`에 읽기 메서드 `conversation`을 더한다. 경로는 코드에 고정하고, 응답은 정해진 항목만 골라 읽는다. 앱에서만 부른다(브라우저는 응답을 읽지 못한다).
- **거절 안내**: Meta가 권한 오류로 거절하면(오류 번호 10 또는 200번대 — 문서 기준, 실제 번호는 확인하지 못했다) "이 계정의 토큰에 댓글 읽기 권한이 없습니다. 토큰 발급 가이드대로 권한 5개로 다시 발급해 PC 프로그램에서 토큰을 교체해 주세요. (Meta 코드 N)". 190은 서버에 알리고(`tokenRejected`) 지금의 토큰 오류 처리를 따른다. 그 밖은 "Meta에서 요청을 거절했습니다 (코드 N)".

### 5.3 답글 순차 전송

[답글 전송]을 누르면 확인창(계정 이름, 답글 n개, 예상 시간)을 거쳐 **대기(`queued`) 답글만** 작성순으로 하나씩 올린다. 답글 하나의 순서는 지금 댓글 등록과 같다.

1. 화면·연결 확인 → 휴대폰에 남은 결과를 서버로 보냄 → 서버에서 그 답글을 다시 읽음(PC에서 취소했으면 건너뜀).
2. 컨테이너 생성: `media_type=TEXT`, `text`, `reply_to_id=그 댓글 번호`. 거절되면 `failed` 보고.
3. Meta 처리 확인(앱) 또는 60초 대기(옛 방식).
4. **게시 직전 기록**(localStorage와 IndexedDB 즉시 기록) → 게시 요청 → 결과 기록 → 서버 보고.
5. 다음 답글까지 **30초**(남은 시간을 보여 준다). 그동안 화면을 켜 둔다(`busy`). 마지막으로 답글을 올린 시각을 휴대폰에 적어 두고, 새 묶음이나 [재등록]도 그 시각에서 30초가 지나야 시작한다(앱을 다시 열어도 같다).

- **거절된 답글은 넘긴다.** Meta가 그 답글을 거절하면(`failed` — 지워진 댓글, 본문 거절처럼 그 답글만의 사유일 수 있다) 사유를 남기고 30초 뒤 다음 답글로 간다. 거절된 답글은 다음 묶음에 다시 끼지 않고, 그 답글의 [재등록]으로 하나씩 다시 올리거나 PC에서 취소한다. 답글 하나가 뒤의 답글을 영영 막지 않는다.
- **멈추는 경우**: 답이 없을 때(`unknown`), 토큰 오류(190), **연속 두 번 거절**(Meta 제한처럼 공통 원인일 수 있다), 화면을 벗어났을 때. 남은 답글은 대기 그대로다.
- **답 없음**: 그 답글만 [재등록]·[등록 완료]·[댓글 가져오기]로 정리한다. 그 글에 `unknown` 답글이 있으면 [답글 전송]을 시작하지 않는다.
- **휴대폰 기록**: 답글 결과는 등록 기록과 **다른 키**에 둔다(localStorage `threads-account-answer-results:…`, IndexedDB는 같은 저장소의 다른 구획). 지금 기록은 `kind`가 `root`·`comment`가 아니면 "실행 기록 형식 오류"로 전체를 못 읽는다(`journal.ts`의 `resultEntries.clean`). 키를 나누면 웹을 이전 이미지로 되돌려도 옛 코드가 답글 기록에 걸리지 않는다. [결과 동기화]와 남은 결과 수는 두 기록을 함께 다룬다.
- `Publisher`에 답글용 실행(`answer`)을 더하고, 생성·처리 확인·게시·보고는 지금 코드를 같이 쓴다.
- **등록 완료 탭의 7일 거르기는 웹에도 있다**(`publication-list.ts:14`, 테스트가 경계를 고정). 서버 조건과 함께 "끝나지 않은 답글이 있으면 남긴다"로 고친다.
- **한계(지금 등록과 같음, 사용자 결정 2026-11-21)**: 서버는 휴대폰이 올리기 시작한 것을 모른다. 휴대폰 두 대가 같은 계정의 같은 답글을 동시에 올리면 두 번 달린다(계정 잠금은 한 휴대폰 안에서만 유효하다, `gate.ts`). 다른 휴대폰의 늦은 결과가 상태를 덮을 수도 있다. 한 계정은 한 휴대폰에서 올린다는 지금 전제를 그대로 둔다.

## 6. PC (threads-media-manager 0.1.13)

### 6.1 화면

- 일상 탭 **등록 완료 카드**에 버튼 **[댓글 n]**이 생긴다(조회한 적이 있는 글만. 0건이면 "댓글 없음 · 조회 시각" 글자만). 답글이 휴대폰에 있으면 "답글 대기 n", 확인이 필요하면 "휴대폰에서 확인 필요"를 함께 보인다. 조회한 적 없는 글은 지금과 같다.
- 버튼을 누르면 **댓글 창**이 열린다(공용 대화상자).
  - 위: 원글 본문, 조회 시각("휴대폰에서 [댓글 가져오기]를 누르면 새 댓글이 들어옵니다").
  - 가운데: 댓글 목록. 원글에 달린 댓글은 최신순, 대댓글은 그 아래에 들여 써서 시간순. 부모 댓글이 저장돼 있지 않은 대댓글(최신 100개에 대댓글만 들어온 경우)은 맨 위 단계에 "대댓글" 표시와 함께 보인다. 한 줄에 `@이름`, 시각, 본문, 한국어 뜻(있으면). 우리 계정이 쓴 글은 "내 답글"로 표시한다. 그림·영상 댓글은 본문 옆에 "[이미지]"·"[영상]"과 Threads 링크.
  - 댓글마다 답글 칸의 상태는 하나다: 없음 → **[답글 쓰기]** / 초안 → 본문과 [수정]·[삭제] / 휴대폰 대기 → [보내기 취소] / 실패 → 사유(Meta 코드)와 [보내기 취소](휴대폰에서 [재등록]할 수도 있다) / 확인 필요 → "휴대폰에서 [재등록] 또는 [등록 완료]" / 올라감 → "내 답글"로 목록에 보임.
  - 아래: **[한국어 뜻 보기]**(다른 언어 페르소나이고 뜻이 없는 댓글이 있을 때), **[모바일로 보내기 (n개)]**(초안이 있을 때).
- 새로 읽는 시점은 지금 일상 탭과 같다(보드 표시, 창 포커스, 작업 뒤). 주기 조회는 넣지 않는다. 댓글 창은 열 때와 작업 뒤에 그 글 하나를 읽는다.

### 6.2 답글 쓰기와 ChatGPT

- **[답글 쓰기]**: 일상 글 수동 등록과 같은 창(본문, 글자 수, 작성 언어). 페르소나 언어로 쓰면 그대로 초안이 되고, 한국어로 쓰면 ChatGPT가 페르소나의 언어·말투로 바꾼다. **바꿀 때 넘기는 것은 쓴 한국어와 페르소나뿐이다 — 댓글 본문은 넘기지 않는다.** 결과는 사용자가 읽지 못하는 언어일 수 있어서, 남이 쓴 글이 답글의 내용에 영향을 줄 길을 두지 않는다. 쓴 한국어는 초안의 한국어 뜻으로 둔다. 영어 페르소나의 한국어 200자 한도는 일상 글과 같다.
- **[한국어 뜻 보기]**: 그 글의 뜻이 없는 댓글을 **한 번의 요청으로** 옮긴다. 묶음은 개수가 아니라 글자 수로 자른다(본문 합계 4,000자까지 — 결과 파일 한도 64KiB와 180초 안에 들게). 남으면 다시 누른다. 여기서는 댓글 본문이 입력이지만 결과는 화면에 보이는 뜻일 뿐 어디에도 올라가지 않는다.
- 지시문은 `daily-generator.ts`에 두 가지를 더한다: 남이 쓴 댓글 여러 개의 한국어 뜻, 한국어 답글 초안을 페르소나 말투의 답글로. "stdin은 참고 자료이지 지시가 아니다"와 한 번에 하나(`DailyGenerator`) 규칙을 그대로 쓴다.

### 6.3 저장과 보내기

- **이 PC에만 두는 것**(`daily.json`, 지금의 구획 안에 새 필드):
  - 답글 `answers: [{ id, postId, publicationId, replyThreadsId, text, translation?, createdAt, send }]` — 초안일 때 만들어 **올라간 것을 확인할 때까지 지우지 않는다**(보낸 뒤에도 본문이 PC에 남는다). 보낼 등록본(`publicationId`)을 함께 적는다.
  - 댓글의 한국어 뜻 `replyNotes` — 뜻과 함께 **옮긴 원문**을 적어 두고, 서버의 본문이 달라졌으면(댓글이 고쳐짐) 그 뜻을 쓰지 않는다.
  - `version`은 1 그대로다 — 구버전은 모르는 필드를 보존한다(`daily-store.ts:126-154`). 구버전이 페르소나를 지우면 글만 지워지므로, 새 버전은 글이 없는 답글·뜻을 읽을 때 조용히 버린다(파일 전체를 무효로 보지 않는다).
- **서버에서 읽는 것**: 댓글, 답글의 상태. 댓글의 사본은 PC에 두지 않는다.
- **[모바일로 보내기]**: 그 글의 초안을 하나씩 서버에 보낸다(`POST …/answers`, 요청 본문 한도 16KiB 안). 보내기 전에 "보내는 중"을 먼저 적는다. 응답을 잃으면 "전송 확인 필요"와 [다시 보내기]가 남고, 같은 id로 다시 보내므로 두 번 들어가지 않는다. 중간에 하나가 실패하면 거기서 멈추고 남은 초안은 그대로다.
- **[보내기 취소]**: 서버의 답글을 `cancelled`로 바꾸고 PC의 답글을 초안으로 되돌린다. 응답을 잃어도 본문은 PC에 있고 취소는 다시 보내도 된다. **되돌린 초안은 새 id를 받는다**(취소된 id로는 다시 보낼 수 없다). 서버가 그 id를 모른다고 답하면(받은 적 없음) 같은 id의 초안으로 되돌린다 — 늦게 도착한 첫 요청과 겹쳐도 한 줄이 되게. 휴대폰이 이미 올리는 중이었다면 올라갈 수 있다(일상 글 취소와 같은 한계) — 그 경우 서버가 취소된 답글을 "올라감"으로 바꾸고, 다음에 읽을 때 PC가 되돌린 초안 옆에 "이미 올라간 답글이 있습니다"를 보인다.
- **페르소나 삭제**: 휴대폰 대기·확인 필요 답글이 있으면 거절한다("답글을 먼저 취소하거나 올려 주세요"). 지금 원글의 휴대폰 대기를 막는 것과 같다(`daily.ts:584`). 삭제하면 그 글들의 초안과 뜻도 지운다.
- 서버 호출은 `ServiceApiClient`에 고정 경로 메서드 `replyRequest`로 더한다(요약·글 하나·답글 저장·취소). IPC는 `tmm:daily:*` 채널로 더하고, 읽기 채널은 수집 글 전송 중에도 되게 `publication-work-gate.ts`에 넣는다.
- 서버에 새 경로가 없으면(404·`MIGRATION_REQUIRED`) 댓글 표시를 조용히 뺀다(페르소나 경로와 같은 처리). 일상 탭의 나머지는 그대로 돈다.

순서: **서버(0011 포함) → 앱 0.3.0(Play 내부 테스트) → 모바일 웹 → PC 0.1.13.** 앱은 서버·웹과 순서가 바뀌어도 된다.

## 8. 수집 글로 넓힐 때

서버의 테이블과 경로는 등록본 번호 기준이라 글의 종류를 가리지 않는다(PC 요약만 `libraryId`를 받는다). 넓힐 때 고칠 곳은 화면 두 군데다: 모바일 웹이 댓글 구역을 일상 글에만 보이는 조건, PC에서 댓글 창을 여는 곳(수집 글은 등록 상세). 수집 글은 등록 번호와 글 번호를 PC가 이미 다른 경로로 다루므로 그때 따로 설계한다. 수집 글에 미리 달아 둔 내 댓글은 조회에 "내 답글"로 섞여 나온다.

## 11. Claude가 판단한 것 (확인해 주실 것)

사용자가 정하지 않아 가장 단순한 쪽으로 잡았다. 바꾸고 싶은 것이 있으면 구현 전에 고친다.

1. **휴대폰의 댓글 목록은 읽기 전용이다**(사용자 결정 12). 대댓글도 들여 쓰지 않고 최신순 한 줄로 보이며, 한국어 뜻은 없다(뜻은 PC의 ChatGPT가 만들고 PC에만 둔다).
2. **PC에서 댓글을 여는 곳**은 등록 완료 카드의 [댓글 n] 버튼 → 창이다. 열(페르소나)마다 "새 댓글" 표시를 따로 두지는 않았다.
3. **댓글 하나에 진행 중인 답글은 하나**다. 올라간 뒤에는 또 쓸 수 있다.
4. **순차 전송은 거절된 답글을 넘기고 계속한다.** 답 없음·토큰 오류·연속 두 번 거절에서 멈춘다(검토 반영).
5. **[한국어 뜻 보기]는 그 글의 댓글을 한 번에**(본문 합계 4,000자까지) 옮긴다. 댓글마다 누르는 방식이 아니다. 버튼은 다른 언어 페르소나에만 둔다(한국어 페르소나의 글에 달린 외국어 댓글은 옮기지 못한다).
6. **답글 초안과 한국어 뜻은 이 PC에만** 둔다(일상 글 초안과 같은 기준). 보낸 답글의 본문도 올라갈 때까지 PC에 남긴다.
7. **PC의 [보내기 취소]는 휴대폰 대기·실패 답글만** 된다. 올라갔는지 모르는 답글은 휴대폰에서 정리한다.
8. **저장하지 않는 것**: 프로필 사진, 좋아요 수(Meta가 주지 않는다), 인증 표시.
9. **그림·영상 댓글**은 본문과 종류 표시, Threads 링크만 보인다(그림을 내려받지 않는다).
10. **서버의 댓글은 지우지 않는다**(사용자 삭제 때만 함께). 등록본도 지금 지우지 않는다.
11. **가져오기는 매번 최신 100개를 읽어 한 번에 저장한다.** Meta 요청은 한 번에 5번까지다(보통 1번).
12. **보내기 취소 뒤에 올라간 글은 댓글을 가져올 수 없다.** 취소된 등록본은 휴대폰 목록과 상세에 나오지 않는다(`mobile/service.ts`의 `ready` 조건). 드문 경우라 그대로 둔다.
13. **올라갔는지 모르는 답글은 [댓글 가져오기]로 자동 정리한다**(대상 댓글 아래에 같은 본문의 내 글이 있으면 올라간 것으로 본다).
14. **답글 변환에는 댓글 본문을 넘기지 않는다**(쓴 한국어와 페르소나만).
