# 다운로드 복구·DB 관리 통합 검증

2026-09-22 Mac 개발 환경에서 수행했다. 임시 합성 라이브러리, 가상 시계·모의 전송, 실제 Electron main/preload/renderer와 Python 실행기를 사용했다. 사용자 수집 Excel·DB·미디어의 다운로드·복원·변경은 하지 않았다.

## 복구·DB 관리 구현 당시 자동 검사

- TypeScript 668개, Python 424개 테스트 통과.
- lint, TypeScript 타입 검사, 코드 format 검사 통과. 문서는 별도 Prettier 검사로 확인했다.
- 기존 편집·삭제·댓글·등록·ZIP·목록 테스트를 함께 실행했다.
- 새로운 복구 테스트는 실제 별도 Python 프로세스의 `os._exit()`로 WAL·잠금·부분 파일을 남기는 경우를 포함한다. 조회 시 원본 바이트 불변, 명시적 재개 시 남은 첨부만 모의 요청, 완료 미디어 UUID·파일·기존 요청·대기 보존을 확인했다.
- 401/403 동일 URL 해시 재요청 차단, Retry-After, 시계 역행, 저장 확정 중 종료, 기존 회차의 잔여분 처리, 새 Excel 게시글 미편입, source/attempt 갱신 트랜잭션 실패 rollback을 확인했다.
- 재개 후 퇴역한 `planned` 기록 때문에 삭제가 막히는 결함을 수정했다. 과거 `.part` 파일은 게시글 삭제 대상에 계속 포함되며 현재 작업만 삭제 차단 조건으로 사용한다.
- 백업에는 WAL의 확정 데이터·재시도 이력·등록·댓글이 포함되고 정상 복원은 최신 운영·삭제 이력을 유지한다. 유실/손상 DB 전체 복원, raw 안전 보관, 잘못된 UUID·스키마·재시도 연결 거부, 동일 폴더 이동과 중단 파일 복구를 검증했다.

## 실제 Electron 연결 확인

별도 userData와 합성 자료를 연결한 개발 앱에서 main→Python→목록 갱신까지 확인했다. 파일 선택·확인 대화상자의 반환값만 테스트 경로로 대체했으며 DB 작업은 실제 실행기를 사용했다.

1. 이동한 합성 라이브러리 재연결 → 완료 파일 목록 복구.
2. DB 백업 저장 → 동일 백업 복원 → 복원 전 자동 백업 생성과 성공 안내.
3. 잘못된 새 Excel 폴더의 조회가 실패해도 설정은 이전 화면의 경로가 아닌 현재 선택 폴더를 표시.
4. 일반 화면과 최소 창 크기 940×650에서 설정 모달의 가로 넘침 없음. 작은 화면은 본문 세로 스크롤.
5. 중단된 합성 배치의 재실행에서 진행 수·이어서 다운로드 버튼 표시. 사용자 중지 버튼과 preload 중지 함수 없음.
6. 네트워크 전송 전 대기 시각을 한 시간 뒤로 둔 합성 배치를 명시적으로 재개. 대기 중 창 닫기·`app.quit()`가 모두 차단되고 다운로드 완료 뒤 종료하라는 안내 표시.
7. 해당 테스트 Electron 프로세스만 강제 종료. 기존 요청 2건이 그대로 2건이며 추가 HTTP 전송 없음. 앱 재실행은 자동 재개하지 않고 중단 상태를 표시.
8. 오류 안내 X로 닫기 → 일반 새로고침 뒤에도 안내가 다시 뜨지 않음. 같은 라이브러리의 읽기 전용 상태 조회는 새 다운로드 결과로 취급하지 않음.

정상 완료 안내의 3초 타이머는 기존 동작을 유지하며 상태 재조회로 다시 시작하지 않는 controller 회귀를 추가했다. 모의 HTTP 성공·오류 검증과 실제 CDN 검증은 구분한다.

## 검증 범위 밖과 다음 단계

실제 컴퓨터 전원 차단, Windows 프로세스/파일시스템·설치·업데이트 검증과 추가 실제 CDN 다운로드는 이번에 수행하지 않았다. Mac의 위 개발·통합 검증 완료가 Windows 배포 준비 완료를 뜻하지 않는다.

DB 유실·손상 후 전체 복원은 백업 이후 요청 이력을 알 수 없어 다운로드를 `database_restored`로 보류한다. 해당 이력 확인·해제 절차는 현재 제공하지 않으며 일반 이어서 다운로드로 우회하지 않는다. 이미지·영상과 Excel은 DB 백업에 포함되지 않는다. [DB 관리](database-maintenance.md)의 복원 의미를 따른다.

다음 기능 단계는 별도 요청에 따른 API 관련 작업이다. 계정 연결·게시글/답글 전송·답글 이미지·미디어 전달·결과 이력·실패 복구를 함께 구현하고, 이후 Windows 실기·배포를 검증한다.

## 최초 폴더 설정 반영 후 GitHub 체크포인트 검사

같은 날 최초 폴더 선택·설정 재연결 개선까지 포함한 소스 복사본에서 Node 24.18.0으로 다음을 다시 실행했다.

- TypeScript 23개 파일의 675개 테스트, Python 428개 테스트 통과(합계 1,103개).
- TypeScript 타입 검사, 전체 lint, 코드 format 검사 통과.
- Vitest는 복사본에서 의존성 캐시를 쓰지 않도록 `--configLoader runner --cache=false`로 실행했다. Python은 프로젝트 가상 환경을 사용했다.
- 폴더 유지관리 테스트에는 최초 미연결 상태, 선택 취소, 새 폴더 연결, 기존 라이브러리 재연결과 실패 시 기존 연결 보존을 포함한다.
- 앞선 실제 앱 확인에서는 상단 폴더 연결 버튼 제거와 기존 선택 폴더·게시글 표시를 확인했다. 이번 체크포인트 검사는 새로운 실제 컴퓨터 이전, 사용자 DB 복원, CDN 다운로드 또는 API 게시를 추가로 수행한 것이 아니다.

공개 업로드 대상은 수정 44개와 신규 31개 소스·문서였다. 실제 자격 증명·개인 절대 경로·서명 URL·사용자 미디어·DB·수집 Excel·임시 산출물이 포함되지 않았는지 점검했다. 테스트용 문자열과 저장소 주소는 구분했으며, 기존 커밋 전체 이력에 대한 보안 감사를 뜻하지 않는다.
