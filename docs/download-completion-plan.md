# 다운로드 복구·라이브러리 관리 구현과 검증

**2026-09-23 수집 자료 정리 정책:** 로컬 앱은 시작·새로고침과 새 다운로드 시작 전에 `cleanup-source`로 `source_not_ready`·`attachment_not_ready`인 불완전 수집 글만 논리적으로 삭제한다. 완전성은 게시글별 캡션·첨부 수집 상태와 실제 첨부·URL 연결로 판단한다. 상위 수집 실행이 중단되거나 `partial`이어도 해당 글이 완전하면 정상 다운로드 대상으로 유지한다. `post_deletions`로 앱 목록·대기 수·후속 계획에서 숨기고 `cleanedPosts`로 정리 수를 안내한다. Excel·수집 기준·원본 해시는 변경하지 않는다. jobs·부분 파일·다운로드 파일·AI 생성본·등록·편집 등 작업 흔적이 하나라도 있으면 정리 대상에서 보호한다. 정상 수집 글의 다운로드 실패·강제 종료는 삭제 사유가 아니며, 기존 완료/부분 파일·계획·요청 이력·대기를 보존하고 명시적으로 이어서 다운로드한다. 수집 플러그인 동작과 설치는 변경하지 않는다. 정리한 불완전 글 수는 `cleanedPosts`, 정상으로 확인해 제외를 해제한 글 수는 `releasedPosts`로 구분한다.

2026-09-22 사용자가 잔여 기능 구현을 승인한 뒤 구현한 다운로드 복구·관리 계약도 유지한다. 다운로드 상태 조회·명시적 재개·동일 라이브러리 재연결·DB 백업과 복원을 구현했으며, Mac 자동 검사와 합성 자료를 사용하는 Electron 통합 검증을 완료했다. 구체적 근거와 한계는 [검증 기록](download-recovery-verification.md)을 따른다. Windows 배포 준비 완료를 뜻하지 않는다. 상세 실행 계약은 [1E 다운로드](phase-1e-download.md)를 따른다.

이번 범위는 로컬 앱의 다운로드와 자료 복구다. API 게시·계정 연결·미디어 전달·게시 이력과 실패 복구는 다음 단계이며 Windows 실제 기능·설치·자동 업데이트·배포 검증도 남아 있다. 영상 비율 크롭은 제외하고 기존 이미지 크롭·영상 프레임 캡처·영상 구간 자르기를 유지한다. 카드와 등록 상세의 ZIP 다운로드는 저장된 파일의 내보내기로, CDN에서 원본을 받는 다운로드와 구분한다.

기존 다운로드 복구·관리는 2026-09-22 controller·Python 회귀와 Electron 통합 검증을 완료했다. 이 기록을 이후 추가한 수집 자료 정리·정상 글 제외 해제의 검증 완료로 간주하지 않는다. 새 기능의 통과 여부는 해당 backend 전체 검사와 실제 확인 범위로 별도 판단한다.

## 2. 상태 조회와 이어서 다운로드

내부 `command: status`는 중단 사유, 게시글·파일·회차 진행, 다음 허용 시각과 복구·재개 가능 여부를 읽는 읽기 전용 명령이다. 비정상 종료로 WAL이나 죽은 다운로드 잠금이 남아도 이 조회는 원본 DB·잠금·부분 파일을 변경하지 않는다. 필요한 DB 복구 조회는 임시 복사본에서 수행한다. 조회만으로 빈 라이브러리에 DB를 만들지 않으며 원격 GET은 0회다.

앱 시작·새로고침과 새 배치 전에는 별도 `cleanup-source`로 작업 없는 불완전 수집 글만 DB에서 논리적으로 삭제하고 일반 상태와 `cleanedPosts`를 받는다. 이 정리도 HTTP 요청이나 파일 삭제를 하지 않는다.

수동 중지 버튼은 제공하지 않는다. 전송·검증·대기 중 정상 창 닫기와 앱 종료는 차단하고 완료 후 종료하도록 안내한다. 강제 종료·프로세스 오류·절전 복귀 등 비정상 중단은 별도로 복구한다. 과거 버전이 남긴 사용자 중지 기록도 재개 가능한 사유인지 검증한다.

`이어서 다운로드`를 명시적으로 누르면 다음 순서로 처리한다.

1. 활성 수집·다운로드·삭제 복구와 충돌하지 않는지 확인한다. 종료가 확인된 다운로드 전용 잠금만 명시적 복구 과정에서 처리하며 수집·활성·소유자 미상 잠금은 해제하지 않는다.
2. 이미 받은 파일을 로컬에서 검증·복구한다. `staged` 파일은 근거가 맞으면 새 GET 없이 완료하고 불완전한 전송은 과거 시도로 보존한다. 로컬 복구만 실행하는 `파일 상태 확인`은 재전송하거나 중단을 해제하지 않는다.
3. 기존 배치·현재 작업 연결·완료 파일·Excel 원본·첨부 종류와 순서·중단 사유·대기를 다시 검증한다. 손상된 완료 파일이나 DB 복원 후 이력 불명 상태는 재개로 우회하지 않는다.
4. 허용된 남은 첨부만 이어서 처리한다. 실패·중단된 전송은 동일 미디어 ID에 새 작업 ID와 새 `.part` 경로를 연결해 처음부터 받는다. HTTP Range 방식의 바이트 이어받기는 제공하지 않는다.
5. 이전 작업·부분 파일·요청·중단 사유·계획 이력은 보존한다. `job_attempts`로 이전 시도와 새 시도를 연결하므로 과거 실패를 완료로 바꾸거나 현재 작업으로 재사용하지 않는다.

첫 재실패도 배치 전체를 중단하며 완료/부분 파일·기존 계획·작업·요청 이력을 보존한다. 실패·부분 저장·미시작 정상 글을 자동 삭제하거나 작업을 완료로 바꾸지 않는다. 앱 재실행·새로고침·시간 경과·새 Excel만으로 재개하거나 자동 재시도하지 않는다. 완료 파일은 URL이나 원본 해시가 달라져도 다시 받지 않는다.

### 불완전 수집 글만 정리하는 경계

`cleanup-source`는 `source_not_ready`·`attachment_not_ready`인 불완전 수집 글 중 기존 작업이 전혀 없는 기록만 `post_deletions`로 논리적으로 삭제한다. 앱 목록·pending·후속 계획에서 제외하지만 Excel·수집 기준·원본 해시는 바꾸지 않는다. 이 수집 기록에는 삭제할 앱 소유 다운로드 파일이 없으며 원격 요청·파일 삭제를 실행하지 않는다.

jobs가 하나라도 있거나 부분 파일·다운로드 파일·AI 생성본·등록·편집 등 작업 흔적이 있으면 나중에 원본이 불완전해져도 보호한다. 기존 `meta.download_exclusions` 중 게시글별 검사로 정상임이 확인된 글은 제외를 해제한다. 여전히 불완전하고 같은 보호 조건을 만족하는 작업 없는 글만 이관한다. 전체 원본 읽기 오류·로컬 무결성 문제·원본 변경·HTTP 실패는 수집 자료 정리로 우회하지 않는다. 수집 플러그인 코드는 변경하지 않는다.

## 3. 수집 Excel 변경 처리

원본 변경은 수집 플러그인의 당일 Excel 갱신·다음 날 파일 추가로도 발생한다. 사용자가 Excel을 직접 수정해야 하는 기능이 아니다. 앱은 플러그인을 호출하거나 새 URL 수집을 자동 실행하지 않는다.

진행 중 원본이 달라지면 다운로드를 중단한다. 이후 사용자가 `이어서 다운로드`를 누르면 최신 원본에서 **기존 배치의 대상만** 다시 검증한다. 별도의 변경 목록 승인·계획 갱신 버튼은 구현하지 않는다.

- 새 Excel이나 캡션 변경은 기존 대상의 연결이 유효하면 수용할 수 있다. 원본 참조·해시·확인 실행·URL 해시를 다시 연결하고 이전 계획을 이력으로 남긴다.
- 계정·게시글 ID·첨부 수·순서·종류가 충돌하거나 기존 대상이 원본에서 사라지면 차단한다. 단순 행 누락을 삭제·완료로 처리하지 않는다.
- 앱의 명시적 게시글 삭제 기록은 제외 근거로 인정하되 이전 계획과 작업 이력은 보존한다.
- 새 게시글로 기존 회차의 하한을 채우지 않는다. 기존 회차의 남은 수가 35개 미만이어도 그 대상을 먼저 끝내고 신규 자료는 후속 명시적 다운로드에서 계획한다.
- 401/403으로 거절된 동일 URL 해시는 재요청하지 않는다. 같은 대상의 새로 수집된 유효 URL이 필요하며 일반 증분 수집이 반드시 URL을 갱신한다고 가정하지 않는다.
- 재검증 이후 전송 전에도 원본 변경을 확인한다. 저장된 대기 시각은 유지하며 재개로 재추첨해 단축하지 않는다.

## 4. 폴더 재연결과 DB 백업·복원

설정은 마지막 정상 목록 대신 main의 현재 연결 폴더를 별도로 조회한다. 목록 조회가 실패해도 표시하는 복구 대상과 실제 작업 대상을 일치시킨다. 다운로드·편집·삭제·등록·댓글·캡션 생성 등 다른 작업과 유지관리를 동시에 실행하지 않는다. 유지관리 완료 후 목록과 다운로드 상태를 다시 읽는다.

### 최초 폴더 지정과 동일 라이브러리 재연결

앱에 기억된 작업 폴더가 없으면 최초 실행 때 폴더 선택창을 자동으로 한 번 연다. 수집 플러그인의 설정은 선택창 기본 위치의 힌트로만 사용한다. 선택한 위치는 다음 실행부터 자동으로 불러오며 상단 폴더 연결 버튼은 표시하지 않는다. 처음 선택을 취소하면 빈 화면의 **설정 열기**에서 다시 선택한다.

수집 폴더 전체를 이동했다면 **설정 → 폴더 재연결**에서 새 위치를 선택한다. 같은 동작 안에서 DB와 `media/.library.json`의 라이브러리 UUID, 상대 경로와 완료 파일을 검증한 뒤 DB 루트 경로를 갱신하고 앱의 연결 위치를 기억한다. 별도의 사전 연결은 필요하지 않으며 선택 취소·검증 실패는 기존 연결을 유지한다. 미완료 작업·부분 파일·요청 이력·대기·중단은 그대로 남기며 필요한 다운로드 복구는 이후 별도 동작으로 처리한다.

DB가 없는 첫 폴더는 연결만 하며 DB나 미디어 식별 파일을 자동 생성하지 않는다. 복원이 필요한 기존 자료 폴더도 먼저 선택한 뒤 같은 설정에서 DB 복원을 진행할 수 있다. 세부 계약은 [DB 관리](database-maintenance.md)를 따른다.

앱이 폴더를 자동 이동하거나 미디어만 다른 위치에 분리하지 않는다. 다른 UUID·누락 또는 변경된 완료 파일·활성 잠금을 새 DB 생성으로 우회하지 않는다. 재연결은 누락된 Excel을 복원하지 않으며 새 다운로드에는 검증된 원본이 필요하다.

### DB 백업

설정의 `DB 백업`에서 저장 위치를 선택하면 현재 DB의 일관된 SQLite 백업을 `.sqlite`로 저장한다. 다운로드·요청·편집본·삭제·시도 연결·등록·댓글 등 DB 정보와 백업 식별 정보를 포함한다. **실제 이미지·영상·수집 Excel은 포함하지 않으므로 수집 폴더도 별도로 보관해야 한다.**

### DB 복원

백업 파일 선택과 사용자 확인 후 같은 라이브러리의 유효한 백업인지 검사한다. 다른 앱·다른 라이브러리·지원하지 않는 DB는 덮어쓰지 않는다.

| 현재 DB 상태   | 복원 동작                                                                                                                   | 다운로드 상태                                                                       |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 정상           | 현재 DB를 먼저 자동 백업하고 등록·댓글 정보를 백업 시점으로 복원. 현재 다운로드·요청·대기·중단·삭제·편집본·시도 이력은 보존 | 기존 운영 상태 유지. 복원만으로 재개하지 않음                                       |
| 유실 또는 손상 | 백업의 전체 DB 상태로 복원. 손상 DB가 있으면 원본과 sidecar를 별도 보관하며, 없는 DB는 보관할 파일이 없음                   | 백업 이후 이력을 알 수 없으므로 `database_restored` 중단과 이력 확인 필요 상태 설정 |

자동 보관 위치는 수집 루트의 `state/backups/`이며 완료 안내에 표시한다. 정상 복원은 현재 삭제 기록을 되돌려 게시글·편집본을 되살리지 않는다. 전체 복원도 필요한 로컬 파일을 검증하지만 백업 이후 이력을 추정할 수는 없다. `database_restored`는 일반 이어서 다운로드나 파일 상태 확인으로 해제하지 않는다. 이력 확인과 해제 절차까지 포함한 완전한 재해 복구 완료로 간주하지 않는다.

## 5. 유지하는 실행 정책

- 계정명 순서, 계정 안 오래된 게시글 순서, 첨부 순서를 고정한다. 같은 계정의 남은 첨부 35–45개를 게시글 단위로 묶고 마지막 작은 회차를 허용한다.
- 파일 완료 후 3–10초, 회차 후 60–120초, 계정 후 10–30초와 서버 대기를 적용한다. 겹친 조건 중 가장 늦은 허용 시각을 따르고 마지막 회차·계정의 대기도 다음 실행에 남긴다.
- 무응답 30초·파일 시도 총 600초, 시각 역행 검사, redirect·호스트·파일 검증, 첫 오류 전체 중단을 유지한다. 일일 횟수 상한은 없다.
- 다운로드·복구·백업·재연결은 수집 Excel과 수집 기준을 변경하지 않는다. 사용자가 승인한 게시글 삭제의 Excel 삭제 표시는 별도 계약이다.
- 수집 플러그인은 다운로드 DB를 읽거나 쓰지 않는다. 앱 오류 기록은 이후 별도로 요청된 수집을 자동 금지하지 않는다.

## 6. 검증 항목과 남은 확인

합성 라이브러리·가상 시계·모의 전송 및 main의 모의 프로세스·네이티브 대화상자로 다음 회귀 항목을 검증한다. 실제 사용자 자료의 재수집·추가 CDN 다운로드를 검증 근거로 사용하지 않는다.

| 영역        | 핵심 검증 항목                                                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 상태 조회   | 빈 폴더에서 DB 생성 없음, 비정상 종료 WAL·잠금·부분 파일 바이트 보존, GET 0, 중단·대기·회차 표시                                                |
| 수집 정리   | 두 준비 불가 코드·작업 없는 글만 post_deletions, 멱등성·legacy exclusions 이관, cleanedPosts, Excel 해시 불변, jobs/부분/다운로드/AI/등록/편집 보호. 중단/partial 실행의 완전한 글 유지·정상 글의 과거 제외 해제 |
| 명시적 재개 | 완료 파일 재요청 0, staged 로컬 복구, 새 시도와 과거 부분 파일·요청 보존, 반복 실패 이력 연결, 첫 오류 이후 추가 GET 0                          |
| 원본 변경   | 새 Excel·메타데이터·URL 변경 수용 범위, 새 게시글 미편입, 첨부 충돌·기존 대상 누락 차단, 삭제 기록 유지                                         |
| 대기·오류   | 401/403 동일 해시 차단, Retry-After 보존, 시각 역행 차단, 작은 잔여 회차와 기존 경계 대기 유지, DB 복원 보류 우회 차단                          |
| 라이브러리  | 같은 UUID 이동·재연결, 완료 파일 손상·다른 UUID 거절, 죽은 다운로드 잠금과 수집 잠금 구분                                                       |
| 백업·복원   | WAL의 확정 데이터와 모든 테이블 백업, 정상 DB의 운영 이력 보존, 삭제된 자료 비복원, 손상·유실 DB의 전체 복원 보류, 자동 보관과 실패 시 rollback |
| Electron    | 중복 실행·다른 작업 busy 차단, 대화상자 취소, 유지관리 종료 대기, receipt·경로·출력·timeout 검증, 목록 읽기 실패 시 설정의 현재 루트 접근       |

Mac Electron 합성 자료 화면에서 정상 종료 차단, 이어서 다운로드 표시, 대기 토스트, 오류 닫기·새로고침 유지, 설정 경로·실제 DB 백업/복원·결과 반영을 확인했다. 상세 검증 범위는 검증 기록을 따른다. 단위 검증의 통과를 화면·배포 검증 완료로 해석하지 않는다. API 관련 작업과 Windows 실기·설치·자동 업데이트 검증은 이후 범위다.

주요 구현은 `local-runtime/threads_runner/{attempts,batch,recovery,resume}.py`, `download_ui.py`, `library_maintenance.py`, `src/main/{download,library-maintenance,index}.ts`와 renderer의 다운로드 토스트·설정 연결이다. 관련 회귀는 `tests/test_download_resume.py`, `tests/test_library_maintenance.py`, main의 download·library-maintenance 테스트와 기존 다운로드·자료 관리 테스트에서 유지한다.
