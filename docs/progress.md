# 구현 진행 기록

## 2026-09-21 — 1A 플러그인부터 시작

사용자 결정: Electron보다 플러그인을 먼저 만든다. 이번 단위는 `threads-collector` 0.1.0의 수집 전용 패키지와 설치 확인 경로다. 실제 수집, CDN 요청, 다운로드 실행기, DB, Electron 구현, GitHub 공개는 수행하지 않는다.

패키지 형식 검증은 실제 수집 성공의 증거가 아니다. 설치 점검 스킬은 탭을 열거나 로그인 상태를 조사하지 않으며, 필요한 도구가 노출되는지만 보고한다. 기존 스킬과 구분되는 수집 명령은 `$threads-collect`다.

다음 확인은 Mac의 새 대화에서 설치된 스킬의 로드와 초기 설정을 검증하는 것이다. 아래 플랫폼 기준 변경에 따라 1A 개발 완료는 Mac 검증으로 판단하며 Windows 미확인은 최종 1G에서 확인한다. 사내 배포 준비 완료에는 Windows 최종 검증이 필요하다.

## 2026-09-21 — 1A 초기 설정 통합

사용자 결정: 설치 확인을 초기 설정에 포함하고, 계정을 등록한 뒤 별도로 수집을 시작한다. 이후 수집에서는 점검 명령과 폴더 지정을 매번 요구하지 않는다.

- `$threads-setup` 추가: 설치/필수 도구 점검, 수집 폴더 한 번 선택, 빈 양식 준비 또는 기존 계정 파일 보존, 위치 기억, 계정 입력·Threads 로그인 안내. 초기 설정으로 수집을 시작하지 않는다.
- Python 표준 라이브러리 helper 추가: 사용자 홈의 `.threads-media-manager/settings.json`에 `schema_version`과 `collection_root`만 보관한다. status는 읽기 전용이다. 실제 멤버의 설정은 이번 개발 작업에서 생성하지 않았다.
- 기존 설정·계정 파일의 덮어쓰기 금지, 잠금/손상/폴더 누락/자료 복구 필요 구분, 부분 생성 후 재실행을 검증했다. 계정 양식은 열 이름으로 읽어 재정렬과 추가 열을 보존한다.
- 스킬의 6개 사용자 상황을 독립적으로 검토했다. `초기 설정 완료`, `계정 입력`, `로그인 확인`, `수집 가능`을 구분한다.
- 격리 테스트 **24개 통과**. 한글/공백 경로, 읽기 전용 status, 반복 실행 byte·mtime 불변, 동시 잠금·파일 충돌, 저장 실패/재개, 다른 플러그인 내부 저장 차단, ASCII 출력 환경의 Unicode JSON 보존을 포함한다.
- 실제 배포 accounts.xlsx로 임시 폴더에서 CLI 초기화·반복·상태 조회를 검증했다. 실제 사용자 Excel, Threads 브라우저, CDN에는 접근하지 않았다.

재현 명령은 프로젝트 루트에서 Codex가 제공한 Python으로 `python -B -m unittest discover -s tests -v`다. 멤버에게 실행시키는 설치 절차가 아니다. helper는 로컬 파일시스템의 원자적 hard link 생성을 사용하며 미지원 환경에서는 중단한다. Excel 잠금 표식 검사는 파일 닫기를 대신하지 않는다.

로컬 Codex에 `0.1.0+codex.20260921042152`를 재설치해 installed/enabled=true를 확인했고, 설치 캐시 14파일과 소스의 SHA-256이 일치했다. 기존 단독 수집 스킬 6파일도 변경되지 않았다. 새 대화의 스킬 로드, Windows 실행/설치, 실제 사용자 초기 설정은 여전히 미검증이다. 다운로드 실행기·상태 DB·Electron 앱·Windows 설치 및 업데이트 도우미는 이번 작업에 포함하지 않는다.

## 2026-09-21 — Mac 개발 / Windows 최종 배포 검증

사용자 기준을 반영해 플러그인·공용 실행기·Electron 기능은 양쪽 OS를 지원하되 개발과 단계별 테스트는 Mac에서 수행한다. Mac은 개발 환경 직접 실행용이며 설치 파일을 배포하지 않는다. 1A–1F의 Mac 완료 기준을 통과하면 다음 단위로 진행하고, Windows 실제 환경 검증은 구현 완료 뒤 최종 1G로 모은다.

Windows에서는 전체 기능과 런타임·파일 경로·잠금·설치·자동 업데이트·데이터 보존을 확인한 후 배포한다. 이전 Windows 미검증 기록은 그대로 유지하며 앞선 개발 단계를 막는 조건으로 쓰지 않는다. 이번 작업은 문서의 진행 기준만 수정했으며 기존 검증 결과를 성공으로 바꾸거나 코드·설치 패키지를 변경하지 않았다.

## 2026-09-21 — 실제 초기 설정과 예제 계정 안내

Mac에서 사용자가 지정한 저장 폴더로 helper 초기 설정을 실행하고 status의 prepared, 계정 양식 형식, results/backups/_work 준비를 확인했다. 이번 실행은 설치 캐시의 스킬을 직접 읽어 수행했으며 새 대화의 자동 로드 성공을 뜻하지 않는다. 계정 등록·로그인·수집은 수행하지 않았다.

사용자 요청에 따라 배포 계정 양식과 방금 생성한 사용자 양식의 7행에 `Y / sample / https://www.threads.com/@sample` 예제를 넣고 상단에 삭제·실제 계정 등록 안내를 추가했다. 초기 설정 완료 안내도 예제 삭제를 포함하며, 수집 지침은 활성 sample 행이 남아 있으면 브라우저 호출 전에 전체 실행을 중단한다. 반복 초기 설정·업데이트는 기존 사용자 양식에 예제를 삽입하지 않는다.

검증: 예제 3셀과 안내 1셀만 변경, 모든 스타일·열 너비·틀 고정·입력 검증 등 보존, 렌더링 확인. 기존 helper 테스트 24개 통과. 새 양식으로 최초 설정 시 예제 복사, 반복 설정 byte·mtime 보존, 기존 빈 양식 연결 시 예제 미삽입을 격리 환경에서 확인했다. 수집·CDN 요청은 실행하지 않았다.

로컬 플러그인을 `0.1.0+codex.20260921045128`로 갱신했다. 설치 캐시 14파일과 소스의 SHA-256, 사용자 양식과 배포 양식 byte 일치를 확인했으며 저장 폴더 설정은 유지됐다. 새 대화에서 갱신 스킬을 자동으로 불러오는 동작은 별도 확인 대상이다.

## 2026-09-21 — 수집 중 Excel 저장 제거와 DOM 관찰 주기 검토

Mac 실제 수집 1회에서 최초 DOM 카드 5개(미디어 원글 2개, 텍스트 원글 1개, 후속 답글 2개), 12회 이동으로 미디어 원글 8개를 확보했다. 10분 탐색 상한으로 partial 종료했고 기준 ID는 유지했다. 이미지 15개·영상 1개는 URL 후보이며 다운로드하지 않았다.

신규 DOM 카드 등장 이동은 1·3·5·6·8·9·12회였고 각각 2·2·2·2·2·2·3개였다. 간격 평균 1.71회, 적격 미디어 원글 추가 간격 평균은 2회다. 기존 5~~20초 대기와 Excel 중간 저장이 포함된 단일 표본이며 서버 페이지 크기나 새 3~~8초 설정의 평균을 검증한 값이 아니다. 4→5회 이동에서는 DOM 카드 수가 9개로 같아도 기존 2개 제거·신규 2개 추가가 관찰됐다. 따라서 카드 총수만 비교하거나 3~5회 이동을 무조건 건너뛰는 방식은 채택하지 않았다.

사용자 요청에 따라 수집 중에는 계정별 append-only JSONL에 여러 게시글·첨부를 묶어 기록하고, 계정 종료·중단 후 Excel을 한 번 내보내 검증·반영하도록 변경했다. 목표 미달 중단도 확보 자료를 partial로 정리한다. 대기는 3~~8초로 변경하고 이동 30~~70%, 계정 간 15~60초, 탐색 상한 30회/10분은 유지했다. 수집 중 매 화면 Excel running 저장을 제거하고 JSONL 미완료·부분 마지막 줄·Excel 반영 중 중단의 복구 순서를 정리했다.

DOM의 ID·준비 상태 비교와 새 카드/미완료 카드 추출은 가능한 한 한 번의 읽기 호출로 합친다. 과거 임시 실행 코드에서 본 ID를 전부 제외했던 한계를 반영하여 seen/pending을 분리했다. 이는 갱신된 실행 지침이며 새 조건의 실수집 성능·누락 여부는 아직 재검증하지 않았다. 이번 변경 과정에서 브라우저·CDN 접근이나 사용자 Excel 수정은 하지 않았다.

검증: JSONL helper 15개와 기존 초기 설정 24개, 총 **39개 오프라인 테스트 통과**. 스킬·플러그인 형식 검증 및 독립 복구 검토를 완료했다. 로컬 플러그인을 `0.1.0+codex.20260921052750`로 재설치했고 installed/enabled=true와 설치 캐시 16파일의 소스 SHA-256 일치를 확인했다. 새 대화 자동 로드·3~8초 조건의 실제 수집·Windows 실행은 별도 미검증이다.

## 2026-09-21 — 계정당 이동 상한 조정

사용자의 이동 상한 확대 요청에 따라 기본값을 30회에서 40회로 조정했다. 10분 탐색 상한과 최초10·증분20 목표, 3~8초 대기 및 JSONL 후처리 방식은 유지한다. 40회와 10분 중 먼저 도달하는 조건에서 partial로 종료한다. 이번 조정으로 실수집을 다시 실행하지 않았다.

## 2026-09-21 — 이동 거리와 대기 범위 조정

사용자 요청으로 이동 거리를 스크롤 영역 높이의 매회 무작위 50~~80%, 이동 전 대기를 매회 무작위 2~~5초로 변경했다. 운영 기본값과 실제 수집 절차의 숫자를 함께 변경했다. 40회/10분 탐색 상한·로딩 중 연속 이동 금지·제한 신호 중단 및 JSONL 후처리 계약은 그대로다. 이번 변경은 설정 갱신이며 새 조건으로 브라우저 수집을 실행하지 않았다.

## 2026-09-21 — 처리 시간을 포함한 최소 이동 간격

사용자 결정에 따라 이동 전 추가 대기 2~~5초를 폐기하고, 직전 이동 호출 시작부터 다음 이동 호출 시작까지 최소 목표 간격을 구간마다 무작위 2~~8초로 정한다. DOM 확인·JSONL 저장·도구 처리 시간이 목표 이상이면 추가 대기하지 않고, 부족하면 차이만 기다린다. 첫 이동은 초기 로딩 완료 기준이다. 단조시계로 경과를 계산하고 목표는 같은 구간에서 재추첨하지 않는다. 로딩 대기·중단 조건과 탐색 상한을 이동 직전에 다시 확인한다.

50~80% 이동은 유지한다. JSONL 계약에서 목표 간격·추가 대기 실측·실제 이동 간격을 구분했다. 이번 변경은 실행 지침/기록 계약 갱신이며 실제 브라우저 수집은 실행하지 않았다.

## 2026-09-21 — 계정 전환과 다운로드 초기 운영값 조정

사용자 요청으로 수집 플러그인의 계정 후처리 완료 후 대기를 무작위 10–30초로 변경했다. 수집 스크롤은 기존 50–80% 이동과 처리 시간 포함 최소 간격 2–8초를 유지한다.

다운로드 설계는 파일 하나씩 순차 처리하고 저장·검증 완료 후 3–10초를 추가 대기한다. 회차는 같은 계정의 남은 첨부 35–45개에 맞춘 온전한 게시글 묶음이며 회차 종료 후 무작위 1–2분을 쉰다. 마지막 잔여 묶음은 35개 미만을 허용한다. 회차·계정·서버 대기가 겹치면 가장 늦은 허용 시각을 적용하며 첫 오류 전체 중단과 성공 파일 보존은 유지한다. 모든 활성 설계의 예시 계산도 새 범위에 맞췄다.

회차 수량을 줄였지만 대기도 짧아져 요청 속도가 더 빨라질 수 있다. 쿠키를 보내지 않는 CDN GET이라는 이유로 IP 차단만 가능하거나 차단 확률이 낮다고 단정하지 않는다. 다운로드 실행기·실제 CDN 요청은 이번 변경에 포함하지 않으며 누적 요청 예산은 실행기 구현 전에 확정할 잔여 항목이다.

검증: 변경한 두 스킬과 플러그인 형식 검증 통과. 독립 검토에서 새 수치·묶음 예시·마지막 잔여분·중첩 대기·기존 중단/복구 규칙의 일관성을 확인했다. 실행 코드와 사용자 Excel은 변경하지 않았고 새 수치의 실제 수집·다운로드 검증은 수행하지 않았다.

## 2026-09-21 — 1D 앱 다운로드 최소 연결

Electron Main이 로컬 Python worker를 소유하고 좁은 IPC로 다음 파일 확인·다운로드·진행률·중지·로컬 저장 복구를 제공한다. 준비 단계는 DB를 초기화하거나 네트워크에 연결하지 않는다. 시작 시 Excel 해시와 같은 대상을 다시 확인하며 완료 후 목록/로컬 이미지가 갱신된다. 앱 종료는 worker 취소와 종료를 기다리고 중복 클릭·활성 다운로드 중 폴더/원본 변경을 차단한다. 원문·서명 URL·private plan은 renderer/DB에 복제하지 않는다.

기존 one-file-pilot-v1과 소비 기록을 보존한다. 첫 오류 중단·예산·대기·UUID를 유지하고 로컬 복구는 staged 확정 또는 interrupted 기록만 한다. 죽은 download-runner 소유 잠금만 명시적으로 검증하여 복구하며 수집/활성/불명 잠금은 유지한다.

pnpm check: TypeScript31개·Python182개, lint/typecheck/format 통과. 실제 Python 강제 종료로 남긴 WAL·잠금을 네트워크 없이 복구하고 소비1회·중단을 유지했다. Mac Electron의 네트워크 차단 모의 전송으로 준비 → 시작 → 진행률 → 저장1/2 → 640px 로컬 이미지 표시를 확인했다. 빠른 중복 클릭에도 작업1개·모의 요청1회, renderer 예외0·원격 요청0이다.

사용자 자료에서 게시글10건·첨부20개·기존 JPEG1개를 읽고 다음 첨부/요청1/1/시작 비활성화/다음 가능 시각을 확인했다. 기존 사용자12파일 SHA-256 불변, 실제 추가 GET/HEAD0·수집0·정책 이관0이다. 개발용 상한에 이미 도달했으므로 추가 실물 검증은 명시적 한도 변경 범위 확정 뒤 수행한다. 1E 회차와1G Windows 실제 기능·설치·업데이트는 후속이다. [1D 상세](phase-1d-download.md).

## 2026-09-21 — 개발용24시간1회 상한 제거

사용자 지시로 다운로드의 일일 횟수 제한을 제거했다. 다른 일일 상한으로 대체하지 않는다. 요청 수에 따른 차단과 잔여량 UI를 삭제했으며 파일 사이 대기·redirect0회·첫 오류 중단·요청 기록은 유지한다. local-download-v2의 첫 쓰기는 알려진 기존 정책 메타데이터와 이관 기록만 한 트랜잭션으로 변경한다. 기존 요청·작업·UUID·중단·대기·기타 메타데이터를 보존하며 알 수 없는 정책은 자동 교체하지 않는다.

pnpm check: TypeScript31개·Python185개, lint/typecheck/format 통과. 같은24시간 안의 두 번째 파일 성공, 짧은 파일 사이 대기, 기존 정책의 읽기 전용 준비, 기록·중단 보존 이관, 이관 중 저장 실패 시 rollback을 검증했다. 실제 추가 다운로드 결과는 후속 기록에 남긴다.

## 2026-09-21 — 현재 수집 자료 전체 다운로드 완료
