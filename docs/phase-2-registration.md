# Phase 2: 게시글 등록

**2026-09-22 추가 시험:** API 연동 전에 원본 이미지와 캡션을 활용한 제품 홍보 이미지·Threads 캡션 생성을 구현한다. 제품명이 없는 입력을 기본으로 처리하며 상세 왼쪽의 AI 생성에서 별도 로컬 초안을 만든다. 기존 등록의 AI 캡션 기능과 구분한다. [AI 생성 계약](ai-content-generation.md)을 따른다.

2026-09-22 사용자 요청으로 원글당 한 개의 로컬 등록·조회·수정과 AI 캡션을 구현했다. 이후 다운로드 복구·재개, 폴더 재연결과 DB 백업·복원도 구현했다. 현재 등록은 실제 게시 전의 로컬 준비 상태이며 Threads 게시·답글 이미지 등록을 포함한 API 연동은 다음 단계다. Windows 실제 기능·설치·자동 업데이트·배포 검증은 그 이후에 진행한다.

## 화면과 저장

- 게시글 상세의 편집 오른쪽에 작성 버튼을 둔다. 이미 작성한 원글은 눈 아이콘과 보기 버튼으로 연다. 저장한 게시글 카드에는 다운로드 아이콘 오른쪽의 세로 구분선 뒤에 녹색 등록 배지를 표시한다.
- 등록 폼 상단은 같은 원글의 원본·편집본을 작은 가로 캐러셀로 표시한다. 개발 실행에서는 저장된 AI 생성본을 편집본 뒤에 추가해 원본→편집본→AI 생성본 순서로 선택할 수 있다. 각 AI 버전의 선택 ID는 재생성 뒤에도 유지하며 등록·재조회·캡션 입력·등록 ZIP에서 같은 파일을 사용한다. 클릭한 미디어는 아래 선택 영역에 추가하며 다시 누르면 선택을 해제한다. 각 썸네일 아래에는 왼쪽에 전체 미디어 기준 순번(`1/3`), 오른쪽에 원본/편집본/AI 생성본을 표시한다. AI 이미지 기능은 개발 실행 전용이며 배포 앱에는 생성 버튼과 AI 후보를 표시하지 않는다.
- 선택 영역은 캐러셀 미리보기와 순서 썸네일을 제공한다. 드래그 또는 앞/뒤 이동 버튼으로 순서를 바꾸고 선택을 해제할 수 있다.
- 원본 캡션은 읽기 전용으로 표시하고, 별도의 등록 캡션 입력란에서 직접 작성한다. 신규 등록 캡션은 빈 값으로 시작하며 수정 시에는 저장한 등록 캡션을 불러온다. 미디어 한 개 이상이 필요하며 등록 캡션은 비워 둘 수 있다. 로컬 입력 상한은 미디어100개·캡션10,000 UTF-16자이며 향후 API 한도를 뜻하지 않는다.
- 등록하면 원글당 한 개를 SQLite `post_drafts`에 저장한다. 등록한 게시글 목록에서 조회·수정한다. 해당 목록의 날짜 필터·정렬은 최근 수정 시각을 기준으로 한다.
- 수정은 revision 비교 후 적용한다. 다른 실행에서 바뀐 내용을 덮어쓰지 않는다. 기존 미디어 ID·순서를 그대로 참조하고 원본 파일이나 Excel 캡션을 변경하지 않는다.
- 등록한 게시글에서 사용 중인 편집본은 선택을 해제하고 저장한 다음 삭제할 수 있다. 원글 전체 삭제를 확인하면 등록 내용도 함께 삭제한다. 외부에서 파일이 사라지면 참조를 조용히 빼지 않고 누락으로 보여준다.

## 작성한 게시글 삭제와 다운로드

- 등록한 게시글 카드 하단은 원본 카드처럼 왼쪽 삭제·오른쪽 ZIP 다운로드 아이콘을 표시한다. 카드 본문이나 미디어를 누르면 조회·수정 화면을 연다.
- 삭제는 네이티브 확인창에서 승인한 뒤 해당 원글의 `post_drafts` 행만 삭제한다. 원본 게시글, 원본·편집본 파일, Excel, 다운로드 요청·중단 이력은 보존한다. 참조 파일이 없어도 작성 내용은 삭제할 수 있으며, revision이 변경되었으면 삭제를 중단한다.
- ZIP 이름은 `게시글ID.zip`이며 작성한 게시글에 선택한 미디어만 지정한 순서대로 `01`, `02` 등으로 저장한다. `게시글정보.txt`에는 계정명·수집일·원문 주소와 작성한 캡션을 넣는다. 미디어 누락·변경 또는 draft revision 변경 시 불완전한 ZIP을 만들지 않는다.
- 작성 내용 삭제 후 원본 카드의 녹색 등록 배지가 사라지며, 원본 상세에서 다시 작성할 수 있다.

## 상세 화면과 댓글 정보

- 수집 상세에는 원문 주소 다음에 수집·파일 정보를 기본으로 펼쳐 표시한다. 댓글 입력은 등록 게시글 상세에서 제공한다.
- 등록 상세의 캡션 아래에 댓글 정보 영역을 두고 캡션·링크를 저장하거나 수정한다. 기존에 입력한 댓글은 같은 원글의 등록 상세에서 그대로 표시하며 링크는 외부 브라우저로 연다.
- 댓글은 정상 등록 내용이 있는 게시글에 저장한다. 원본 미디어 일부가 누락되어도 댓글을 작성할 수 있다. 등록 내용 삭제·재등록 후에도 기존 댓글을 보존한다.
- 등록 상세 하단 왼쪽은 `삭제 | 닫기 수정`, 오른쪽은 `다운로드 API 업로드` 순서다. 삭제·다운로드는 기존 등록 게시글의 확인 삭제·ZIP 내보내기를 사용한다. API 업로드는 준비 중인 비활성 버튼이며 실제 게시 기능을 실행하지 않는다.
- 댓글 작성 중 닫기를 누르면 입력을 버릴지 확인하며, 저장 중에는 중복 작업을 막는다. 게시글 자체의 수정은 댓글 입력을 저장하거나 취소한 뒤 진행한다.

## AI 캡션

앱의 AI 캡션 생성 버튼이 Electron main에서 로컬 `codex exec`를 호출한다. Codex CLI 설치와 해당 사용자의 로그인이 필요하며 API 키를 앱이나 저장소에 넣지 않는다. CLI의 기본 모델을 사용한다. 출력 언어는 영어가 기본이며 한국어·일본어를 선택할 수 있다. 원본 언어와 관계없이 선택한 언어로, 원본 주제·사실을 유지하면서 다른 표현의 캡션을 요청하고, 한 번 요청할 때 서로 다른 캡션 세 개를 제안하며, 사용자가 하나를 선택하면 등록 캡션에 적용한다. 적용 후에도 직접 수정할 수 있다. 생성 응답 자체는 작성 중인 등록 캡션을 덮어쓰지 않는다. 성공만으로 자동 등록하거나 게시하지 않는다.

원본 캡션의 의미·말투·흐름을 우선해 유사한 표현 세 개를 만들며, 선택한 이미지는 원본 캡션을 이해하기 위한 보조 자료로만 사용한다. 모든 출력 언어에 공통으로 Threads에 올릴 자연스러운 구어체를 사용하고, 원본 캡션에 없는 질문·구매 유도·과장을 추가하지 않도록 지시한다. 이미지 때문에 주제나 관점을 바꾸거나 새로운 사실·주장을 추가하지 않도록 지시한다.

AI 영역 박스 바깥 상단에 AI 캡션 라벨, 언어 선택, 생성 버튼을 둔다. 안내박스 자체에는 클릭 기능이 없다. 생성 결과는 기존처럼 박스 안의 제안 세 개로 표시한다. 각 제안 제목 오른쪽의 작은 선택 버튼으로 등록 캡션에 적용하며 선택됨을 다시 누르면 선택과 입력란을 비운다. 생성 버튼은 결과가 있어도 다시 누를 수 있다. 새 생성 요청 시 이전 제안을 즉시 비우고 선택한 언어로 세 개를 다시 요청한다. 직접 작성하거나 이전 제안으로 적용한 입력란은 재생성으로 자동 변경하지 않는다. 최신 제안과 요청 언어는 앱 실행 중 수집 폴더·원글별로 메모리에 보관하며, 모달을 다시 여는 것만으로 새로 생성하지 않는다. 실패·취소한 생성에서 이전 제안을 복원하지 않으며 재시도할 수 있다. 제안 자체는 DB에 저장하지 않으며 앱을 완전히 종료하면 초기화된다. 사용자가 등록한 캡션의 SQLite 저장은 기존대로 유지한다.

선택한 이미지가 없거나 영상만 선택하면 AI 생성은 비활성화된다. 영상과 이미지를 함께 선택해도 이미지만 전달하며 영상 프레임을 추출하지 않는다. 사용자가 캡처해 저장한 이미지 편집본은 이미지로 선택할 수 있다. 앱의 생성 입력 상한은 이미지20개이며 선택한 영상 수는 이 한도에 포함하지 않는다. 이미지를 자동으로 일부 생략하지 않는다. 임시 이미지의 크기와 총 용량을 제한하고 이미지 메타데이터를 제거한다. 원문 URL·SQLite·전체 수집 폴더를 전달하지 않는다.

프로세스는 격리 임시 작업 폴더·읽기 전용 sandbox·ephemeral 모드에서 실행하고 불필요한 도구를 끈다. 셸 문자열로 사용자 입력을 실행하지 않고 프롬프트는 stdin으로 전달한다. 시간 제한·출력 상한·중지·앱 종료 후 프로세스/임시 파일 정리를 제공한다. 설치·로그인·모델/이미지 지원 또는 실행 실패는 캡션 영역에 표시하고 기존 작성 내용을 보존한다.

CLI 기능 근거: [OpenAI 비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [CLI 명령](https://learn.chatgpt.com/docs/developer-commands?surface=cli). 설치된 CLI 0.155.1의 `exec --help`에서 이미지·JSON schema·ephemeral·읽기 전용 옵션을 확인했다.

Windows 설치형 런타임과 배포는 아직 검증하지 않았다.

### 등록 화면·AI 제안 개선

- 상세의 편집·등록 버튼을 약 20% 확대하고 아이콘은 16px로 유지했다. 선택 미디어 미리보기와 순서 썸네일을 한 박스로 묶고, 미리보기 높이를 20% 늘렸다. 하단 버튼은 모달 전체 너비를 사용한다.
- TypeScript 테스트 535개, 타입 검사·lint·format 검사를 통과했다. AI 결과의 정확한 개수·빈값·중복·길이·제어문자 검증을 포함한다. Python 실행기는 이번 변경에서 수정하지 않았다.
- 합성 자료로 실제 앱의 AI 버튼을 눌러 서로 다른 제안 세 개를 받았다. 생성 동안 직접 작성한 내용을 보존했고, 제안 선택·다른 제안으로 변경·직접 수정·SQLite 저장·재조회·수정 시 등록 캡션 보존을 확인했다. 원본 캡션은 변경되지 않았다.
- 넓은 창과 540px 창에서 하단 좌우가 모달 테두리에 맞고 가로 넘침이 없음을 확인했다. 사용자 실자료와 작성 중인 등록 폼은 테스트에 사용하지 않았다.

### 캡션 통합 패널과 실행 버전 오류 보완

- 캡션 라벨 아래 한 박스에 원본 캡션(내부 작은 라벨), 등록 입력란, AI 제작 구분선, 전체 너비의 생성 영역과 제안 세 개를 표시한다. 등록 입력란의 별도 라벨·글자 수와 생성 취소 버튼은 표시하지 않는다. 시간 제한과 창/앱 종료 시 작업 정리는 유지한다.
- 개발 중 renderer만 갱신되고 main이 이전 단일 캡션 응답을 반환하면 새 화면에서 undefined.length 오류가 날 수 있었다. IPC 응답을 unknown에서 검증하며 단일 응답·잘못된 응답은 입력을 보존한 채 구체적인 안내로 처리한다. main/preload 계약 변경은 전체 앱 재시작까지 반영한다.
- 회귀 검사를 포함한 TypeScript 테스트 573개, 타입 검사와 lint 통과. 합성 자료의 이미지·영상·편집본으로 실제 AI 생성 세 개와 선택 적용을 확인하고, 생성 결과가 직접 작성한 캡션을 덮어쓰지 않는 것을 확인했다.

### 이미지 입력과 원본 캡션 우선

- 이미지가 없을 때 AI 영역을 비활성화하고, 혼합 선택에서도 선택한 이미지만 전달하도록 화면·main·Python에 적용했다. 영상 프레임 추출은 제거했다. 등록 화면 하단의 저장 안내 문구도 제거하고 버튼의 오른쪽 정렬은 유지했다.
- TypeScript 584개·Python 362개 테스트, 타입 검사·lint·format 검사를 통과했다. 혼합 선택에서 이미지 순서·20개 상한, 영상 전용 차단, 기존 캡처 이미지 허용, 다른 게시글 미디어 거절과 원본 보존을 검사했다.
