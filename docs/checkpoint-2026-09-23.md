# 2026-09-23 소스 체크포인트: API 연동 전

이 문서는 `codex/phase-2-registration` 브랜치의 최신 로컬 앱 작업을 다음 대화로 넘기기 위한 요약이다. 먼저 [AGENTS.md](../AGENTS.md)를 읽고 이 문서, [다운로드 계약](phase-1e-download.md), [AI 생성 계약](ai-content-generation.md), [구현 계획](implementation-plan.md)을 확인한다. 2026-09-22 [이전 체크포인트](checkpoint-2026-09-22.md)는 그 당시 상태의 기록이다.

## 이번에 정리한 범위

- 수집 탐색은 임시 JSONL에 기록하며 앱과 공통 잠금을 공유하지 않는다. 정규화 후 Excel을 최종 반영하는 짧은 구간에서만 잠금을 사용한다. 수집 도중 로컬 앱은 기존 다운로드 완료 게시글의 편집·작성을 계속할 수 있다.
- 앱은 게시글별 수집 완전성을 확인하여 작업 흔적이 없는 불완전 수집 글만 논리적으로 삭제한다. 중단되거나 `partial`인 수집 실행에 속해도 게시글 자체가 완전하면 유지한다. 정상 수집 글의 다운로드 실패·강제 종료는 삭제 사유가 아니며 완료 파일, 부분 파일, 계획과 요청·대기 이력을 보존한다.
- 다운로드 또는 이어서 다운로드를 누르면 게시글 확인·편집·작성이 중단됨을 알리는 확인창이 먼저 열린다. 승인 뒤에는 진행·대기 동안 반투명한 전체 화면 모달과 중앙 상태 카드를 표시하고 배경 조작·ESC 닫기를 막는다. 완료는 3초 뒤 닫히며 중단·오류는 사용자가 닫고 필요하면 다시 확인을 거쳐 재개한다. Excel 파일을 계속 열어두는 것이 아니라 다운로드 배치가 공통 잠금을 유지한다.
- 개발 실행에서만 수집 원본 이미지와 원문 캡션으로 제품 홍보용 AI 이미지·캡션 초안을 만들 수 있다. 원본·편집본·AI 생성본을 구분해 로컬 작성에 선택하며 자동 등록·게시하지 않는다. 패키지 앱은 AI 이미지 생성과 후보 조회를 차단한다. 기존 AI 캡션 기능은 별개다.
- 목록 위의 수집·저장 진단 경고 영역은 제거했다. 불완전 수집 글의 정리와 정상 글의 다운로드·재개 동작은 유지한다.

## 추가 변경: 수집 건수와 저장 미디어 중복 정리

- 수집 기본값은 요청마다 계정당 2개 게시글이다. 실행 전 계정 수와 계정당 목표를 간략히 보여준다. 사용자가 그 요청의 목표를 변경할 수 있고 하루 요청 횟수 상한은 없다. 다음 요청에서는 최신 글부터 이전 기준까지 다시 확인해 새 글만 수집한다.
- 다운로드 또는 명시적 재개에서 새로 완료한 게시글의 첫 이미지 SHA-256은 이미 저장된 게시글의 첫 이미지와, 첫 영상은 첫 영상과 비교한다. 다른 순서의 첨부는 비교하지 않는다. 일치하면 새 게시글 전체를 기존 삭제 저널로 삭제하고 Excel·DB에 표시한다. 완료 화면에는 이번 다운로드 게시글 수와 중복 제거 수를 보여준다.
- 중복 비교는 다운로드 결과의 새 완료 게시글을 대상으로 한다. 중단된 다운로드 계획은 명시적으로 재개해 완료된 후 처리한다. 기존 사용자 작업이 생긴 게시글은 자동 삭제하지 않는다.

## 저장과 다음 단계

Excel은 수집 원본, SQLite는 앱 작업 상태, JSONL은 수집 중 임시 기록이다. 기존 수집 파일·미디어·DB·등록·요청 기록을 초기화하지 않는다. 개인 자료와 생성 이미지, 서명 URL, 인증 정보는 저장소에 포함하지 않는다.

다음 작업은 실무진 피드백에 따른 캡션 품질 조정이다. 그다음 기능 단계는 Meta/Threads API 연동이다. 계정 연결·미디어 전달·게시글과 답글 전송·결과 이력·실패 복구를 함께 설계한다. 현재 `API 업로드`는 비활성 상태다. **Windows 설치·자동 업데이트·배포는 API 연동 이후**에 진행한다. 현재 Forge의 Windows maker와 updater는 구현되지 않았다. DB 유실·손상 뒤 전체 복원은 `database_restored` 보류 상태를 남기며 이력 검토·해제 절차는 아직 없다.

## 검증 범위

이번 소스 체크포인트에서는 `pnpm check`의 lint·타입 검사·TypeScript 테스트 724개·Python 테스트 455개·Prettier 검사를 통과했다. 실제 사용자 자료의 추가 수집·CDN 다운로드·게시 전송은 이 검증에서 실행하지 않았다. 새 다운로드 확인창과 전체 화면 상태는 자동 검사와 코드 검증 범위이며 실제 앱 화면에서의 최종 조작 검증은 별도로 남는다. Windows 설치·업데이트와 실제 패키지 검증도 아직 수행하지 않았다.

추가 변경은 지원 범위인 Node 22에서 `pnpm check`의 lint·타입 검사·TypeScript 테스트 727개·Python 테스트 464개·Prettier 검사를 통과했다. 변경 소스의 개인 경로·인증 정보·서명 URL 패턴 검사와 `git diff --check`도 통과했다. 이 검증 과정에서 실제 수집·다운로드·게시 전송은 실행하지 않았다.
