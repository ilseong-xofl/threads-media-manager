# 검증 기록 — 2026-10-18

대상: `validation/mobile-direct/`의 독립 정적 검증 웹. 기존 Electron 운영 코드, DB, S3, 파일서버, `marketo-sync`는 이번 구현·검증 대상에서 제외했다.

브라우저 시험에서 기본 `fetch`를 객체 메서드처럼 호출하면 발생하는 수신 객체 문제를 발견해 브라우저 전역에 바인딩했고, 회귀 테스트를 포함했다. 준비된 게시본을 새로고침한 뒤 내용 확인 없이 게시하지 못하도록 UI와 호출 로직 양쪽에 입력 복원 검사를 두었다.

재실행:

```sh
node --test --test-reporter=spec validation/mobile-direct/*.test.mjs
node validation/mobile-direct/build.mjs
```

브라우저 모의 시험은 개발 환경에 Playwright와 해당 브라우저가 있을 때 별도로 실행한다. 검증 웹 자체의 실행·배포에는 Playwright나 패키지 설치가 필요하지 않다.

```sh
# Playwright가 일반 모듈 경로에 설치되어 있고 Chrome을 사용할 때
PROBE_BROWSER_CHANNEL=chrome node validation/mobile-direct/browser-smoke.mjs
```

Playwright를 별도 경로에서 제공하는 개발 환경은 `PROBE_PLAYWRIGHT_PATH`에 해당 모듈 경로를 지정할 수 있다. 스크린샷은 Git에서 제외한 `test-output/`에 생성한다. 모의 테스트에서만 Android User-Agent를 사용하며 배포 파일에는 해당 모의 설정이나 요청 가로채기 코드가 포함되지 않는다.

## 미완료·제한

- 실제 Android 휴대폰·모바일 데이터·정상 장기 토큰을 사용한 CORS, 권한, 갱신, 게시, 댓글 검증은 **미완료**다. 브라우저 모의 시험은 이를 대체하지 않는다.
- HTTPS 배포, 운영 인프라 접근·설정 변경, 실제 S3 미디어 업로드와 Meta 게시를 실행하지 않았다.
- 테스트용 웹에는 서비스 로그인·DB 동기화·S3 업로드·관리자 권한이 없다. 실제 서비스의 휴대폰 연결 통제와 별개다.
- 숫자 게시 ID를 제공하는 텍스트 원글·댓글의 제한적 결과 확인만 구현했다. 미디어 원글·컨테이너 생성·토큰 갱신의 결과 불명은 자동 해제하지 않는다. 기록을 보존하고 중단한다.
- Nginx 예시는 작성했지만 실제 Nginx 설치에서 구문 검사하거나 적용하지 않았다. 도메인·인증서·정적 파일 경로는 운영자가 정해야 한다.
- 기존 Electron의 게시·토큰 갱신·통계 실행은 아직 변경하지 않았다. 전환 구현과 구버전 중단 확인은 후속 단계다.

실제 기기 준비와 단계별 절차는 [README](README.md), 운영 서비스의 최종 설계는 [모바일 직접 게시 전환 설계](../../docs/mobile-publishing-migration.md)를 따른다.
