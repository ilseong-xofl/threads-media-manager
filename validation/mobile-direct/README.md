# Android 모바일 직접 호출 검증

이 폴더는 Android Chrome에서 Threads API를 직접 호출할 수 있는지 확인하는 독립 검증 도구입니다. **실제 Android의 정상 토큰 검증과 HTTPS 배포는 아직 완료하지 않았습니다.** 기존의 잘못된 토큰으로 받은 CORS 응답이나 모의 테스트 통과는 실제 게시·댓글·갱신 성공을 증명하지 않습니다.

정적 웹 서버는 화면 파일만 제공합니다. 계정 확인, 토큰 검사·갱신, 컨테이너 생성·상태 조회, 원글·댓글 게시, 결과 확인 요청은 휴대폰 브라우저에서 `https://graph.threads.com`으로 직접 나갑니다. 서버 프록시, Server Action, Lambda, 데스크탑 대체 호출은 없습니다. CORS가 실패하면 중단하며 서버로 우회하지 않습니다.

운영 서비스의 로그인, 사용자 관리, DB 동기화, S3 업로드 기능은 포함하지 않습니다. 기존 데스크탑 게시 기능을 전환하거나 `marketo-sync`를 변경하는 도구도 아닙니다. 휴대폰 한 대에 계정 하나를 고정한다는 운영 규칙을 유지합니다.

## 준비물

- 해당 계정 전용 Android 휴대폰 한 대와 최신 Chrome, 모바일 데이터 연결. Wi-Fi를 끄고 직접 확인합니다. 브라우저가 실제 기기 소유 관계나 셀룰러 연결을 독립적으로 입증하지는 못합니다.
- 본인 소유 Threads 계정 하나, 정확한 사용자 이름과 Meta App ID. 개발자센터에서 해당 앱과 계정의 Threads 테스터 설정·초대 수락·필요 권한을 확인합니다.
- **발급 또는 마지막 갱신 후 24시간 이상 지났고 아직 만료되지 않은 장기 사용자 액세스 토큰.** 짧은 토큰에서 장기 토큰으로 교환하는 절차는 이 도구에 없습니다. App Secret과 앱 액세스 토큰은 입력하지 않습니다.
- 작은 JPEG 한 개와 짧은 MP4 한 개. MP4는 H.264/AAC 등 공식 미디어 사양에 맞는 파일을 준비합니다. 혼합 캐러셀도 별도로 확인할 수 있습니다.
- 미디어를 미리 올려 둔 S3의 HTTPS GET URL. Meta가 로그인·쿠키 없이 파일을 가져올 수 있어야 하고, 컨테이너 처리·게시·중단 후 확인에 충분한 유효 시간이 남아 있어야 합니다. S3 키나 AWS 자격 증명을 입력하지 않습니다. URL 생성과 S3 업로드는 이 도구의 기능이 아닙니다.
- 실제 계정에 게시해도 되는 테스트 본문과 텍스트 댓글. 게시 버튼은 실제 게시를 실행하며, 이 도구는 게시물을 자동 삭제하지 않습니다.
- 휴대폰에서 신뢰할 수 있는 인증서로 접속할 독립 HTTPS 주소. 인증서 경고를 무시하는 방식은 검증 조건에 포함하지 않습니다.

토큰, App Secret, AWS 키, 서명된 미디어 URL을 채팅에 붙여 넣지 마세요. 소스 파일·배포 파일·ZIP에는 실제 토큰을 넣지 않고, HTTPS 화면을 연 **휴대폰에서만** 실행 중 입력합니다.

## 로컬 화면 미리보기

Node.js 22가 필요하며 `npm install`은 필요하지 않습니다. 저장소 루트에서 다음을 실행합니다.

```sh
cd validation/mobile-direct
node serve.mjs
```

기본 주소는 `http://127.0.0.1:4187`입니다. 이 HTTP 실행은 화면 미리보기 전용이며 실제 Meta 호출 검증 조건을 충족하지 않습니다. PC 브라우저에서 토큰을 넣어 검사하지 않습니다.

서버는 `index.html`, `styles.css`, `app.mjs`, `probe.mjs` 네 파일에 대한 GET/HEAD만 제공합니다. API 경로, 업로드, 외부 요청 기능은 없습니다. `--host`, `--port`, `--cert`, `--key`, `--root` 옵션도 있지만, 자체 서명 인증서를 쓰는 것만으로 실제 검증 조건이 충족되지는 않습니다.

## 정적 HTTPS 배포 준비

저장소 루트에서 실행합니다.

```sh
node validation/mobile-direct/build.mjs
```

`validation/mobile-direct/dist/`에 다음 네 파일과 `SHA256SUMS`가 생성됩니다.

```text
index.html
styles.css
app.mjs
probe.mjs
SHA256SUMS
```

빌드는 배포를 실행하지 않으며 ZIP도 만들지 않습니다. 사용자가 소유한 독립 정적 HTTPS 호스트에 **네 웹 파일만 직접 업로드**하고, `SHA256SUMS`는 배포 파일 대조용으로 보관합니다. 별도로 ZIP으로 묶는 경우에도 실제 토큰이나 미디어 URL을 포함하지 않습니다. 저장소 전체, 테스트 파일, 개인키, `.env`를 공개하지 않습니다.

[nginx.example.conf](./nginx.example.conf)는 독립 호스트용 예시입니다. 사용자가 도메인·인증서·정적 파일 경로를 실제 값으로 바꾸고 검토한 뒤 적용해야 합니다. 이 작업에서 AWS 접속, 서버 설정 변경, HTTPS 배포는 실행하지 않았습니다. 기존 서비스나 `marketo-sync`에 합치지 않습니다.

정적 호스트는 캐시 금지, referrer 차단, 프레임 삽입 차단, 콘텐츠 유형 고정, `graph.threads.com`으로 한정한 연결 정책을 적용합니다. 액세스 로그는 끄는 예시이며 앞단 CDN/WAF나 별도 분석 도구의 기록 정책도 사용자가 확인해야 합니다. 분석 스크립트나 오류 수집 도구는 추가하지 않습니다. 호스트에 CORS 헤더를 추가해도 Meta 응답의 CORS 허용 여부를 바꿀 수 없습니다.

## 휴대폰 검증 순서

처음에는 텍스트 원글·텍스트 댓글로 전체 흐름을 확인하고, 완료한 뒤 새 테스트에서 이미지·영상·혼합 캐러셀을 확인합니다. 한 번에 탭 하나만 사용하고, 원글 또는 댓글 결과가 불명이면 다음 테스트로 넘어가지 않습니다.

1. **실행 환경 확인:** 전용 휴대폰의 Android Chrome에서 배포한 HTTPS 주소를 열고 모바일 데이터를 직접 확인합니다. 화면의 확인 항목을 선택합니다. User-Agent나 기기 값을 임의로 바꾸지 않습니다. 브라우저 기본값이 사용됩니다.
2. **계정·토큰 확인:** App ID, Threads 사용자 이름, 장기 사용자 토큰을 입력하고 개발자센터의 앱·테스터·토큰 연결 확인 항목을 선택합니다. `계정·토큰 확인`은 `/me`와 `/debug_token`의 정상 응답을 실제 브라우저에서 읽는지 검사합니다. 응답의 사용자·유효성·만료 등을 확인합니다. `app_id`는 응답에 항상 나온다고 보장할 수 없으므로 누락만으로 차단하지 않으며, 입력한 App ID의 개발자센터 확인이 필요합니다.
3. **토큰 갱신 테스트:** 발급·갱신 후 24시간 이상 지났고 만료 전인 장기 토큰으로 버튼을 한 번 누릅니다. 발급 시각을 확인할 수 없거나 시간 조건이 맞지 않으면 중단합니다. 갱신 응답을 브라우저에서 읽는지 확인합니다. 갱신 토큰은 메모리에만 남으며 서버에 저장되지 않습니다. 필요하면 명시적인 복사 버튼으로 안전하게 보관하고 클립보드를 정리합니다.
4. **원글 준비:** 테스트 본문과 필요한 미디어 URL을 입력합니다. 첨부가 없으면 텍스트 원글입니다. 실제 게시 동의를 확인한 뒤 `컨테이너 준비·이어가기`를 누릅니다. 준비와 게시 버튼은 분리되어 있습니다.
5. **원글 상태·게시:** `처리 상태 확인`을 직접 눌러 준비 완료를 확인하고 `원글 게시`를 누릅니다. 게시 응답의 숫자 게시물 ID를 확인합니다. 컨테이너 ID는 게시물 ID가 아닙니다.
6. **댓글 준비·상태·게시:** 원글 게시 완료 후 테스트 댓글을 입력하고 댓글 컨테이너 준비 → 처리 상태 확인 → 댓글 게시 순서로 각각 실행합니다. 댓글은 방금 게시한 원글에 연결되는 텍스트 답글입니다.
7. **기록 저장:** `검증 기록 내려받기`로 토큰 등이 제거된 JSON 기록을 저장합니다. 실제 Threads 화면에서도 대상 계정·원글·댓글을 확인하고, 다음 미디어 종류의 테스트는 현재 결과가 확정된 뒤 시작합니다.

상태 확인이나 토큰 갱신은 백그라운드 주기 실행으로 반복하지 않습니다. 게시와 댓글도 자동 실행하지 않습니다. 캐러셀 준비 과정에는 생성된 자식 컨테이너의 상태를 한 차례 읽는 작업이 포함되며, 준비가 끝나지 않으면 사용자가 다음 확인을 실행합니다.

### 캐러셀을 이어서 준비할 때

캐러셀은 각 이미지·영상의 자식 컨테이너를 준비한 뒤 부모 컨테이너를 만듭니다. 일부 자식만 처리된 경우 이미 ID를 받은 자식을 새로 생성하지 않고, 상태를 확인한 뒤 `컨테이너 준비·이어가기`로 이어갑니다.

새로고침했다면 같은 계정의 토큰과 사용자 이름을 다시 입력하고, **원래 본문과 동일한 URL·첨부 순서**를 다시 입력합니다. 준비 버튼에서 저장된 지문과 일치하는지 확인하기 전에는 기존 준비 완료 상태만으로 게시할 수 없습니다. 서명 URL을 새로 발급해 문자열이 달라진 경우도 같은 입력으로 취급하지 않습니다.

컨테이너 생성 요청의 응답을 잃어 ID를 모르는 경우에는 생성하지 않았다고 추정하거나 자동 재생성하지 않습니다. 결과 불명 상태를 유지하고 중단합니다.

## 새로고침·결과 불명과 복구 범위

토큰은 페이지 메모리에만 있습니다. 새로고침하면 같은 계정의 토큰과 사용자 이름을 다시 입력하고 검증해야 합니다. 진행 중이던 변경 요청은 결과 불명으로 복원하며 자동 재전송하지 않습니다. 같은 사이트의 다른 탭은 Web Locks와 기록 변경 검사를 통해 동시 작업을 막습니다. 필요한 브라우저 기능이나 저장소를 사용할 수 없으면 진행하지 않습니다.

`게시물 확인·결과 연결`은 다음 조건에서만 제한적으로 사용합니다.

- 텍스트 원글 또는 텍스트 댓글의 **게시 요청** 결과가 불명이고, 기존 컨테이너 ID가 남아 있어야 합니다.
- 사용자가 실제 게시물의 **숫자 API 게시물 ID**를 제공해야 합니다. Threads 주소의 짧은 코드나 URL을 숫자 ID로 바꾸는 기능은 없습니다.
- 휴대폰이 컨테이너의 게시 상태와 해당 게시물의 계정·본문 지문·종류·시각을 확인하며, 댓글은 원글과의 연결도 확인합니다. 조건이 일치하지 않거나 조회할 수 없으면 결과 불명 상태를 유지합니다.
- 미디어 원글은 원격 미디어와 준비한 원본이 같다는 사실을 이 도구가 입증하지 못하므로 **수동 ID를 넣어도 결과 불명을 해제하지 않습니다.** 기록을 내려받고 중단합니다.
- ID를 받지 못한 컨테이너 생성, 자식 컨테이너 생성, 토큰 갱신의 결과 불명은 이 화면에서 해결하지 않습니다.

이 제한은 전체 운영 서비스의 복구가 완성되었다는 뜻이 아닙니다. 미디어 게시 응답 유실 후 안전하게 복구할 수 없다면 해당 검증 항목은 실패 또는 미완료로 기록합니다. 한 번 게시됐을 가능성이 있는 작업을 새 테스트로 다시 보내지 않습니다.

기록은 처음 확인한 계정과 앱에 고정됩니다. 계정을 바꾸거나 결과 불명을 지우고 새 테스트를 시작할 수 없습니다. **사이트 데이터를 지우면 로컬 기록도 사라지므로, 이를 재게시 방법으로 사용하지 않습니다.**

## 저장·전송되는 정보

- 메모리: 입력 토큰, 새 갱신 토큰, 본문, 미디어 URL. 토큰 지우기 또는 페이지 종료·새로고침 뒤에는 다시 입력해야 합니다.
- `localStorage`: 계정·앱의 식별 정보, 사용자 이름의 지문, 만료 시각, 본문·입력 지문, 단계·시각·컨테이너/게시물 ID 등 복구용 메타데이터. 토큰, 사용자 이름 원문, 본문 원문, 서명된 미디어 URL은 저장하지 않습니다.
- 내려받는 JSON: 허용된 진단·복구 메타데이터. 토큰·본문·미디어 URL은 포함하지 않습니다. 계정·게시물 식별자가 들어갈 수 있으므로 공유 전에 확인합니다.
- Meta 요청: 공식 예시에 맞춰 GET에서는 쿼리 매개변수, POST에서는 폼 본문으로 사용자 토큰을 보냅니다. `/debug_token`에는 검사할 사용자 토큰도 들어갑니다. 모든 요청은 휴대폰에서 직접 전송합니다.

브라우저 개발자 도구, 네트워크 기록, HAR 내보내기에는 토큰이나 서명 URL이 포함될 수 있습니다. 원본 HAR·네트워크 화면을 그대로 공유하지 말고 민감값을 마스킹하세요. 검증 공유에는 화면의 JSON 내보내기를 우선 사용합니다. 정적 호스트에는 토큰을 보내지 않는 구조지만, 사용자 입력을 별도 분석·로그 수집에 붙이지 않는 조건을 유지해야 합니다.

## 통과 기준과 아직 확인하지 못한 것

다음은 실제 전용 Android 휴대폰, 정상 장기 토큰, 신뢰할 수 있는 HTTPS에서 각각 확인해야 합니다.

- `/me`, `/debug_token`, `/refresh_access_token` 응답을 CORS 오류 없이 읽으며 계정·토큰·시간 조건을 확인한다.
- 텍스트·JPEG·MP4·혼합 캐러셀의 컨테이너 생성, 처리 상태 확인, 게시 응답을 읽는다.
- 게시된 원글의 텍스트 댓글 생성·상태·게시 응답을 읽고 실제 계정에서 연결을 확인한다.
- 새로고침, 중복 탭, 통신 중단에서 자동 재게시하지 않으며, 텍스트 결과 연결과 미디어 결과 불명 중단이 계약대로 작동한다.
- 새로고침 뒤 같은 입력 확인, 토큰 미저장, 진단 기록의 민감값 제외를 확인한다.

인증된 실제 요청 또는 오류 응답의 CORS 처리가 실패하면 서버 프록시로 바꾸지 않고 실패로 남깁니다. `no-cors`로 응답을 읽지 못하는 요청도 통과가 아닙니다. 실제 휴대폰·통신망 출발지, 정상 토큰 권한, Meta의 실제 게시 결과는 모의 테스트만으로 검증할 수 없습니다. 이 도구의 성공이 계정 제한 가능성을 없애거나 최소화한다고 보장하지도 않습니다.

저장소 루트에서 자동 검증을 실행할 수 있습니다.

```sh
node --test validation/mobile-direct/*.test.mjs
```

자동 테스트는 요청·상태·저장 계약의 로컬 검증입니다. 실제 Meta 호출, Android 실기, AWS 배포 완료로 보고하지 않습니다.

현재 실행 결과와 브라우저 모의 시험 방법은 [검증 기록](./verification.md)에 정리했습니다.

## 공식 참고 자료

- [Threads 프로필 조회](https://developers.facebook.com/documentation/threads/threads-profiles): 사용자 ID와 사용자 이름 확인.
- [액세스 토큰 검사](https://developers.facebook.com/documentation/threads/troubleshooting/debug-access-token): 같은 앱의 Threads 테스터 사용자 토큰으로 검사할 수 있는 조건. 앱 액세스 토큰을 쓰려면 App Secret이 필요하므로 이 도구에서는 사용하지 않습니다.
- [장기 토큰과 갱신](https://developers.facebook.com/documentation/threads/get-started/long-lived-tokens): 장기 토큰, 24시간 경과·만료 전 갱신 조건, `th_refresh_token`. 장기 토큰 교환의 App Secret은 클라이언트에 넣지 않습니다.
- [게시물 생성과 미디어 사양](https://developers.facebook.com/documentation/threads/posts): 미디어 URL, 이미지·영상·캐러셀 컨테이너와 답글 생성.
- [게시·컨테이너 상태 참조](https://developers.facebook.com/documentation/threads/reference/publishing): `threads_publish`, `creation_id`, 상태 조회.
- [게시물 조회 필드](https://developers.facebook.com/documentation/threads/reference/media-retrieval): 게시물 ID, 계정, 본문, 답글 관계 확인에 사용하는 필드.
- [Meta 공식 Threads Postman 컬렉션](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api): 엔드포인트와 요청 예시. 예시의 자동 게시 옵션을 이 도구에 추가하지 않습니다.

공식 API 문서는 요청 형식의 근거입니다. 특정 Android 브라우저에서 인증된 요청의 CORS가 모두 성공한다는 실증을 대신하지 않습니다.
